# tonari フロア営業の画像素材 ── Codex への依頼（2026-11-20・TFL06 → TFL08・TFL09 で作り直し・TFL10 で画面の構成を更新）

オーナーの指示（どれも 2026-11-20）:

1. 「バイトパートを龍が如く0や極2にあるキャバクラ経営ゲームみたいにしようと思ってます。……画像生成はコーデックスに依頼して見た目も良くして」
2. 「バイトのやつは専用の画像生成で見た目とか作って見栄えからよくしたい。内装のレイアウトは変えてもいいので、それでコーデックスにパーツや見た目の依頼を出して」
3. 「レイアウトとかUIとかかなり龍が如くのキャバクラに寄せていい。ただ席の形は『席席席／席　席』みたいにしたい。ソファで、下の2段は内側を向いた配置で」
4. 「（龍が如く0のキャバクラ経営の動画を挙げて）UIとかシステムとかこの龍が如くのキャバクラのプレイパートを参考にしてみて　ここまでスピード感はいらないけど」

そこで、会話用の店内画に札を重ねる今の形をやめ、**営業の画面のために組み直した店内**と、そこに座る客・卓の上の物・UI の部品を一式そろえる。遊びの仕様は [docs/spec/tonari_floor.md](../../../docs/spec/tonari_floor.md)。Codex への依頼は Issue #3960。

## 目指す見た目

**夜の店の経営ゲームの画面**。少し上から見た tonari の店内に、ソファの席が「上に3つ・下の左右に2つ」。客が座り、卓の上に一台と煙。その上に、黒に近い濃い色の板と金の縁・金の数字の HUD が重なる。

- **席の形（オーナー指定）**: 上の3席はソファがこちら向きで、卓は手前。下の2席は**内向き**（左のソファは右向き、右のソファは左向き）で、卓は内側。まん中は通路。
- **画面の構成は、水商売の経営ゲームの営業画面に寄せる**（2026-11-20 オーナー「UIとかシステムとかこの龍が如くのキャバクラのプレイパートを参考にしてみて」）: 上のまん中に残り時間、右上に売上、卓の上に丸いマーカー（いま出来ること・急ぎの輪）、卓の番号札に滞在の残りの輪、下の左に選んでいる卓のドック（客・ご利用の金額・顔）、下の右に溜まると押せるボーナスタイムのゲージ。卓を押して選ぶ場面（接客ビュー）は、店内がその卓へ寄り、左に選択肢の縦の列、下に大きなドック、選んだあとに判定の印（◎ ○ △ ×）。最後に売上と評価の大きな結果画面。
- **絵そのものは本作のもの**にする。ほかの作品の画面・ロゴ・固有の意匠は写さない。店は今の tonari と同じ店（`assets/backgrounds/bg_tonari_inside_day.png` の緑の布のソファ・木の低い卓・モザイクランプ・窓の外の街・木のカウンター）。内装の並べ方は変えてよい（オーナー決定）。
- 客は名もない客。本編の登場人物（つむぎ・ひより・鉄仮面さん・サイの店の常連など）に似せない。常連帳は作らないので、決まった個人に見える強い特徴（派手な髪色・傷・目立つ装飾）を付けない。
- 画風は、客＝[立ち絵の規格](../../../docs/portrait_standard.md) 3節、店内＝[背景の規格](../../../docs/background_standard.md) 2節の塗り。AIっぽさ（テカり・グロー・エアブラシ・量産型の顔・擬似文字）を避ける（[素材規約](../../../docs/asset_ai_guidance.md)）。
- 数字・名前・時計・満足の輪・マーカーの文字・煙の動き・灯りの明滅はコードが描く。素材には焼き込まない。
- シーシャ機材が写るのは C の一台だけ（`docs/shisha_reference.md` §4 の手順が要る）。店内画と客の絵には、台・ホース・炭を描かない。

### B. 客（座った全身・1枚に1人・15人＋笑顔15枚）

**1024×1024・背景は単色マゼンタ（#FF00FF）**。人物の高さは画面の約85%、足先が下の端の近く、左右は中央。ソファ・卓・背景・影は描かない。両手は膝の上か体の前（グラス・シーシャの台・ホースは持たせない）。

## いまの画面と、届いた後の組み込み

絵が届くまでは、採用済みの会話用の店内画 `bg_tonari_inside_*` に丸い客の札を重ねた形（`STAGES.classic`）で遊べる。HUD はゲーム共通の暗い板と `craft-night` の札・メダルで、構成（残り時間・売上・卓のマーカー・番号札の輪・卓のドック・接客ビューの列と判定の印・結果）は専用レイアウトと同じ。2026-11-20 の時点で、この環境の OpenAI 画像 API は残高切れ（`credit_balance_exhausted`）で、Claude 側では1枚も生成できていない。

専用レイアウトの受け口はコードに入れてある（`remake/js/daily/tonari-floor-stage.js`）。届いた順に、次のように登録する。

1. 原画を `originals/` に置く。マゼンタの背景は透過にし、端のにじみを消す。
2. **客**: 高さ 512px の WebP にして `remake/img/ui/tonari-floor/guest-<ID>.webp`（笑顔は `-happy`）。`FLOOR_ART.guests` に `"first": { idle: "…", happy: "…" }`・`"train-a": { … }` のように、ひとりずつ足す。客の絵だけ先に届いた時は、今の丸い札の中に顔のまわりが切り抜かれて出る。
3. **店内**: `remake/img/ui/tonari-floor/room-day.webp`・`room-night.webp` と、前景 `front-day.webp`・`front-night.webp`（届かなければ `STAGES.floor` の各席の `cover` の範囲で店内画から切り出す）。`FLOOR_ART.stage` を `"floor"` にすると専用レイアウトへ切り替わる。絵の家具が配置図からずれていたら、`STAGES.floor` の `box`・`bubble`・`plate`・`prop`・`lamps` を絵に合わせて測り直す。
4. **卓の上の一台**: `remake/img/ui/tonari-floor/shisha-table.webp` を `FLOOR_ART.props.shisha` に登録する。
5. **部品・記号**: `remake/img/ui/tonari-floor/` に WebP で置き、`remake/css/tonari-floor.css` の `border-image`・`background` と、`remake/js/daily/tonari-floor-art.js` の `glyph()` を替える。
6. `node remake/test/browser/tonari_floor.mjs`（`seated-stage` が専用レイアウトの席の形と重なりを見る）と、PC 1280×720・横持ち 844×390 の実画面で確認する。
