7. 「**カットインとかUIとかは新たにコーデックスで作りたい**」「**表情アイコンが元ネタのまんまなので少し変えたい**」「好感度1以上の人物がたまにレアで遊びに来たりとかも入れたい」→ **カットイン（E）を足し、UI の部品（D）は一式を専用に新しく作る**。満足の顔の印は、丸い顔をやめて**煙のかたちの顔・5つの表情**にする（TFL-UI07）。たまに遊びに来る本編の人物（つむぎ・なる・アダム）の座った絵を B に足した。原価・利益は扱わなくなったので、ショップカードの絵は取り下げ

## 目指す見た目

**夜の店の経営ゲームの画面**。少し上から見た tonari の店内に、ソファの席が「上に3つ・下の左右に2つ」。客が座り、卓の上に一台と煙。その上に、黒に近い濃い色の板と金の縁・金の数字の HUD が重なる。

- **席の形（オーナー指定）**: 上の3席はソファがこちら向きで、卓は手前。下の2席は**内向き**（左のソファは右向き、右のソファは左向き）で、卓は内側。まん中は通路。
- **画面の構成は、水商売の経営ゲームの営業画面に寄せる**（2026-11-20 オーナー「UIとかシステムとかこの龍が如くのキャバクラのプレイパートを参考にしてみて」＋仕様書）: 上の左に**作成中の一台**（2枠。進みの棒）、上のまん中に残り時間、右上に売上。**右の端（カウンターの上）に定番ミックスの列**（最大8つの横長の札）。**卓ごとに「卓の札」**（二つ窓の箱。箱の上の帯は客の要望で、色が求める吸い心地＝紫・緑・黄・水色。左の窓に卓番号と客の顔、右の窓に満足の顔とドリンクの杯数（注文待ちは残り秒）。箱の下に細い棒＝作成の進み／炭の残り。箱の上に用件の見出し、左下に滞在の残りの円、右下に待たせている残り秒）。下の左に選んでいる卓のドック（客・ご利用の金額）、下のまん中に出来事の行とはじめの心の声、下の右に**フィーバーのゲージ（3段）**。注文待ちの卓を押すと**調合の窓**（画面いっぱいの板。左に定番、まん中に系統のタブと棚のフレーバーの札、右にボウルと予想）。ケアと会計で卓を押す場面（接客ビュー）は、店内がその卓へ寄り、左に選択肢の縦の列、下に大きなドック、選んだあとに ◎○△× の大きな印。フィーバーの突入は、画面を横切る紫と金の帯。
- **絵そのものは本作のもの**にする。ほかの作品の画面・ロゴ・固有の意匠は写さない。店は今の tonari と同じ店（`assets/backgrounds/bg_tonari_inside_day.png` の緑の布のソファ・木の低い卓・モザイクランプ・窓の外の街・木のカウンター）。内装の並べ方は変えてよい（オーナー決定）。
- 客は名もない客。本編の登場人物（つむぎ・ひより・鉄仮面さん・サイの店の常連など）に似せない。常連帳は作らないので、決まった個人に見える強い特徴（派手な髪色・傷・目立つ装飾）を付けない。
- 画風は、客＝[立ち絵の規格](../../../docs/portrait_standard.md) 3節、店内＝[背景の規格](../../../docs/background_standard.md) 2節の塗り。AIっぽさ（テカり・グロー・エアブラシ・量産型の顔・擬似文字）を避ける（[素材規約](../../../docs/asset_ai_guidance.md)）。
- 数字・名前・時計・卓の札の文字と顔・円のタイマー・残り秒・煙の動き・灯りの明滅はコードが描く。素材には焼き込まない。
- シーシャ機材が写るのは C の一台だけ（`docs/shisha_reference.md` §4 の手順が要る）。店内画と客の絵には、台・ホース・炭を描かない。

### B. 客（丸の中に入る顔・1枚に1人・15人＋笑顔15枚）

客は**全身を描かない**。席に「丸の中の顔」が出れば来店、という見せ方にする（2026-11-20 オーナー。全身を描くと画面が狭くなるため）。同じ絵を、席の丸・卓のドック・調合の窓で使う。
**1枚に1人**。二人組も、ひとりずつ別の絵にする（ゲームが丸を二つ並べる）。**肩から上**（頭のてっぺん〜鎖骨のあたり）。顔は正面〜少し斜め。丸く切り抜いて使うので、顔を中央に置き、頭の上と左右に少し余白を取る。
**512×512・背景は単色マゼンタ（#FF00FF）**（ゲーム側で淡い色の丸に載せる）。影・背景・小物は描かない。直径48px（スマホ）に縮めても、髪型と表情で見分けがつく単純さにする。下の表の服装・姿勢のうち、肩から上に見える所（髪・帽子・眼鏡・襟・表情）だけを描く。

## いまの画面と、届いた後の組み込み

絵が届くまでは、採用済みの会話用の店内画 `bg_tonari_inside_*` に丸い客の札を重ねた形（`STAGES.classic`）で遊べる。HUD はゲーム共通の暗い板と `craft-night` の札・メダルで、構成（作成中の一台・残り時間・売上・定番の列・卓の札・番号札・卓のドック・出来事の行・フィーバーのゲージ・調合の窓・接客ビューの列と判定の印・精算）は専用レイアウトと同じ。2026-11-20 の時点で、この環境の OpenAI 画像 API は残高切れ（`credit_balance_exhausted`）で、Claude 側では1枚も生成できていない。

専用レイアウトの受け口はコードに入れてある（`remake/js/daily/tonari-floor-stage.js`）。届いた順に、次のように登録する。

1. 原画を `originals/` に置く。マゼンタの背景は透過にし、端のにじみを消す。
2. **客**: 256×256 の WebP にして `remake/img/ui/tonari-floor/guest-<ID>.webp`（笑顔は `-happy`）。`FLOOR_ART.guests` に `"first": { idle: "…", happy: "…" }`・`"train-a": { … }` のように、ひとりずつ足す。席の丸・卓の札・ドック・調合の窓に、そのまま丸く出る（客の絵だけ先に届いても使える）。
3. **店内**: `remake/img/ui/tonari-floor/room-day.webp`・`room-night.webp`。`FLOOR_ART.stage` を `"floor"` にすると専用レイアウトへ切り替わる（前景は要らない。使う時だけ `STAGES.floor.art` に `frontDay`・`frontNight` を足す）。絵の家具が配置図からずれていたら、`STAGES.floor` の `box`・`bubble`・`plate`・`prop`・`lamps` を絵に合わせて測り直す。
4. **卓の上の一台**: `remake/img/ui/tonari-floor/shisha-table.webp` を `FLOOR_ART.props.shisha` に登録する。
5. **部品・記号**: `remake/img/ui/tonari-floor/` に WebP で置き、`remake/css/tonari-floor.css` の `border-image`・`background` と、`remake/js/daily/tonari-floor-art.js` の `glyph()` を替える。
6. `node remake/test/browser/tonari_floor.mjs`（`seated-stage` が専用レイアウトの席の形と重なりを見る）と、PC 1280×720・横持ち 844×390 の実画面で確認する。
