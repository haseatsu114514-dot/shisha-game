## 入力と手元の穴

`holes.js`が実穴を追加した後、座標の読み取り通知だけを`session.setBenchHoleAction`へ渡す。判定/テンプレ/穴数評価/進行/熱への接続は既存のまま。`worker-holes.js`が実座標を写真のアルミ面の楕円へ投影し、針先を同じ位置へ合わせる。MISS/TOO CLOSEも実穴なので表示から消さない。

接触→引き抜き→待機の3コマを0/90/180msで切り替える。連打では旧コマのタイマーを取り消し、最新の実穴一覧を表示。工程変更/やり直しで手元の穴をリセットする。reduced motionでは静止した待機の手と新しい穴だけを表示。表示のタイマーは演出専用で、採点やゲーム時計を進めない。

## 開始待ちと失敗時

- 既存`warmCraftAssets`の共通`imageReady`キャッシュを使用。making/正規顔の先読みに加え、**実際に表示するImage要素のdecode**まで`bench.ready`で待つ。
- 15秒超過・破損・デコード失敗では既存の作業台/読めた正規顔へ戻す。その一台の途中に遅れた新規素材を突然出さない。
- decodeがないブラウザは表示要素のload/errorを待つ。新しい判定・温度・採点・吸引時間・セーブフラグは追加しない。
- 穴あけは右手3枚までdecodeを待つ。1枚でも失敗したら手元全体を既存の人物へ戻し、途中の欠けた手や針だけを出さない。
- ボトル寄りを温度計の左へ置き、前景より前に描く。写真の本体上部を追加しない別カメラなので、固定のHMD/炭数を焼き込まない。
