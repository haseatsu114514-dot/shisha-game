# 蒸らしアタック（Issue #356）

引き継ぎ時にオーナーが案Aの全数値とリセット条件を再承認した記録:
https://github.com/haseatsu114514-dot/shisha-game/issues/356#issuecomment-6114287882

## 承認済み仕様

| 被弾までに続けて斬った言葉（コンボ） | 射程 | リチャージ |
|---|---|---|
| 0〜2個 | 80px | 1.8秒 |
| 3〜5個 | 90px | 1.5秒 |
| 6個以上 | 100px | 1.2秒 |

角度は現行の80度。オーナーの追加指定で上側の前方へ固定し、方向キー／スティックは移動だけに使う。旧SF64の四方向アタックを更新する。Z・タッチ・支援技術のclickで同じ処理を呼ぶ。カウントダウン後から使用可能で、初回練習を含む全セッションで章条件なし。

1つの言葉弾につき1個加算。同時に複数斬った場合はそれぞれ数え、炭・時計等の物体弾は斬れても強化数には入らない。攻撃の命中判定とその刃の大きさには発動直前の射程を使い、その攻撃で段階に到達したら次の攻撃の射程と今回の待ち時間から強化が適用される。

空振り・時間経過・リフレッシュでコンボは減らない。2026-10-12の追加指定で、実際の被弾時に0へ戻り、射程・次回のリチャージは初期段階へ戻す（以前の被弾維持指定を更新）。すでに始まったリチャージは途中で延長/短縮しない。新しい蒸らしセッション開始時も0に戻す。セッションの総切断数と最大コンボは別に記録する。

セーブの解放フラグ・スキーマを追加せず、旧セーブも開始時は80px／1.8秒。リフレッシュの8秒・心の回復・得点・温度・ハートの判定は既存処理を使用する。

## 現行との比較

従来は毎回80px／1.8秒。最大段階では射程が25%伸び、再使用間隔は約33%短くなる。1回で周囲全体を斬る仕様にはせず、前方80度の扇形判定を保つ。DAY3解放案は初回練習・旧セーブの扱いを変えるため採用せず、開始時解放を維持する承認に従う。これらは承認された値であり、実測の難易度評価や他作品の数値を根拠なく断定しない。

## 表示と検証

画面は待ち時間の数字と進捗リング、「×N」の言葉カウントだけに絞り、矢印・ダイヤ・条件の文章は出さない。説明文は「?」ヘルプと読み上げ側へ置く。ボタンの剣は中央に合わせ、斬撃は半円状の弧を残した太い根元／細い先端の非対称な刃にする。強化すると刃の色と輝きが水色→紫→金へ変化。小さな物体弾も既存の実矩形判定で斬れるが、言葉の強化数には加算しない。

命中は火花と輝く刃、空振りは淡い刃で区別する。「N個斬った」「強化！」「空振り」の文章は画面に重ねず、操作結果だけをlive regionで読み上げる。

言葉を斬ると、描画と同じ刃の曲線の接線に合わせて元の文字が二分される。位置や文字の回転にかかわらず固定した斜め線にはせず、元の文字の回転を保って切断面から垂直に離す。破片は当たり判定を持たず、0.5秒のゲーム時刻で片付ける。リフレッシュは既存の溶ける演出を維持する。動きを減らす設定では破片を静止させる。

ハート外形はオーナー追加指定で18pxから20pxへ少し拡大。中央の白丸・標準半径4pxと能力／体調補正の判定は変更しない。

検証は `node remake/test/steam_attack_growth.mjs`（承認値・可変射程・実弾での成長とリセット）、既存 `steam_slash.mjs`（四方向へ移動中も前方固定・PC／二本指・リチャージ）、`steam_refresh.mjs`、`steam_forecast.mjs`、`steam_heart.mjs`、`browser/save_load.mjs`。ブラウザテストでは `NODE_PATH=remake/test/browser/node_modules` と環境に応じた `CHROME_EXECUTABLE_PATH` を設定する。実施結果・未確認事項と画像はPRに記録し、全項目の成功をこの文書だけで宣言しない。
