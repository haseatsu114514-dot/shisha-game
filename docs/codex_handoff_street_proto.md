## 0. これは何か

日常パートが「マップのピンを選ぶ→会話→寝る」の繰り返しで単調、というオーナーの声から、
マップを **「エリアを選ぶ → 横長の通りを MOTHER2 のような斜め見下ろし・8方向で歩く → 店に入る」**
形にする案が出ている。本編に入れるかを決める前の**試作**として、繁華街の通り1本を作る。

すでにあるもの（Claude作成・このブランチ）:
- `web/proto/walk/index.html` … 8方向歩行の実験ページ（移動・タップ移動・2コマ歩行・左右反転・足元yソート・
  設定パネル・8方向一覧）。画像が無いあいだはコード描画の仮スプライトで動く
- `tools/proto_walk_sheet.py` … 生成AIの歩行シート（マゼンタ背景・5×2）→ 足元を揃えたゲーム用シートへ変換
- `asset_sources/images/proto_walk/pose_reference_sheet.png` … 歩行シート生成時に渡す「向きの並び・足の位置」の参照
- 使い方の詳細は `web/proto/walk/README.md`

**あなたの担当**: 街並み（建物・小物）とキャラのドット絵の生成、そして通りの試作ページの実装。
歩くキャラは**仮でつむぎ**（最終的には主人公はじめに差し替える想定。今回ははじめを描かない）。

## 4. 実装仕様（`web/proto/street/`）

### 体験の流れ
1. `web/proto/street/index.html` を開くと**エリアマップ**。背景は既存の `assets/backgrounds/bg_osu_map_day.png`。
   「繁華街」のピンだけ押せて、他のエリアは「準備中」でグレー。
2. 繁華街を押すと、横長の通りの左端につむぎが降り立つ。
3. 斜め見下ろし（3/4ビュー）で、通りを**8方向**に歩ける。上に店の建物が並び、下が歩道（歩ける帯）。
   カメラは**横方向だけ**追従する。
4. 店の入口の前で決定すると暗転して店内（既存の背景画像）を表示し、メッセージを出す。
   「外に出る」で同じ入口の前に戻る（下向き）。
5. 看板・自販機などを「しらべる」と一言テキスト。通行人に話しかけると、相手がこちらを向いて喋る。
6. **ファストトラベル**: 「マップ」ボタン（Mキー）で、**一度入ったことのある店**の前へ瞬時に移動できる。
   未訪問は「？？？」で押せない。「通りの入口」へはいつでも戻れる。
   訪問記録は localStorage（キー `shisha_proto_street_v1`、読み書きは try/catch）。`?reset=1` で消去。

### 技術
- 素のJS＋Canvas 2D。移動・向きの量子化・2コマ歩行・左右反転・足元yソート・タップ移動は
  `web/proto/walk/index.html` の実装を流用する（挙動を揃える）。
- 見え方は内部解像度 320×180 を4倍（1280×720）が基準。整数倍・`image-rendering: pixelated`・
  `imageSmoothingEnabled=false`。ウィンドウに16:9でフィットさせる。
- **キャラは32px版**（`assets/proto_walk/tsumugi_walk_32.png`、セル24×36）を使う。
- ステージ（内部px）: 幅およそ960（画面3枚分）×高さ180。
  - y 0〜約100: 建物のファサード列（建物の下端を y≈100 に揃える）
  - y 約104〜148: 歩ける帯（足元がこの範囲）
  - y 約150〜180: 車道（歩けない）
  - 地面（歩道のタイル・縁石・車道と白線）は**コード描画**
- 操作:
  - キーボード: 矢印/WASD で8方向、Shift で速歩き、Z/Enter/Space で決定（入る・しらべる・話す・文送り）、
    X/Esc で閉じる、M でマップ
  - マウス/タッチ: 地面をタップしてそこへ歩く。入口・人・物をタップすると、その前まで歩いてから自動で決定する。
    スマホ横向き用に、右下に「しらべる」「マップ」ボタンを出す
- 当たり判定: 歩ける帯＋小物の足元矩形。キャラの足元ヒットボックスは約10×4。壁沿いに滑る。
- 決定対象: 足元から約20px以内で、向いている方向にある最も近いもの。対象があれば頭上に小さな「！」。
- メッセージウィンドウ: 画面下部、黒地＋白の二重枠のレトロRPG風。
  フォントは `assets/fonts/DotGothic16-Regular.ttf`。1文字約30msのタイプ表示。
  1回の表示は全角24字×2行以内（テキストに手動改行を入れない）。
- **看板の店名など文字はすべてコードで描く**（画像に焼き込まない）。各入口の上に店名ラベル。
- 画像が無い・読めない場合はプレースホルダで最後まで動く。画像を置けば**コード変更なしで差し替わる**。
- `?night=1` で夜（全体に濃紺の乗算＋窓の灯り）。余力があれば。
- デバッグ用に `window.__street = { warp(doorId), state() }` を公開する。

## 5. 画像（6枚）

### 共通ルール（全画像）
- 透過はAIに頼まない。**背景は完全な単色マゼンタ(#FF00FF)**で描かせ、透過はスクリプトでやる。
- ドットの粗さもAIに頼まない。普通の画質で生成し、スクリプトで縮小・減色して揃える。
- 画風参考: `assets/backgrounds/bg_eden_shop.png` を第一基準にする。温かい照明の2Dドット絵〜ピクセルペインター調で、
  輪郭・影・質感に細かいドット感を残す。リアル写真調や滑らかすぎる3D調にしない。
  シーシャ台の先端は小さい凸型の金属ポストにし、凹んだカップ型・ボウル一体型・大きな先端パーツにしない。
- 文字・ロゴ・数字・透かし・フレーム・マスの区切り線を入れない。影を背景に落とさない。
- 特定の既存ゲームの模写はしない（一般的な「16bit時代のレトロJRPG」の画風で）。
- 生成した元画像は `asset_sources/images/proto_walk/`（キャラ）・`asset_sources/images/proto_street/`（街）に保存する。
  作り直した場合は `_try2` のように連番で残し、採用したものを指定のファイル名にする。各画像は最大3回まで。

  - 歩行実験ページ（`web/proto/walk/`）を開けば、つむぎが生成画像に切り替わったかと8方向の一覧を確認できる。

  - クロマキー → 透過後の**連結成分（塊）ごと**に切り出す（グリッドからはみ出しても切れるように）→ 位置で並び順を決める
  - 建物は**6棟共通の縮小率**で縮める（ドアを同じ大きさで描かせているので、共通倍率ならドアも揃う）。
    基準は「ドアの高さ ≈ 40px（キャラ32pxの約1.25倍）」。建物の高さはおおむね90〜110pxになる想定
  - 小物の目安の高さ: 自販機40／ベンチ18／立て看板22／植木20／街灯64／自転車22
  - 倍率1（拡大しない）で出力し、減色（48色程度）。半透明は二値化する（`pixelize.py` と同じ方針）
  - 出力: `assets/proto_street/facade_{cafe,peppermint,kemurikusa,filler_a,filler_b,filler_c}.png`、
    `assets/proto_street/prop_{vending,bench,aboard,plant,lamp,bicycle}.png`
  - 生成後、各ファサードのドアの位置を画像で確認し、`stage_hankagai.json` の doors の x / w を合わせる。
