# プレイヤーのロード容量（2026-10-10計測・10-11整理）

**初回タイトルの通信は約21MB、NEW GAMEの冒頭までで累計約21.4MB。第1章の検証ルートでは同梱ファイル約62MBを参照し、再取得・外部BGMを含む通信は約116MBだった。** 約230MiBの配信物全体を起動時にダウンロードしているわけではない。

対象は `bf75d572ec45bc349955c2bdfabf01db9cbd1b41`。その後の帰宅演出・会話待機の修正は画像・音声を変更していない。この数値は計測時点の実装の記録で、将来の素材追加やルート変更では増減する。

標準のGitHub Pages URLは10月10日と11日の確認で404。既存のmainの公開ワークフローも `actions/configure-pages` で失敗していたため、同じゲームをローカル配信して測った。**公開ホストの実測値ではなく、圧縮・キャッシュ・音声のRange配信により実際の通信量は変わる。**

単位はMB＝1,000,000 bytes、MiB＝1,048,576 bytes。根拠は [計測結果JSON](../reports/load-capacity-20261010.json)。各段階の通信は累計、再訪の「追加」は直前との差分。

## 初回起動・開始・再訪

Chromium 154.0.8037.57、1280×720、新しいブラウザコンテキスト。タイトルの自動先読みが落ち着くまで待ち、NEW GAMEの冒頭を表示し、同じコンテキストでタイトルを再訪した。

| 段階 | 通信した本文・標準preview | 参照した同梱ファイルの全容量（重複除外） |
|---|---:|---:|
| 初回タイトル＋自動先読み | 20.87MB | 21.34MB |
| NEW GAMEの冒頭まで | 累計21.37MB（追加0.49MB） | 21.83MB |
| タイトル再訪 | 追加6.48MB | 21.83MBのまま |

標準previewはコード・JSONを `no-store` で配信し、gzipを使わない。再訪では画像・フォントはキャッシュから読んだが、コード・JSON約2.09MBと、途中までしか保持されていないタイトルBGMの再取得が発生した。

比較用にgzip・Range・600秒キャッシュを有効にした配信モデルでも計測した。初回18.35MB、冒頭まで累計18.84MB、再訪で追加6.29MB。再訪時の追加は音声で、ほかのファイルはキャッシュから読んだ。**このモデルも公開ホストの再現を保証するものではない。** 音声はブラウザが先読みを途中で止めるので、キャッシュが有効でも「再訪は必ず0MB」にはならない。

初回に参照するファイルの内訳は次のとおり。音声の全容量と実際に受信したバッファ量は異なる。

| 種類 | ファイル全容量 |
|---|---:|
| 画像48ファイル（タイトル・UI・自動先読み） | 9.57MB |
| フォント3ファイル | 2.93MB |
| タイトルBGM | 6.76MB |
| JS・CSS・HTML | 1.05MB |
| JSON34ファイル | 1.04MB |

## 第1章の検証ルート

既存の `playthrough.mjs` を1回実行。会話はturbo、ミニゲームは自動操作。DAY1〜14、初回の配達、買い物、占い、雨のマップ、セーブ・ロード、大会の敗北→再挑戦→優勝を含む。全分岐や全恋愛ルートを通ったものではない。通常プレイとは曲の切替頻度と滞在時間が異なる。

| 種類 | 参照した同梱ファイル（重複除外） | 通信本文（再取得を含む） |
|---|---:|---:|
| 画像132ファイル | 29.73MB | 29.73MB |
| 同梱BGM6ファイル | 27.12MB | 外部BGMを含め76.67MB |
| フォント4ファイル | 2.94MB | 2.94MB |
| JS・CSS・HTML113ファイル | 1.12MB | 3.25MB |
| JSON34ファイル | 1.04MB | 3.11MB |
| 合計 | **61.95MB（59.08MiB）、289ファイル** | **115.69MB（110.33MiB）** |

この合計のファイル容量はリポジトリ内の同梱ファイルだけ。コンティニューの外部BGM（BGMer）約2.81MBの通信は右列に含み、左列には含まない。左列は全ゲームの最大容量でも、実際のダウンロード量の上限でもない。

同じ卸店BGMに13回の要求があり、合計約44.9MBを受信していた。同じ曲でも別の `Audio` を作り直すこと、部分バッファのまま曲を切り替えること、セーブ・ロードによる再訪が積み重なる。`.bgm` の大会曲は復元用の取得Promiseを共有しており、このルートでは各1回だった。

17件の音声 `ERR_ABORTED` は曲の切替に伴う先読み中断。HTTPエラー・その他の通信失敗・ブラウザ例外は0。最終時点で未完の音声要求が2件あるため、通信量はその時点までに観測した量であり、曲を最後まで受信した場合の総量ではない。

## 約230MBの正体

公開ワークフローは `assets/`・`remake/`・`data/` とアイコン・エディタ・ルート転送HTMLをコピーする。計測コミットの合計は **243,966,173 bytes＝243.97MB＝232.66MiB**。230程度という値に対応するのはこの配信フォルダのサイズ。

| リポジトリ内の領域 | 容量 | 公開ワークフローに含むか |
|---|---:|---|
| `assets/`（元PNGや音声など） | 189.77MB | 含む |
| `remake/`（実行コード・表示用WebPなど） | 52.75MB | 含む |
| `data/` | 1.37MB | 含む |
| `asset_sources/`（原画・制作資料） | 1,361.84MB | 含まない |
| `.claude/` | 83.13MB | 含まない |
| `docs/`・`brand/`などの資料 | 約0.95MB | 含まない |

配信に元PNGと表示用WebPが両方あるが、ゲームはWebPが用意された絵にはWebPを選ぶ。配信物の全ファイル、制作資料、録画を起動時に一括取得する処理はない。

軽量化するなら、通信量にはBGMの再取得と初回画像先読み、配信物の容量には未参照素材の梱包範囲が効く。このPRでは容量の実測と再計測手段を追加し、音声・素材の運用は変更していない。

## 再計測

```bash
python3 remake/tools/serve_preview.py --port 8123
CHROME_EXECUTABLE_PATH=/usr/bin/chromium node remake/tools/measure_load.mjs /tmp/first-load.json

# gzip・Range・600秒キャッシュの比較用モデル（本番ホストではない）
python3 remake/tools/serve_load_audit.py --port 8124
BASE_URL=http://127.0.0.1:8124/remake/ CHROME_EXECUTABLE_PATH=/usr/bin/chromium node remake/tools/measure_load.mjs /tmp/model-load.json

# 章全体を再計測する必要があるときだけ実行（通常の修正検査には不要）
LOAD_REPORT=/tmp/chapter-load.json CHROME_BIN=/usr/bin/chromium node remake/test/playthrough.mjs
```

Playwrightが必要。公開URLが使える場合は `BASE_URL` で対象を変更する。同梱ファイルの全容量はローカルチェックアウトを使うので、公開版のコミットと一致させる。

本文量はCDPの完了量から既知のヘッダを引き、キャッシュ・304は0として数える。完了した応答にContent-Lengthがあればそれを上限とする。今回の外部音声ではHTTP/2の付帯分3,105 bytesをこの方法で補正した。JSONには補正前の記録も残す。未完・中断した音声は観測時点の受信量、ファイル全容量は要求URLを重複除外して別に集計している。
