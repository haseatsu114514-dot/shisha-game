# 演出の終端・帰宅の扉の修正（2026-10-11）

PR [#283](https://github.com/haseatsu114514-dot/shisha-game/pull/283)。途中版 `4010643c` とその前の `6e0d053` のイージング調整を引き継ぎ、実際のブラウザで通常速度の終端を確認した。

## ゲーム内の変更

- マップの「家に帰る」だけ採用済みの扉aを使う。ほかの行き先はピンから広がる短い演出。扉は約2.0秒から約1.3秒、ほかの移動は約0.8秒。画像のロードが遅いときは全面を覆って待つ。
- 開いている扉に会話や選択肢が先に出ていた原因は、背景の差し替え完了で待機Promiseが解決し、扉の開き終わりを待たないこと。幕を外すまで会話の文字送りを始めず、tonari・ショップなどの新しいメニューも出さない。古いマップは全面を覆ったところで片付ける。
- チェキはペンの最終着地点が70px戻ってしまう計算を直し、紙へなめらかに着地する。背景のドットは1周期で28pxタイルの整数倍移動し、繰り返しの境目をつなぐ。
- チェキ・贈り物の最後の光は消え切ってから演出を終了する。チェキの拡大・中央移動も実際の完了を待ち、CGへ同じ位置・大きさで渡す。
- 共通の放射線・紙吹雪・きらめきは区間ごとのイージングにし、輪は透明・線幅0まで消す。演出の撤去時にループを含めてアニメーションを解放する。

比較用の `?move=door`・`?move=pin`、`?movar=a|b`、配色指定は維持。既定の採用は扉a・チェキb・占いa・贈り物a・バイトb・サメb・スケッチb。

## 確認

`motion_endings.mjs` は通常速度の21ケース。PCは扉・チェキ・占い・贈り物・バイト・サメ・スケッチ・朝4種、スマホ横画面は8種、共通部品を使う別案のチェキa・贈り物bも検査した。消えかけの光の打ち切り、ペンの同フレームの飛び、チェキと本編CGの位置、Enterの抑止と解放、遅い背景、後片付けを確認。SKIP・動きを減らす設定・例外時の解放もPASS。録画の終端、PC・スマホの表示を目視で確認した。

`navigation_transitions.mjs` は7ケースPASS、ブラウザ例外・通信失敗0。

| ケース | 確認 |
|---|---|
| 実マップ→帰宅、PC・スマホ | 帰宅だけ扉。約1.3秒。幕の途中は新しい台詞が空のまま、終了後に帰宅の会話が始まる |
| 実マップ→tonari、PC | ピンの演出。終了後に客・バイトの選択肢 |
| 実マップ→ショップ、スマホ | ピンの演出。終了後にショップUI |
| 遅い場面画像＋先頭が選択肢の会話 | 同じ背景を要求する会話も進行中の開き終わりを待つ。選択は終了後に使える |
| 演出中に次のメニュー指定を更新 | 古い予約で新しい画面を消さず、最後の画面だけ出す |
| 動きを減らす設定の帰宅 | 扉を省略した短い幕。途中に会話を出さない |

第1章の通し検査はロード容量の計測を兼ねて1回実行し、敗北→再挑戦→優勝、セーブ・ロード、能力上限、画面の残留、BGM切替がPASS。追加の帰宅修正後は上記の関連箇所を検証し、通し検査は重複実行していない。[ロード容量の報告](player_load_capacity_20261010.md)。

CIの `Motion endings` は計測器の検査→演出21ケース→ナビゲーション7ケースを直列で実行する。既存の `Remake browser regressions` によるセーブ・ロード検査もマージ前に確認する。他チャットのPRやClaudeのブランチには変更を加えていない。
