# 温度による背景変化 — Claude引継ぎ

## オーナーの依頼と保存理由

蒸らし以降に、シーシャの熱量で背景アニメーション・色・絵が変わるシステムを本編へ入れる。かなり高温なら火炎になる。下記の動画を実際に再生し、忠実に参照する。使用リミットが迫る場合はGitHubへ保存してClaudeに引き継いでよい。画像生成が必要になったらCodexへ頼む。

参照: https://x.com/37564114ne/status/2108096009616458136?s=20

## 実際に見た映像

Codexのアプリ内ブラウザでMP4を実際に再生し、シークして途中の段階も目視した（14.848秒）。動画自体は辛さ／難易度の選択画面。実物の温度測定ではなく、ゲーム内の温度イメージへ転用する。

- 冒頭: 鮮やかな黄色／黄橙、濃い青の輪郭、斜めに流れる大小の四角模様。中央の料理は通常の絵。
- 約1〜3秒: 段階が上がるとオレンジが強くなり、四角の模様が強調される。注ぐ動作とキャラの表情も段階で変わる。
- 約5秒: 全面の背景が赤へ切り替わる。黄色とオレンジの炎が下から立ち、中央の絵も燃える。煙・火の粉が上昇。
- Extraの最上段（約9〜11秒）: 紫の背景、黄緑／ミント色の炎、黒〜紫の煙、焦げた中央の絵。炎・煙は動き続ける。

## 保存済みの実装

`remake/js/craft/thermal.js` がCanvasで背景を描く。6段階（yellow cold / warming / orange ready / hot / red fire / purple inferno）。過熱は0.76以上、灼熱は0.90以上。適温0.46〜0.62は既存 `conditions.js` と共有。左のシーシャ上にはSVGの煙／炎の絵を重ねる。動画のキャラ・UI・音声はコピーしていない。背景と煙／炎はコードで描くため画像生成は不要。

`session.js` でベンチへ接続し、`steam.js` は温度計と同じ実温度を毎フレーム渡す。`pull.js` は待機中に予測針へ追従せず実温度へ追従する。`care.js` は実際の炭の操作後の温度へ追従する。trialも直前の温度を保持。蒸らしのストップで背景とSVGを停止し、別工程ではリセットする。CSSは操作欄を暗くして文字と弾幕を保護し、reduced-motionでは動きを止める。

## 確認済み／未完（2026-10-09 Claude更新）

確認済み（Claudeのクラウド環境・Chromium）:

- `remake/test/thermal_background.mjs` を実行し通過。追加で、オーナー指定の色（低温は薄い、適温は緑、過熱は赤、灼熱は紫）、炎がボウルの後ろから昇る位置、見出しの暗幕、蒸らしのやり直しで前回の熱を残さないこと、吸い出し後の温度一致を検査する。
- 局所回帰 `craft_focus.mjs` が通過（キッチンタイマー・弾幕・吸い出し・コメント欄、デスクトップ／横持ち／縦長）。
- 練習・大会の蒸らし弾幕、吸い出し、熱管理、審査、タイマー設定画面を撮影して目視。文字・雑念弾・心拍線・はじめの絵が読める。[確認画像](../../asset_sources/thermal-background-20261009/README.md)

目視で見つけて直した点:

- 炎・煙のSVGがボウル全体を覆い、台がたいまつに見えた → 台の部品の後ろへ回し、ボウルの中ほどから包むように昇らせる。炎は外炎・中炎・芯の3層。
- 見出し帯の暗幕が素材スキン（`data-art-skin`）の同じ詳細度の規則に負け、黄色の上の白文字が読みにくかった → 熱のCSSをスキンより後へ移動。
- 作業風景の色味がカウンターと周辺減光に隠れてほぼ変わらなかった → 台の周りと手元から熱の色で照らす `.thermal-glow` を追加（段階で強くなる。停止中・reduced-motionでは脈動しない）。
- タイマー設定画面・蒸らしのやり直しで前回の温度の段階が残った → 蒸らしへ入るときは炭を置いた直後の温度から始める。

色の変更（TH02）: 作業中のオーナー指示「適温だと緑、やばいと赤や紫、低い時は薄い感じから」に従い、参照動画の黄→橙→赤→紫から、薄い霧→薄い緑→緑→橙→赤→紫へ差し替えた。灼熱の炎は黄緑からマゼンタへ変更。

## 作業環境の注意

GitHub mainから取得した独立の一時チェックアウトを使った。旧 `web/` は削除済みで、オーナーはこのチャットで「web/は不要、remake/・data/・assets/を確認する」へ安全条件を更新済み。Godotを探さない。

巨大な原画や音声を避けたpartial/sparse clone。初期Git取得が遅く、Pythonのシステム証明書と認証のないraw URLの取得にも失敗した。GitHub APIで表示用画像／フォントを取得してblob SHAを検証したが一部で取得が中断した。ブラウザ素材不足は実装不具合と混同しない。別の環境では新しい独立チェックアウトで対象素材を揃える。未マージのため一時チェックアウトは保持する。
