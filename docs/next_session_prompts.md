## 1. 大会賞金スケーリング（5万一律 → 3→5→10→50万）

### 【アイデア／推奨】
現状ch1で **いきなり5万** は確かに大きい（初期所持金30,000円・バイト下限8,000円・家シーシャ一式24,800円の経済感に対して過剰）。
章が上がるほど賞金が伸びる＝「世界に近づくほど桁が変わる」体感が出るので **章スケーリング推奨**。推奨テーブル：

| 章 | 大会 | 優勝賞金 | 補足 |
|---|---|---|---|
| ch1 | SMOKE CROWN CUP | **30,000** | 地方大会。初期金と同額で「元手を一度取り返す」感 |
| ch2 | 全国 | **50,000** | 予選/準決の進出ボーナスは小さく（例 +5,000 / +10,000）、決勝優勝で50,000 |
| ch3 | 世界（東京） | **100,000** | |
| ch4 | ドバイ世界大会 | **500,000** | ここだけ桁が跳ねる＝最高峰の演出 |
| ch5 | 隠しボス | **賞金なし** | スコアUIを出さない興行外なので金銭報酬は無し（レシピ等で報いる） |

⚠️ **要決定（2点）**:
1. 初期所持金30,000をどうするか。ch1賞金を30,000にすると「初期金と同額」になる。下げるなら20,000程度に。balance.mjs の黒字前提が崩れないか再検証が要る。
2. ch2の段階賞金（現状 予選10,000/準決15,000/決勝30,000=計55,000）を、進出ボーナス小＋決勝50,000 に組み替えるか、決勝一発50,000のみにするか。

### 現状コード（目安）
- ch1優勝: `web/js/game.js` 4792行付近 `addMoney(50000); // 優勝賞金`
- ch2段階: `web/js/game.js` 4870〜4905行 `CH2_STAGES`（`qual.prize:10000 / semi:15000 / final:30000`）、付与は4989行付近 `addMoney(cfg.prize)`
- 付与関数: `addMoney(amount)` 437〜457行（`state.money` 加算・バナー表示・HUD更新）
- 初期所持金: `state.money = 30000`（143行 `newState()`）

### 実装プロンプト
```
web/js/game.js の大会賞金をハードコードから「章ごとのスケーリング」に変更する。

1. 章→優勝賞金のマップを1箇所に定義する（例 CHAPTER_PRIZE = {1:30000, 2:50000, 3:100000, 4:500000, 5:0}）。
   将来 ch3/ch4 をブラウザ実装したときに自動で効くよう、章番号から引く形にする。
2. ch1優勝の addMoney(50000)（4792行付近）を CHAPTER_PRIZE[1] 由来に置換。
3. ch2の CH2_STAGES（4870〜4905）を、決勝優勝=CHAPTER_PRIZE[2]、予選/準決は小さな進出ボーナス
   （+5,000 / +10,000）に組み替える。addMoney(cfg.prize)（4989付近）はそのままで値だけ変える。
4. リザルト画面・LIME・セリフに「5万」等の賞金額が直書きされていないか grep（"5万" "50000" "50,000"）。
   あればトークン化 or 文言修正。
5. balance.mjs（web/test/balance.mjs）の期待値を新賞金に合わせて更新し、黒字維持・無理して寝込む等の
   既存検証が通るよう再調整。playthrough は craft>=80 で南雲票勝ちなので、賞金減で詰まないか通しで確認。

⚠️ 初期所持金 state.money=30000（143行）を下げるかは別途オーナー判断。今回は触らず、賞金スケーリングのみ実装でよい。
受け入れ条件: 7本テスト緑。ch1で30,000・ch2決勝で50,000が入る。リザルト/HUDに数値が露出していない（所持金表示はゲーム仕様通りでOK）。
```

## 2. 凛の実験（試作）フレーバーの扱い

### 【アイデア／推奨】
オーナー案（A:コミュニティ／モルモットイベントで仲良くなる演出、B:ch3以降で時差発売されたら使える）は **両方採用が綺麗**。
シーシャ文化的にも **未発売の他社サンプルを公式戦・営業で出すのは規約違反** なので、**ch1の試作は「試香オンリー＝はじめの舌を育てる」用途に限定**し、競技/接客では使えなくする。そして **凛が「モルモットくん」の感想を反映して仕上げた一袋が、ch3以降にNIGHTSIDEから正式発売 → そこで初めて配合に使える**、という時差ペイオフにする。

これは「はじめの繊細な舌が製品を形にした」という承認の回収になり、ch3（味覚／継承）への伏線にもなる。

⚠️ **現状との衝突＝要決定**: 今の `nightside_earlgrey`（試作）は **制限なしで大会・バイトに使え**、しかも「spiceカテゴリ初解放＝余韻/高火力テーマの2マッチが初めて可能になる」という **大会バランス上の役割** を持たされている（web_version_plan.md 第6便）。試作を競技不可にすると、この2マッチ手段が消える。
→ **推奨**: spiceカテゴリの2マッチは、凛の試作とは別に **通常のブロンドspiceフレーバーを1種** 追加して担保する（例: 既存の正規ラインに spice を1つ）。凛の試作は「知識・好感度・舌の成長」専用にする。

### 現状コード（目安）
- 定義: `data/flavors.json` 88〜99行 `nightside_earlgrey`（短名「NS アールグレイ」/ category:spice / price:0 / leaf:blond / `requires_flag:"_rin_sample"`）
- 解放: `data/dialogue/ch1_rin.json` の `ch1_rin_third`（259行付近で `_rin_sample` を立てる）
- 配合フィルタ: `web/js/game.js` 3939〜3940行（`requires_flag` と `leaf==="blond"` で絞る）— **競技/接客の区別が無い**
- 凛訪問: `web/js/game.js` 2455〜2481行 `RIN_SEQUENCE` / `doRinVisit()`

### 実装プロンプト
```
凛の試作フレーバーを「ch1=試香オンリー（競技・接客で使用不可）／ch3以降=正式発売で使用可」に作り替える。

1. data/flavors.json の試作フレーバーに区分フラグを追加する:
   - "sample": true（試作＝未発売の他社サンプル）
   - "competition_legal": false / "serve_legal": false（大会・バイトで提出不可）
2. web/js/game.js の配合フィルタ（3939付近）を、モード別に出し分ける:
   - 大会(mode==="tournament")・バイト(接客)では sample/競技不可フレーバーを候補から除外。
   - 練習・自宅・凛の試香イベントなど「試すだけ」の文脈では出してよい。
   ※ ミックス画面に出す/出さないの判定箇所を1関数にまとめると安全。
3. ch1の凛イベント（data/dialogue/ch1_rin.json の third）のメッセージを「使えるようになった！」から
   「“感想を聞かせて”＝試香モニター。これは大会では出せない（未発売サンプルだから）」という建て付けに修正。
   報酬は センス/洞察UP＋用語集追記＋好感度（フレーバーの“競技解放”はしない）。
4. ch3以降に「凛がモルモットくんの感想を反映して仕上げた一袋が正式発売」イベントを1つ用意（data/dialogue/ に新規 or 既存の凛ch3導線に追記）。
   そこで competition_legal:true の正規フレーバー（例: nightside_earlgrey_release）を解放する。
   ※ ch3ブラウザ未実装なら「データとフラグだけ用意してフックはTODOコメント」でよい。
5. ⚠️ spiceカテゴリの2マッチ手段が試作に依存していた分を、通常のブロンドspiceフレーバー1種で代替（flavors.jsonに追加）。
```

## 3. LIME連絡先交換の「建て付け」（軽すぎる → ちゃんとした交換ビート）

### 【アイデア／推奨】
現状、**つむぎだけ** が明示的な交換ビート（ひびの入ったiPadでQRをそっと向ける `ch1_tsumugi_second`）を持っていて良い。一方 **みんと等は「訪問回数しきい値」で無音のまま自動的に交換済み** になる＝「気づいたら交換してた」原因。
→ **各ヒロインに“交換した瞬間”のビートを1つずつ用意** し、訪問回数による自動追加は **保険（取りこぼし防止）に格下げ**。交換は「店の連絡用に」「次いつ来るか教えてよ」等、**そのキャラらしい一言**で起こす。

### 現状コード（目安）
- 判定: `web/js/game.js` 1136〜1152行 `hasLimeContact(id)`。`state.limeContacts`（162行）に記録。
  - ①既に交換済み ②会話フラグ `_lime_contact_<id>` ③`state.visits[id] >= LIME_EXCHANGE_VISITS[id]` で自動追加（=無音）
- しきい値: 1131行 `LIME_EXCHANGE_VISITS = { naru:2, adam:3, minto:1, tsumugi:2, sumi:1, rin:2 }`
- 良い例: つむぎは `ch1_tsumugi_second` 内で `set_flag _lime_contact_tsumugi`

### 実装プロンプト
```
LIME連絡先交換を「キャラごとの明示ビート」主導に変える。無音の自動交換をやめる。

1. つむぎ以外の交換相手（みんと/なる/アダム/凛/スミ等）にも、初対面〜数回目の適切な会話の中で
   "交換ビート" を1つずつ用意する（data/dialogue/ の各キャラ会話に1〜2行＋ set_flag _lime_contact_<id>）。
   - みんと: 店モードのノリで「連絡先、交換しとこ？常連割の連絡用ね」等、素を匂わせない範囲で。
   - キャラ口調・関係性に合わせる（軽い相手は軽く、距離のある相手は理由をつけて）。
2. web/js/game.js の hasLimeContact（1136〜1152）から「訪問回数で自動交換」する分岐（③）を
   "保険" に弱める: 明示ビートを通常ルートにし、しきい値自動追加は「ビート未設定キャラの取りこぼし防止」だけに残す
   （= ビート実装済みのキャラはフラグ経由でのみ交換）。LIME_EXCHANGE_VISITS は保険値として維持。
3. 交換が成立した瞬間、LIME上 or トーストで「○○と連絡先を交換した」と一度だけ提示（つむぎと同じ手触り）。
4. 既存セーブ互換（5485行付近の limeContacts 復元）を壊さない。新規ゲームで各ヒロインの交換が
   "ビートを見てから" 成立することを確認。

受け入れ条件: みんと等が「無音でいつの間にか交換済み」にならない。playthrough/ch2 緑（LIME配信が止まらないこと）。
```

## 4. LIME再オープンの不具合（後日開くと前日の内容が残る／古い位置から開く）

### 【アイデア／推奨】
望ましい挙動を先に定義する：**LIMEを開くたびに、その日の新着スレッドを“頭から”クリーンに表示**。前日のDOMが残って古い位置から始まらない。新着が無い日に開いたら「新着なし」のクリーンな状態を見せる（前日の吹き出しの残骸を出さない）。

### 現状コード（目安）
- 朝の受信: `web/js/game.js` 1243〜1256 `morningPhone()` → `limeDueMessages()` を `limeQueue` へ
- スレッド描画: 1258〜1280 `nextLimeThread()`（**スレッド開始時に `#lime-chat`/`#lime-actions` を innerHTML="" でクリア**）
- 吹き出し: 1282〜1291 `addLimeBubble()`（毎回 `chat.scrollTop = chat.scrollHeight`）
- 閉じる: 1447〜1469 `closePhone()`（**ここではDOMをクリアしていない** → 残骸が残りうる）
- 任意表示: 1400〜1409 `phoneShowCustom()`
- スクロール位置の保存機構は無い

### 実装プロンプト
```
LIMEを後日開いた時に「前日の吹き出しが残っている／古い位置から開く」現象を直す。

原因: #lime-chat / #lime-actions のDOMクリアが nextLimeThread() の開始時にしか行われず、
closePhone() や、新着0で開いた経路、phoneShowCustom 経由などで前回の吹き出しが残留する。

1. スマホUIを「開く時」と「閉じる時」の両方で #lime-chat / #lime-actions / #lime-unread を確実にクリアする
   共通関数（例 resetPhoneDom()）を作り、morningPhone / phoneShowCustom / closePhone の頭で呼ぶ。
2. 開いた直後は必ずスクロール位置を先頭（または新着スレッドの先頭）にリセットしてから、
   addLimeBubble の自動 scrollTop=scrollHeight に任せる（＝最新まで自然に流れる）。
3. 新着が無い日に開いた場合の状態を定義: 残骸を出さず「新着はありません」等のクリーンな空表示にする
   （履歴ビューを別途出すなら、それは“最新スレッドの先頭から”表示）。
4. 既読管理 state.limeDone / 連絡先 state.limeContacts のセーブ挙動は変えない。

受け入れ条件: Day Aで読んだLIMEがDay Bで開いた時に残っていない。新着0の日に開いても前日の吹き出しが出ない。
playthrough/ch2/screenshots 緑。スクリーンショットで「開いた瞬間に最新スレッドの頭が見えている」ことを確認。
```

## 5. 縦スクロール撲滅（1280×720に“スクロールせず”収める）

### 【アイデア／推奨】
ステージは16:9固定（1280×720, `#game` は overflow:hidden）。問題は **中央オーバーレイ（`.panel`）が `max-height:86%` + `overflow-y:auto`** で、内容過多のパネルがスクロールする点。方針は **「スクロールできるから良し」ではなく、内容を畳んで収める」**：
- **用語集（5グループ）** → カテゴリ**タブ化**（1グループずつ表示）で1画面に収める。
- **ショップ／練習メニュー** → 2カラム化 or 行高・余白の圧縮。
- **大会リザルト（結果テーブル＋内訳breakdown＋ボタン）** → 内訳を2列グリッド化＋フォント圧縮で1画面に。
- **バックログ／ギャラリー** は性質上スクロール可で許容（が、まずは要否をオーナーに確認）。

### 現状コード（目安）
- 汎用パネル: `web/css/style.css` 856〜867 `.panel`（`max-width:760px / max-height:86% / overflow-y:auto`）
- 用語集: `#glossary-list` 2475行付近 `flex:1; overflow-y:auto`
- バックログ: `#log-list` 2228行付近 / ギャラリー: `#gallery-grid` 2322行付近
- 大会リザルト: `#tn-body`（`#tn-layout` の右 .panel, 620px高）に結果テーブル＋ `.result-breakdown`（2872〜2887）＋ボタン
- LIMEチャット: `#lime-chat` 2101〜2106（ここはスクロール可で妥当）

### 実装プロンプト
```
ゲーム全体のオーバーレイ/パネルを「1280×720でスクロール不要」に収める。

1. まず 1280×720 固定で各オーバーレイを開き、コンテンツが max-height を超えてスクロールするものを列挙
   （用語集 / ステータス / ショップ / 練習 / 大会リザルト＋内訳 / セーブロード / 設定 / くじ 等）。
2. スクロールが出るものを“畳んで収める”:
   - 用語集 #glossary: 5グループをタブ（シーシャの仕組み/リーフ/道具/作り方/大会用語）に分け、1グループずつ表示。
   - ショップ #shop-list / 練習 #practice-menu: 2カラムグリッド化、行高・padding圧縮。
   - 大会リザルト #tn-body: result-table の行高/フォント圧縮、.result-breakdown を2列グリッド、rb-hints の余白削減。
     どうしても入らない場合のみ「次へ」でページ送り（スクロールにしない）。
3. .panel の overflow-y:auto は“最後の保険”として残してよいが、通常プレイで縦スクロールが発生しないことを基準にする。
4. スマホ横向き（アスペクト維持）でも破綻しないこと。

受け入れ条件: 通常プレイで開くどのオーバーレイも縦スクロールせずに全内容が見える。7本テスト緑。
（バックログ/ギャラリーは大量ログ前提なのでスクロール可のまま残してよいか、着手時にオーナー確認）
```

## 8. 第2章「才能の壁 / JEALOUSY HAZE」添削案（初見プレイFB反映）

### 【方針】
2章は「徹頭徹尾沈む章」で、empty_victory の落差を効かせる設計は **成功**。なので **強みは触らず、摩擦点（重複・冗長・矛盾に見える箇所・意味不明な一言）だけを削る**。「鬱の尺が長い」のは演出意図だが、初見が**飽き／混乱**する手前で刈り込む。

### 維持する強み（壊さない）
- スミさんの過去匂わせ（`ch2_sumi_silence`「ガラスの向こうから聞こえる顔」）＋ はじめ「明日も勝てば、全部正しくなる」の慢心
- なるの決別（`ch2_isolation`「全部入ってて、お前がどこにもいない」＋既読無視）／はじめ「勝ってるのは僕です」の豹変（衝撃＝狙い通り）。⚠️ただし**衝突は2章“中盤”から**（序盤のなるは気にかけてくれて、どんどん仲良くなる→中盤で決裂、に組み替える）
- つむぎ「色が、見えないんです」（みんとは衝突させない＝下記7）
- `ch2_empty_victory`（「なんのために勝ったんだっけ」・1章優勝との対比）。⚠️みんとだけは味方に残す（数人の味方が残る方がリアル）

### 直す摩擦点（ファイル対応付き）
全て `data/dialogue/ch2_main.json`（特記以外）。

1. **チャコール博士の口調ブレ＆唐突な粘着**（`ch2_opening` 4行〜）
   - ⚠️**芝居がかった博士口調（ヒッハハ系）は旧設定なので廃止**。基調を「タメ口＋観察的でうっすら不気味」の一本に統一する（「それ、作ったの俺だもん」がこいつの素）。
   - 対応: 芝居がかった行を削り、観察的な怖さに寄せる。初対面の粘着の動機を1行で接地（「1章ラストの白衣・PCの男＝こいつ」が分かる符牒を入れて同一性を繋ぐ）。

2. **神崎・ヴォルクのチラ見せ重複**（`ch2_opening` 末尾 と `ch2_rivals_first_sight` 93行〜）
   - 「刺青の大男が機材を優しく握る」「長身が空調を計測」を2シーンで二度読み。
   - 対応: openingは**気配だけ（シルエット/匂い）**に削り、具体描写は `rivals_first_sight` に一本化。チラ見せ→本登場の段取りにする。

3. **スランプ三部作のリフレイン過多**（`ch2_abyss_baito` 249 / `ch2_slump_taste` 323 / `ch2_sofa_burn` 406）
   - 「組長の覚悟・ヴォルクの精度・あげはのバイブス・なるの情熱──みんな武器、僕には何もない」リストが3回**全部**に出る。
   - 対応: **このリスト独白は1回だけ**（推奨: 最初の abyss_baito に置く）。slump_taste は「味が薄い」身体感覚、sofa_burn は「炭を落とす失敗」と、**各回で別の喪失**を描き分ける。重複文は削る。

4. **あげはの励ましが長い／説教的**（`ch2_pre_tournament_realisation` 464）
   - 「嫉妬＝リスペクト＝武器＝吸収」を5〜6回角度替えで反復。
   - 対応: **尺を半分**に。核（「妬みやすい＝相手の良さに気づける＝武器」）を1〜2回の強い言い回しに凝縮。説明を減らし、あげはの体温（軽さ）で言わせる。

5. **「吸収」アイロニーが“矛盾”に見える**（最重要・`ch2_pre_tournament_realisation` ×`ch2_isolation`）
   - あげは「吸収すればいい」↔ なる「全部吸収して、お前がどこにもいない」。線引きが本文で効かず、初見が「で、吸収はいいの悪いの？」と混乱（1章の“優勝の理由”以上の躓き）。
   - 対応: **同じ「吸収」という語を、二人が別の意味で使っていると分かる楔を1本**入れる。例:
     - あげは側に限定を付ける（「**リスペクトして自分のものにする**のが吸収。借り物で着飾るのとは違うけどね」）＝あげは自身が線を引く。
     - なる側を**あげはの語に呼応**させる（「お前のは“吸収”じゃねえ。**借り物で着飾ってる**だけだ」）＝同語反復で対比を可視化。
   - これで「あげは＝敬意ある吸収（正）／はじめの現状＝借り物（誤）」のアイロニーが**意図**として読める。

6. **なるとの衝突タイミング**（`ch2_isolation` ほか）
   - 現状は早い段階で決裂気味。⚠️**衝突は2章“中盤”から**にする。序盤〜中盤前半は「気にかけてくれて、どんどん仲良くなる」描写を足し、warm→clashの段差を作ってから決裂→既読無視。

7. **みんとは衝突させない**（味方に残す）
   - ⚠️みんとの“笑顔の刃”の刺し台詞は撤回。心配しつつ**味方に留まる**側へ（数人の味方が残る方がリアル）。empty_victory でも「みんとだけは気にかけている」気配を残す。

8. **REIのひとり言が意味不明**（`data/dialogue/ch2_rei.json`）
   - 「“私のこと愛してる？”が、君の口癖」のV系ネタは⚠️**削除**（意味不明なので残さない）。

9. **ヴォルクが偵察客の手の甲で体温測定**（`data/dialogue/ch2_volk.json`）
   - ⚠️体温測定の描写は**削除**（人体接触をやめる・代替演出も不要）。

10. **救い／息継ぎ不足**（章全体）
   - 救いがあげは1シーンのみで「しんどい時間が長い」。
   - 対応: スランプ帯（DAY4〜6あたり）に**小さな救い/笑いの息継ぎを1つ**追加（既存の `ch2_steve_cameo` のような軽さ）。重さを薄めず、empty_victory の落差を**際立たせる**ための“呼吸”。常連のさりげない一言／テツコ的なマスコット小ネタ等、短く。

ℹ️ **保留（演出意図として今は触らない）**: 味覚喪失が「本当に失われた」のか「疲れの主観」かの宙ぶらりんは、ch3で回収する設計なので**現状維持**（初見の宙ぶらりん感は狙い）。
