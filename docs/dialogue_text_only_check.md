# 台詞テキスト限定差分チェッカー (`tools/check_dialogue_text_only.py`)

Issue #690（Refs #564）向けに作成された、変更前後のJSONファイル間で「明示的に許可された RFC 6901 JSON Pointer の文字列（string leaf）以外にいかなる構造・型・値の変更もないこと」を検証する、Python標準ライブラリのみの読み取り専用CLIツールです。

> 本ツールは独立した検査ユーティリティであり、Issue #564 の台詞修正作業そのものを編集・完了するものではありません（Issue予約は2026-10-23に撤廃済み）。

---

## 使い方・コマンドライン引数

3つのファイルパス（変更前JSON、変更後JSON、許可Pointer配列JSON）を位置引数として明示的に指定します。ネットワークアクセス、Git操作、自動修正、入力ファイルの書き換えは一切行いません。

```bash
python3 tools/check_dialogue_text_only.py <before_json> <after_json> <allowlist_json>
```

### 終了コード（Exit Code）と出力仕様

| 終了コード | 意味 | 標準出力 (`stdout`) | 標準エラー出力 (`stderr`) |
| :--- | :--- | :--- | :--- |
| `0` | 検証成功（許可された文字列leaf以外の差分なし） | 空 | 空 |
| `1` | 許可外の変更を検出 | 空 | `DIFF category=<分類> path="<RFC6901 Pointer>" detail=<詳細>` を決定的な順序で1行ずつ出力 |
| `2` | 入力エラー（引数不正、ファイル読込失敗、JSON構文エラー、重複キー、非有限数、allowlist違反など） | 空 | `INVALID_INPUT: <理由>` を1行出力 |

- **本文・値の非漏洩**: 診断メッセージには RFC 6901 Pointer と変更分類（`unallowed_string_change`, `scalar_value_change`, `type_mismatch`, `missing_key`, `extra_key`, `array_length_mismatch`）のみを出力し、変更前後の台詞本文やスカラー値、ファイル断片、Pythonトレースバックは出力しません。
- **安全な1行エスケープ**: Pointer表示は制御文字や改行をエスケープした二重引用符付きの1行形式（ルートPointer `""` を含む）で出力されます。

## Allowlist（許可リスト）の仕様と記入例

`allowlist_json` は、変更を許可する **RFC 6901 JSON Pointer 文字列のJSON配列** です。

### 記入例

```json
[
  "/scenes/0/text",
  "/scenes/0/choices/0/label",
  "/scenes/0/choices/0/subchoices/0/text",
  "/special/a~1b",
  "/special/c~0d"
]
```

変更がまったくないことを検証する場合は、空配列 `[]` を指定できます。また、allowlist に記載されたパスが実際には変更されていなくても（前後とも存在する文字列leafであれば）エラーにはなりません。パス件数や文字数の固定上限はありません。

### 厳密な検証ルール

差分比較を行う前に、3つの入力JSONすべてと allowlist の全要素に対して以下の厳密な検証を行います（違反時はすべて終了コード `2`）。

1. **JSON構文・重複キー・非有限数の禁止**
   - `before_json`、`after_json`、`allowlist_json` の全階層において、同一オブジェクト内の重複キーを拒否します。
   - `NaN`、`Infinity`、`-Infinity` などの非有限数定数、および不正な UTF-8 や UTF-8 BOM を拒否します。
   - JSON解析後であっても、比較処理などでPythonの再帰上限に達した場合は、本文やtracebackを出さず入力エラー（終了コード `2`）として拒否します。処理可能な深度は実行環境に依存し、上限を超えた入力を成功扱いにはしません。
2. **前後両方に存在する string leaf のみ許可**
   - 各Pointerは `before_json` と `after_json` の**両方**に存在し、かつ両方で JSON の文字列型（`string`）である末端（leaf）を指していなければなりません（ルート自身が文字列の場合の `""` も可）。
   - オブジェクトや配列（コンテナ）への包括許可、数値・真偽値・`null` の指定、片方にしか存在しない（追加・削除された）パス、存在しない余計なパス、allowlist内の重複Pointerはすべて拒否されます。
3. **厳密な RFC 6901 Pointer 構文**
   - 空文字列 `""`（ルート）または `'/'` で始まる文字列のみを受け付けます。
   - URIフラグメント形式（`#/...`）やパーセントデコード（`%20` 等）は解釈せず、`#` 始まりは拒否、`%` はリテラル文字として扱います。
   - エスケープは `~0`（`~`）と `~1`（`/`）のみ有効です。その他の `~` 表記はすべて拒否します。
   - 空キー（例: `"/special/"` の末尾空トークン）や Unicode キー、数値風オブジェクトキー（例: `"01"`）も RFC 6901 どおり正確に解決します。
4. **ワイルドカード非対応（`*` の扱い）**
   - `*` にワイルドカード展開の意味はありません。キー名一括許可もありません。
   - 配列に対する `*` は非正規インデックスとして拒否され、オブジェクトに対する `*` は文字どおり `"*"` という名前のキーが実際に存在し、かつその値が前後とも文字列である場合のみリテラルキーとして解決されます（存在しなければ不存在キーとして終了コード `2` で拒否されます）。
5. **配列インデックスの正規表現**
   - 配列要素を参照するトークンは、正規の非負整数（`0` または `[1-9][0-9]*`）かつ配列長未満の範囲内のみ許可します。先頭ゼロ（`01`）、符号付き（`+0`, `-1`）、`-`、全角数字、範囲外（巨大インデックスを含む）はすべて拒否します。
6. **型と数値精度の比較**
   - JSON の真偽値（`true`/`false`）と数値（`1`/`0`）は明確に別型として区別します。
   - 数値は `decimal.Decimal` 等で厳密に比較し、`float` 丸めによって大きな整数や高精細小数の差を見逃しません。
   - 整数も `Decimal` で読み込み、Pythonの整数文字列変換の桁数上限による例外を避けます。`Decimal` 自体の表現範囲を超える指数などは本文を出さず入力エラー（終了コード `2`）として拒否します。巨大な配列indexも整数変換前に範囲外として拒否します。
   - JSON仕様上、数値は単一の意味型であるため、`1` と `1.0` のように数値として等価な表現は同一値とみなします。数値の字面表記、オブジェクトキーの並び順、JSONの空白・改行差はバイト単位の比較対象ではありません。

## テストの実行方法

オフライン環境で Python 標準の `unittest` から実行できます（一時ディレクトリの fixture のみを使用し、リポジトリ内のファイルは書き換えません）。

```bash
python3 -m unittest discover -s tools -p 'test_check_dialogue_text_only.py'
```

## 保証範囲と限界（重要）

本ツールが保証するのは **「指定された allowlist の文字列leafパス以外に JSON データ上の変更がないこと」のみ** です。以下の点は本ツールでは証明・保証されないため、必ず既存のリンタ・人間によるレビュー・関連テストを併用してください。

1. **ゲーム挙動・報酬・セーブ互換性の非保証**
   - `remake/` の `engine.js` における `parseCue` や演出指定、報酬処理、条件式、シーン遷移などは文字列の内容に依存する場合があります。
   - 文字列leafの変更であっても、制御トークンやタグ、変数展開などを書き換えるとゲームの挙動・報酬・セーブデータの互換性が壊れる可能性があります。本ツールは文字列の中身の意味的安全性や挙動同一性を証明しません。
2. **許可パス同士の入れ替え（意味的な行移動）は検出不可**
   - 複数の文字列パス（例: `/scenes/0/text` と `/scenes/1/text`）が同時に allowlist に入っている場合、それらの間で台詞テキストが入れ替わったり、話者（`speaker`）と台詞の対応が実質的にずれたりしても、「許可された文字列leafが変更された」ことしか分からず、意味的な行移動は識別できません。
3. **過剰に広い allowlist の妥当性は人間のレビューが必要**
   - 実在するすべての文字列パス（`id`, `speaker`, `next`, `condition`, `reward` 内の文字列などを含む）を機械的に allowlist へ列挙してしまうと、ツール上は構文的に有効な string leaf として通過してしまいます。
   - allowlist 自体が「本当に編集対象の台詞テキストだけを指しているか（過剰に広くないか）」は人間が必ずレビューしてください。
4. **既存リンタ・ストーリーレビュー・関連テストの継続実施**
   - 本ツールは既存の台詞・データ検証リンタ、キャラクター設定・世界観・改行ルールの本文レビュー、およびゲーム本体の関連テストを代替するものではありません。引き続きそれらを実行・確認してください。
