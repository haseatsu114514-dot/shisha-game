## 0. 要約

1. **いま弱いのは個々の画面ではなく「構造」**。作業台は LESSON と大会で中身が同じで、ライバル3人は文字でしか存在せず、審査員の持ち点は最後まで動かず、工程の出来は左下の小さな一言で終わる。盛り上がりが結果発表の10カウントに全部寄っている。
2. 解決の軸は**「生中継」の枠組みを大会モードの作業台に被せる**こと。ただし枠に映すのは観客の盛り上がりではなく、**一台の熱の記録（ヒートライン）**、**相手3人の台の実状態**、**審査員の一口の判断**。実際に作ったことがある人が「そこを見るよね」と頷く情報だけを増やす。
3. 工程を終えるたびに**決めカード**（◎○△のスタンプ＋審査員の顔＋**その工程の実記録**＝「取り頃で3個」「外周12穴が揃った」「提供は適温・低め」）で区切り、**ジャスト炭・提供が適温・帯外から戻した**などの実際の山場で審査員4分割カットインが出る。
4. 結果発表は **10カウント → 南雲の10点 → 4位から呼ぶ順位発表 → 表彰（ヒートライン・ハイライト3枚・審査員の一言・称号）** の4段にし、優勝の「溜め」を作る。
5. 採点・勝敗・難度は変えない（`score.js`・`NAGUMO_BAR`・調整2回の配点は現行のまま）。中間投票だけ、実績に連動させる案（§3.4）を推奨するが、これはオーナー判断。

## 2. 体験の目標と守ること

**目標**: 「一台の熱を、4人分、60分の生中継で見せる」。
操作は変えずに、①自分の一台の熱の軌跡が見える ②相手3人の台の実状態（炭・煙・温度帯）が見える ③審査員の判断が一口ごとに動く ④工程ごとに実記録で決め所がある ⑤最後に溜めて爆発する、の5点を画面で成立させる。

**設計の原則（TC06）**
- 画面に出す情報・反応・見せ場は、**その一台と相手の台の実状態**から出す。観客の気分を表すメーターは作らない。
- 観客が反応するのは、客席から見えるもの（煙の量と色、炭の火、手元の動き、審査員の顔）だけ。
- 数字は疑似精密にしない（E06）。温度は帯の呼び名で、炭は「取り頃・早い・遅い」「灰が厚い・小さくなった」で、葉は赤い葉の枚数で語る。
- 実作経験者が読む順（炭の火 → ホイルの穴と炭の位置 → 蒸らしの長さ → 一口の煙と温度 → 炭の燃え進み → 交換）を、そのまま画面の情報の順にする。

**守ること（既決事項）**
- 採点（`score.js`）、南雲の基準 90.8、配点 20%×5（第1章アルミ省略時の 40%）、吸い出し・調整の操作、焦げ／冷え／葉切れの失敗はそのまま。**新しい演出は点数に影響させない**。
- 表示は ◎（90以上）／○（65以上）／△。大きな S・A 等の等級表示は出さない。
- 制作中に話すのは左下の審査員またはパッキー1人。大会・リハーサルではメタ発言をしない。南雲は静かに考える表情にとどめる。
- 中間票は「実際に投入された持ち点だけ」。南雲は最後まで10点を温存し、1位は南雲票の前から首位（#1282）。
- FLAVOR TRIAL（プレゼン）は再実装しない。蒸らしの雑念は「はじめ自身の内心」。
- 「クリティカル」の語は使わない（ジャスト◯◯で統一）。湿度は出さない。ロートスの蓋の操作・風防・灰落としの新操作は E06 の決定まで入れない（#1129）。
- 動きを減らす設定では、閃光・揺れ・強い点滅を止める（#1950 の設定と同じ境界）。

## 3. 設計の柱（7本）

### 3.1 生中継フレーム — 大会モードだけの作業台クローム

`bench[data-mode="tournament"]` のときだけ、作業台の外側に次を足す（LESSON／PRACTICE／REHEARSAL は現行のまま）。

```
┌ LIVE ● SMOKE CROWN CUP │ ROUND 1 準備 │  ⏱ 12:40  │ [は][な][ア][み] 進行チップ │ 審査員ボード ┐
├──────────────┬────────────────────────────────────┬───────┤
│ 作業風景     │ 工程パネル（現行のまま）                 │ 対戦席 │
│ 審査員の一言 │                                      │ なる   │
│              │                                      │ アダム │
│              │                                      │ みんと │
├──────────────┴────────────────────────────────────┴───────┤
│ ヒートライン（一台の熱の記録） ─── 流れるコメント（作業中も薄く流れる） ─── │
└───────────────────────────────────────────────────────┘
```

- **試合時計**: 「経過 mm:ss」のカウントアップ。実際の工程時計（`clock.js`）が動いている間だけ進み、会話中は止まる。制限時間 60:00 は表示だけで、**時間切れの失敗は作らない**。
- **4人の進行チップ**: 顔アイコン＋現在工程の小アイコン＋**温度帯の色**（まだ火が入っていない人は無色）。はじめは実際の工程と実温度、ライバルは §3.2 の台本。
- **審査員ボード**（右上）: 上園・博士・南雲のチップに「投入 n／残り m」。南雲は錠前付きで「10」。票が動く瞬間に光る。
- **ヒートライン**（下）: §3.3。
- 1280×720 では対戦席を右に 152px、844×390（スマホ横）では対戦席を上バーのチップに畳み、ヒートラインは上バーの下の細い帯にする。工程パネルの入力座標は変えない。

### 3.2 対戦席 — ライバル3人の「台」を読めるようにする

- 右端に3枚の**対戦席カード**（顔・名前・いまの工程・台のシルエット）。台のシルエットには**実作経験者が読む3つの状態**を乗せる: **温度帯の色**（温度計と同じグラデーション）、**炭の数と状態**（赤い／灰が厚い／小さくなった）、**煙の量と色**（白い細い煙／厚い白煙／灰色の煙＝過熱）。
- ライバルの進行は**実時間ではなく、はじめの工程の節目で進む台本**（`rival_timeline.json`／章別）。台本の中身は制作の言葉で書く。例・第1章:

| はじめの節目 | なる | アダム | みんと | 台から見えること（実況・コメント） |
|---|---|---|---|---|
| 配合終了 | **穴あけ**（速い・外周だけ先に） | 詰め（山盛り気味） | 詰め（きっちり） | 「なる選手はもう配合を終えた！」 |
| 穴あけ終了 | 炭（フラット3） | 穴あけ（内周多め） | 穴あけ（丁寧・やり直し1回） | みんとのアルミが一度はがれる |
| 炭焼き終了 | 蒸らし短め | **炭を早取り・黒い面が残る** | 炭（取り頃） | アダムの炭がムラ、煙が薄い |
| 蒸らし終了 | 提供が早い（熱が入っていく帯） | 蒸らし長め→**熱が強い帯・灰色の煙** | 提供（適温） | アダムの台から厚い煙、「焼きすぎでは」 |
| 提供 | 一口「軽い」 | 一口「いがらっぽい」 | 一口「おとなしい」 | 審査員の一口の顔 |
| 調整1回目 | 炭1個追加で立て直す | 炭を1個外して冷ます | 交換1個・安定 | 炭壺の動きが見える |
| 調整2回目 | 安定 | **熱が落ちて煙が細い** | 安定 | 「アダムの台、煙が細い」 |

- 既存の `broadcast.json rivalFeed`・`chapterN.rivalComments` をこの表に紐づけ、該当カードの吹き出し＋流れるコメントの両方に出す。文面の追加はこの表の「台から見えること」ぶんだけ。
- カードをタップすると、その台の読み（例「炭3個・1個は灰が厚い／熱が強い／煙が厚い」）を帯の呼び名で出す。時間・体力は消費しない（情報の確認だけ）。**ここが実作経験者の楽しみ**: 相手の台を読んで、自分の次の炭交換を決める。
- 第2〜4章は出場者が変わる（あげは・神崎・REI／久世・スティーブ・ヴォルク／なる・王煙楼・シェイク）。台本は章ごとに1枚ずつ、第1章を先に作る。

### 3.3 ヒートライン — 一台の熱の記録（「会場の熱」の代わり）

- 画面下の帯に、**その一台の温度が時間の中でどう動いたかを一本の線で描く**。縦は温度計と同じ帯（まだぬるい→熱が入っていく→**適温**→熱が強い→過熱）を同じ色で、横は工程の進み（炭を置く → 蒸らし → 吸い出し・提供 → 調整1 → 調整2）。
- 線の上に**節目の印**を打つ: 炭を置いた（炭の個数・取り頃か）、蒸らし開始〜終了（選んだ分数）、吸い出しの各一口（熱を入れる／キープ／逃がす）、**提供**（その時の帯）、炭が燃え進んで落ちる区間、**炭交換**（個数）、調整の各一口。失敗（焦げ・冷え切り・葉切れ）は線の終点に印。
- 値は**既存の実温度だけを読む**（`temperatureAfterSteam`・`pull.js` の実温度・`careHistory`）。新しい計算も点数への影響もない。数字は出さず、帯の呼び名だけ（E06）。
- 作業中は**現在地の針が線の先端**にある。実作経験者は「提供は適温の低め、1回目の調整で中央に戻し、2回目は炭を替えず維持」という自分の仕事を一目で振り返れる。初めての人には「今どこにいて、どこへ戻すか」の地図になる。
- 流れるコメント・歓声の密度は、客席から見えるもの＝**煙の量と色**（実温度の帯と炭の状態から `thermal.js envAt` の smoke を読む）と工程の結果で決める。観客の気分の値は持たない。
- ヒートラインは R1 の後の中間投票・最終の表彰にも同じ部品で出す（§3.7）。相手の台には出さない（相手の線は見えないのが実戦。見えるのは煙と炭だけ）。

### 3.4 審査員の持ち点を見せる — 投票ボードと「一口審査」

**A. ボード（演出・必ず入れる）**: §3.1 右上のチップ。上園・博士が票を入れる瞬間に、`vote_token` の札がはじめ／ライバルの進行チップへ飛ぶ。南雲は錠前のまま「まだ動かず」。

**B. 一口審査**: 提供と調整のたびに、審査員が**実際に一口吸って顔を変える**（ボードのチップの表情＋短い一言）。一言は現行の `feedback.js`／`served-eval.js` と同じく、**その時の帯と煙**から出す（「熱が強い。でも焦げてない」「ぬるい。香りが開いてない」）。実作経験者が自分でも読める判断を、審査員が声にする。

**C. 中間票の実績連動（推奨・オーナー判断）**: 現行は `interimPointTable(round)` が固定で、はじめの出来と無関係。これを次に変える。

- 上園は R1（配合・穴あけ）と R2（提供の一口）の後、博士は R1（炭）と R3（調整1の一口）の後に票を入れる。はじめへの票は **◎=2／○=1／△=0**（各イベント）。ライバルへの票は台本のまま。
- **#1282 の規則を保つための上限**: 最終集計の前に、`outcomeOf(total)` が1位なら上園＋博士のはじめ票を **6以上**、1位でなければ **4以下**に丸める。これで「1位は南雲票の前から首位」「敗北時は南雲票でなるが抜く」が必ず成立する。
- 中間投票の盤は、票が入る行だけ札が飛んで数字が増える。表示は 3.6 秒固定から**「読み終わるまで」＋最短 2.5 秒**（タップで送る）に変え、盤の下に**ここまでのヒートライン**を出す。

### 3.5 決めカード — 工程ごとの「決まった！」を実記録で

- ミニゲーム終了後、現行の `resultCard`（詳細）を出す**前に 1.1 秒の決めカード**を全幅で出す: `stamp_ring` の輪の中に大きな ◎／○／△、右に担当審査員の顔（表情は評価に連動）と一言（既存 `feedbackLine`）、下に**その工程の実記録1行**（穴あけ「外周12・中周8、均等」／炭「取り頃で3個」「1個早取り」／蒸らし「6分・被弾1」／提供「適温・低め」／調整「炭2個交換 → 適温の中央」）。◎は `hype_burst` の閃光と歓声、△は輪が灰色で静か。
- 途中の山場にも**小さい決め**: 穴あけの EXCELLENT 連続3、炭を取り頃で取った、蒸らし終盤を無被弾、提供が適温帯の中央、調整で帯の外から中へ戻した → 画面端に短い光とコメント（既存の `comment`）。
- 等級の語（S／A）やスコアの数字は出さない。詳細はこれまでどおり任意に開く。

### 3.6 審査員4分割カットインとラウンド構成・テンポ

- **4分割カットイン**（master_spec 第2部 §5 の未実装分）: 発生は**実際の山場だけ**: 炭を全部取り頃で取った／外周が完璧に揃った／提供が適温（低め・中央・高めいずれも帯内）／帯の外から調整で戻した／過熱寸前から救った。セリフは「◯◯！ でも、◯◯！」形式で、**前半はその時の実状態**（「熱い！」「煙い！」「早い！」「軽い！」）、後半は結果（「でも、飛んでない！」「でも、焦げてない！」「でも、雑じゃない！」「でも、味はある！」）。上園・博士・パッキーの3コマ＋4コマ目は南雲が黙って目を細める。
- 見出しを**放送のセグメント**にする: `ROUND 1 準備` を **R1-A 仕込み（機材・水・配合・詰め・穴あけ）** と **R1-B 火入れ（配置・炭・蒸らし）** に見た目だけ分け、R1-A の終わりに 1.2 秒のタイトルプレート（`round_plate`）を挟む（会話は増やさない）。
- ラウンド間の非操作時間の目安: **25 秒以内**（会話はそのまま、中間投票を会話の裏の盤面として出し、速報 2 行はティッカーへ移す）。R2 後の 10＋9 行は、`ch1_tournament_served` の一口の感想を**「一口カード」**（審査員3人の顔＋一言ずつ・一画面）にまとめる案を推奨（台詞の削除はしない。表示形式の変更のみ）。
- R3・R4（調整）に**見せ場**を足す: 一口審査（§3.4 B）と、ヒートラインに「炭が燃え進んで落ちる区間」が見えること自体が緊張になる。アダムの台の煙が細る「事件」を R4 に置く。

### 3.7 結果発表 2.0 — 溜めて、呼び上げて、表彰する

1. **審査（試喫）会話** … 現行。
2. **RESULT 10 COUNT** … 背景を `result_backdrop`（スポットライトの台座）に。カットインは言葉の札から**その試合の実カット**（穴あけのアルミ・取った炭・温度計の帯・提供の煙＝既存の工程画像を小さな額で）に。4人のカードは対戦席と同じ部品。プチュン／パリン／フライングは現行。
3. **南雲の10点** … 現行に `vote_token` ×10 が南雲チップから飛ぶ動きを足す。
4. **順位発表**（新規）… 4位 → 3位 → 2位 の順に、名前と持ち点を呼び上げる（各 1.4 秒）。1位の前で 0.8 秒の暗転 → スポットライト → **「CHAMPION」**。はじめが2〜4位の場合も同じ順で呼ばれ、自分の順位で止まり、敗北会話へ（CONTINUE は現行）。
5. **表彰**（`resultTable` の拡張）… 左: 最終順位と持ち点（現行）。右: ◎○△の6枠（現行）＋**その一台のヒートライン**（提供と調整2回の印つき）＋**ハイライト3枚**（候補は `craftRecognition` とヒートラインから。例「ジャスト炭」「外周12穴が揃った」「調整2回目で帯の中央へ」）＋**審査員の一言3つ**（上園・博士・南雲。南雲だけ短い。内容は一口審査の記録から）。賞金・称号「SMOKE CROWN CUP 優勝」を右下に表示し、称号とヒートラインはタイトルのギャラリー「大会の記録」へ残す。
6. 表彰のあとは現行の会話・LIME（スミさんの採点表）へ。

### 3.8 実作経験者向けのパワーアップ（小さく・点数を変えない）

- **相手の台を読む**（§3.2）: 温度帯の色・炭の状態・煙。タップで読みが出る。大会の面白さの新しい芯で、既存の操作を増やさない。
- **一口審査**（§3.4 B）: 審査員の判断が、自分でも読める実状態の言葉で返る。
- **ヒートラインの振り返り**（§3.3・§3.7）: 「提供は低め、1回目で中央、2回目は維持」のように自分の仕事を語れる。記録として残る。
- **雑念に試合の出来事を映す**: 蒸らしの雑念（`DODGE_WORDS`）に、その試合の実状態から選ぶ内心の言葉を混ぜる（「アダムの煙、気にするな」「炭、1個早かったか」）。**弾の数・速度は変えない**（文面だけ）。
- **記録**: 大会ごとの自己ベスト（総合・各工程の◎数）とヒートライン・ハイライトをセーブに残し、ギャラリーから見返せる。再挑戦（CONTINUE）の動機になる。
- **後続（E06 の決定後）**: 炭交換中心モデル（案A）が決まれば、ヒートラインに「交換した炭の個数・配置で決まる到達温度」がそのまま見えるので、同じ部品で受けられる。蓋・風防・灰落としの操作は入れない。

## 9. 既決事項との整合

| 熱はシーシャの熱（TC06） | 観客ゲージは作らない。下帯・表彰・中間投票に出す「熱」はすべてその一台の実温度の記録。観客の反応は煙と工程結果から |
