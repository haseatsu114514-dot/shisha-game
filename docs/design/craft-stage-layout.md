## 今の画面で気になった点（スマホ16:9＝667×375・倍率0.52で確認）

1. 上の帯・左のカード・右のカードの三分割で、どれも同じ太さの枠と同じ濃さ。主役がない。
2. はじめは額縁の中の絵で、右のパネルの作業と別の場所に見える。ライバルの小窓・工程の灯・温度計が絵に重なる。
3. 熱ゲージは高さ360（画面の半分）。穴あけ・炭焼きでは出ず、詰め方では位置が変わる。
4. 上の帯（高さ64）に空の工程チップと「外観を選ぶ」が常に出る。「？」が炭壺・調整の説明文・はじめの頭に重なる。
5. 決定ボタンの場所と大きさが工程ごとに違い、横持ちの親指（左下・右下）に合っていない。

### 熱の柱の見せ方（2026-11-10 オーナー決定）

「熱ゲージは消灯で大丈夫」「蒸らしてる最中とかは『ぬるい』とかでなくていい。吸い出し以降に出す」。柱は全工程で同じ場所に立て、**状態の札（ぬるい・適温…）は吸い出し以降だけ**出す。

| 工程 | 柱 | 札 |
|---|---|---|
| 配合・詰め方 | 配合の温度帯の予想（今と同じ中身） | 「温度帯」（見出し。状態ではない） |
| 穴あけ・炭の配置・炭焼き | 消灯（灰色） | なし |
| 蒸らし時間 | 目盛りを暗めに出し、蒸らし後の目安の点線だけ（時間を決める材料なので残す） | なし |
| 蒸らし（雑念よけ） | 上がっていく温度と矢印（今と同じ中身） | なし |
| 吸い出し・提供・調整 | 今の温度・適温の線・矢印 | あり（ぬるい／適温・低／最適温／熱い…） |

### 工程ごとの決めごと

- **配合**: 葉の行に商品パッケージ（ショップと同じ絵 `flavorPackageArt`）を高さ約110で出す。1行は122で、4種が一度に見える。スマホは字が大きいので、名前を一行で読めるよう −／＋ を名前の下の段に置き（3種強が見える）、左の器を小さくして予想を全部見せる。色の見方（おいしい範囲・低め／高め）は柱の左上へ。
- **炭焼き**: 決定ボタンが無い工程なので下の列まで使い、コンロを幅約850・炭を幅約176に大きくする。炭壺は右上へ小さく、案内は上の札に。
- **蒸らし（雑念よけ）**: スティックと補助ボタン（リフレッシュ・アタック・精密）は**今と同じく近くにまとめて右下**に置く（押しやすさのための配置。オーナー指示）。雑念の場は舞台の幅いっぱい。
- **蒸らし時間**: タイマーの数字は本編の7セグ（`digital-clock.js`）。液晶とボタンの位置の割合も本編（`.timer-display`・`.timer-button`）のまま。
- **ランク**: オーナーが選んだ D〜SSS の7枚（原画 `asset_sources/ui/craft-rank/`）を使う。上のレールには幅120の小さな札で出し、ランクが変わった瞬間だけ舞台の中央に下の英語まで読める大きさ（幅420）で約1.3秒出してから、レールの札へ縮んで収まる（CSL10。動きを減らす設定では出さない）。

## スマホ横持ちの層（2026-11-20・PHN）

骨組み（上の表）はそのまま、スマホ横持ち（`html[data-density="phone"]`・倍率 0.44〜0.62）で桜井版の作業台をどう置くかは **`remake/css/craft-phone.css` の1枚**で決める。経緯は `docs/owner_requests.md` の PHN。

- なぜ1枚か: この骨組みの CSS（`craft-stage.css`）は `!important` が多く、その上にスマホ補正が5枚（`craft-landscape`・`phone-density`・`wide-craft`・`phone-layout`・`craft-route`）重なっていた。1か所の直しが別の層に負けたり別の工程を崩したりして、重なり・はみ出しが直っては戻っていた。`craft-phone.css` は `#stage #screen` の ID 2つで前の層より強くしてある。**スマホの桜井版の配置を直すときは、この1枚だけを直す**（前の層へ継ぎ足さない）。
- 効く範囲: スマホ横持ち × 桜井版（`.bench[data-craft-version="sakurai"]`）× 一枚の舞台（`body.craft-stage`）。PC の配置と、第1章大会の既定（リニューアル版）は前の層のまま。
- 寸法の変数（作業台の上に定義）: `--ph-tap`（押す所・実寸44.1px）、`--ph-text`（主文・実寸12.6px以上）、`--ph-sub`（補助文・実寸11.6px以上）、`--ph-rail`（上のレールの高さ）、`--ph-top`（舞台の上端）。値はステージ上の px なので、倍率が小さいほど大きくなる。**740×320（倍率0.44）でも収まること**を確かめる。
- 置き方の決めごと:
  - 金の決定ボタンは舞台の右下・高さは押す所1つぶん。文字は1行（折れるなら、補足を `span` に分けてスマホでは畳む。文は変えない）。
  - 説明の文は画面に置かず「?」へ。表・読み方・補足は、押して開くダイアログへ（配合の仕上がりの目安、機材の一式の表）。
  - 選ぶ札は、2択までは大きな絵の札を左右に、3つ以上は2列。
  - 見守る人の一言は、熱の柱の根元より下に収まる行数ずつ送る（`craft/audience.js` の `wrapNote`。札は下端を固定して上へ伸びるので、行が増えると右上が柱の裏に入る）。
  - JS が `hidden` で隠す部品（調整で炭を選ぶ間の `.pull-play` など）を、`display: … !important` で出してしまわない。ファイルの最後の `[hidden]` の規則で必ず消える。
  - **既存の検査が「見えること」を守っている部品は、畳んでも消さない**（葉の行の熟練度、予想の札の「仕上がりの目安・予想幅・低め／高め・熟練の開閉」）。場所が足りない時は、見える高さを決めて続きを中で送れるようにする（`display: none` にすると `flavor_mastery`・`mastery_display`・`flavor_expression` が落ちる）。
  - 下の段を動かしたくないカード（工程の結果）は、下の段をカードの下端に絶対配置で固定し、上の中身を flex で伸び縮みさせる（格子の行に任せると、中身が多い時に下の段が押し出される）。
  - 表示だけの JS 変更（文を `span` に分ける・「?」へ補足を足す）は、擬似 DOM の単体検査（`story_guidance_1045`・`appearance_selection` など）が通る書き方にする: `textContent` を先に入れてから `replaceChildren?.()`、`closest?.()`・`after?.()` のように「無ければ何もしない」形。
  - **遊び込んだ状態で増える部品にも置き場所を決めておく**。能力が11以上で出る効果の印（技・感・察・根の札、感の帯、効果の一言）と、心得で増える部品（配合の「単体で勝負」「香りの記憶」、吸い出しの「ズボー」「味の名前を伏せる」、事故の予兆）は、はじめの状態では出ない。行やボタンを足して押し出す形にせず、決まった場所に重ねる:
    - 穴あけ: 「技」「感」の札はアルミの舞台の右上の角。右の列には行を足さない（文は「?」）。
    - 配合: 一覧の頭に押す所1つぶんの1行。「香りの記憶」を開いても行は増やさず、同じ行を横へ送る。
    - 大会: 「手応え」は一言の札の左上に、押す所1つぶんの大きさで立てる（開けない間は出さない）。
    - 吸い出し: 効果の一言はダイヤルの上の中央（予兆が出ている間は予兆と入れ替え）。心得のボタンがある時だけ下を2段にし、上の段の右に置く（「吸う」の上にズボー、「提供する」の上に伏せる）。いつもの「状態・提供・吸う」は動かさない。ダイヤルは行の高さに合わせて縮む（`container-type: size` と `cqh`）。
- 検査: `remake/test/browser/craft_phone_layout.mjs`（判定は `craft_phone_audit.mjs`）。はじめの状態（844×390）と、育成済み（上の部品が全部出る状態）の 844×390・844×340・740×320 で全工程を開き、文字・押す所・欠けたら困る絵が「外へ出ない・切られない・実寸11.4px／44pxを割らない・覆われない・ボタンの字が3行に折れない」を確かめる。見た目の良し悪しは判定しないので、直したら本編を横持ちの大きさで開いて撮って見る。**確かめるときは、はじめの状態だけでなく育成済みの状態でも開く**（オーナーの手元のセーブは育成済み。2026-11-20 までの直しは、はじめの状態でしか確かめておらず、穴あけの右の列と吸い出しの下の列が崩れたままだった）。

## 本編へ入れる進め方

- 寸法・判定の座標は変えず、作業台（`.bench`）の配置だけを新しいCSS（`craft-paper.css` の後に読む）で組み替える。アルミと雑念の場は中身の座標系を保ったまま拡大する。
- 切り替え: 2026-11-10 から既定で入（大会・チュートリアル・バイト後の練習も同じ画面）。比べたいときは `?craftStage=0` で旧配置（端末に覚える）、`?craftStage=1` で戻す（`js/craft/stage-layout.js`）。CSSは `asset_sources/ui/craft-stage-20261110/stage_src.css` を直して同じフォルダの `build_stage_css.py` で `css/craft-stage.css` を作る（`&phone` はスマホの密度だけ）。
- 検査: 寸法を確かめるブラウザ検査は、新しい配置の座標（柱 x338〜398、舞台 x410〜）で確かめる。旧配置の位置を前提にした検査は、新しい配置かどうかで期待を分ける。
- 操作の案内文は画面に常設しない（「？」と初回の説明で読む。CSL15）。
- 最初に骨組み（背景・はじめ・熱の柱・上のレール・下の列）を入れ、そのあと1PR＝1工程で、山場の順（吸い出し→蒸らし→穴あけ→炭焼き→配合・詰め方→残り）に進める。各PRで `craft_layout_*`・`phone_density`・`craft_materials` などの関連ブラウザ検査を通す。
