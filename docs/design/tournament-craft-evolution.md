## 0. 結論（先に要点）

1. **システムは変えない**。工程の順番、穴・炭・完成品・調整1・調整2 各20%の採点、配合別温度モデル、蒸らしの弾幕、吸い出しの針、中間投票と南雲の10点はそのまま。変えるのは「水入れの中身」「画面の上に重ねるライブ層」「見た目の統一」の3つ。
2. **水入れは、試遊にある蛇口式（`water-pour-view.js`）を本番へ昇格させ、基準を「金の目安線」から「ステムの先が沈む深さ」へ変える**。実物の基準は「ステム先端が水面下 2〜3cm」。注ぐ→ステムを挿して確かめる→足す／少し捨てる、の3拍子。判定結果は既存の `cs.water`（0〜1）→ `waterComfort` にそのまま入れ、採点の配分は変えない（§3）。
3. **ライブ感は「中継のある職人バトル」として、3つの部品を足す**（§4）。
   - 左の作業風景の窓を**会場カメラ**にする。普段は今までどおり「はじめの手元」。工程の切れ目（MCの前振り・結果確認中）だけ「審査員席」「ライバルの手元」へ2〜3秒切り替えて必ず戻る。
   - 上の帯で文字だけが置かれている左220px（`craft-header.css` の `.bench-mode`）を、**出場者4人の進行チップ**にする（顔と工程の段階。状態の一語は変わった時だけ短く出す）。
   - 右パネルの右上に浮いている「?」の隣に、**いま手元を見ている審査員**の小さな顔チップを1つ（既存の `STEP_JUDGE` を見えるようにするだけ）。
4. **操作中は何も動かさない**。カメラ切替・コメント・ざわめきは工程の切れ目だけ。これは「観客コメントは結果確認中だけ流す」（TP04）の原則をそのまま広げたもの。弾幕・針・穴あけの最中は現行と同じ静けさを守る。
5. **ライバルの進行は演出だけ**。各ライバルの「テンポ」と「見せ場の工程」を持たせ、はじめの実工程に相対して進む。票・順位（`interimPointTable`／`pointTable`）には一切つながない。数字も出さず、段階だけ見せる（◎○△の方針と同じ）。
6. **素材は生成に向く範囲に限る**。顔は生成せず既存立ち絵を切り出して合成（`audience.js` の `FACE_CROPS` が既にある）。生成するのは背景・手元・小物・UI部品、全12枚程度（§6）。
7. **実装は PR 5本**（A 水入れ → B ライブ層の骨格 → C 素材 → D 演出仕上げ → E 見た目の統一と回帰）。各半日〜1日。A と B は独立に進められる（§7）。
8. 決めてほしいことは6つ（§8）。

## 2. 設計の軸

### 2.1 ことば: 「中継のある職人バトル」

- 大会は配信されている（ニコ動風コメント・MCパッキー・LIVEの速報帯）という既存の設定を、制作中の画面にも一貫させる。カメラ、テロップ、審査員席。「黒背景・ネオン・煙・カットイン」（master_spec 第2部）はそのまま。
- 新しい層はすべて**読み取り専用**。採点・温度・弾幕・票の算出には触れず、`cs` と既存のデータを読んで描くだけ。

### 2.2 3つの原則

| 原則 | 具体 |
|---|---|
| 操作中は静か | カメラ切替・ざわめき・コメントは工程開始のMC前振りと結果確認中だけ。弾幕・針・穴あけの最中は何も動かさない。失敗（焦げ・冷え切り）は既存の爆発演出を優先し、ライブ層は黙る |

| システムに触らない | `score.js`・`conditions.js`・`temperature-model.js`・`steam.js`・`pull.js` の判定は変えない。水入れも `cs.water` と `waterComfort` の受け口はそのまま |

## 3. 水入れの設計

### 3.1 実物の基準（台詞・表示の根拠）

- ステム（ダウンステム）の先端が水面下 **2〜3cm**。浅いと煙が冷えず喉に当たり、泡が荒い。深いと吸いが重い。既存 `waterComfort` の4区分（none／shallow／ideal／deep）がそのまま対応する。
- 水の役割の説明は「煙を冷やして吸いやすくする」だけ（K14・#1113）。濾過・除去とは言わない。結果カードの文も既存の4文（`water-view.js` の toast）を引き継ぐ。

### 3.2 ゲームの流れ（3拍子）

```
① 注ぐ            蛇口を長押し。水位が上がるほど注ぐ音の高さが上がる（実物の聴覚の手がかり）
② 挿して確かめる  「ステムを挿す」でステムの影がガラスの中へ下りる。沈んだ深さが側面から見える
③ 直す            「少し足す」（長押し）／「少し捨てる」（長押し：ボトルを傾けて流しへ）→「この水位で決める」
```

- 判定は**ステム先端からの沈み（cm）**。EXCELLENT ±0.4cm／GOOD ±1.0cm／ほぼ目安 ±2.0cm／それ以外は「浅い」「深い」。既存 `POUR.grades`（mm）の単位と幅を置き換えるだけ。
- 結果: 既存の結果カード（`resultCard`）で「沈み +0.6cm」「水 540ml」「注いだ回数」。工程の点としては**採点に入れない**（完成品20%の中の吸い心地にだけ効く、現行どおり）。
- 時計: 水入れに制限時間は付けない（現行の試遊と同じ）。大会の緊張は工程のテンポで出す。

### 3.3 初心者と経験者の両立

| | 初心者 | 経験者 |
|---|---|---|
| 見た目の助け | レッスン・リハーサルでは、ステムを挿した時に「ちょうどいい帯」が淡く光る。本番は洞察★の段に応じて薄く出る（`skill.clarity` を流用） | 帯を頼らず、音の高さと水面の位置で合わせる |
| 結果 | 「ちょうどよく浸かった」の一文と◎○△ | 「+0.6cm」の精密表示を「詳しく見る」に |
| 練習 | DAY3 の基礎練習に水入れを足し、`practice-history` に記録 | 自主練メニュー（`DRILLS`）に「水入れ」を追加できる余地を残す |

### 3.4 機材との接続（任意・後回し）

- ボトル／ステムの長さが機材で違えば目標水位が変わる（`equipment.json` に `stem_depth` を足す）。初版は固定値。実装するなら PR-A の後の小さなPR。

### 3.5 既存コードの再利用

- `water-pour.js` の `PROFILE`・`POUR`・面積計算・`surfaceY`・`holdable` はそのまま。`pickTarget` を「ステム先端 + 2.5cm 相当の y」へ置き換える。
- `water-pour-view.js` の描画・入力・物理はそのまま。変更は (1) ステムの透過パーツを `drawWater` の後に重ねる、(2) 目安線の代わりに「沈みの寸法線」を描く、(3) こぼした水の着地先を卓から流し（画面右下の小さな流し）へ、(4) 音のピッチ。
- `water-view.js` の `stepWater` は `mountWater` の代わりに `mountWaterPour` を呼び、返り値の ml → `cs.water`（0〜1）へ変換して `setBenchWater` と toast を今までどおり呼ぶ。保存形式は変わらないので途中再開・旧セーブは影響なし。
- テスト: `water_pour.mjs`・`water_pour_lifecycle_743.mjs`・`browser/water_pour.mjs` を目標値の計算と流しの着地に合わせて更新。`ch1_tournament.mjs` の工程列に水入れの確定を足す。

### 3.6 変えないもの

採点配分、`waterComfort` の数値、`cs.water` の形、吸い出しの `waterComfortLine`。

### 4.3 ライバルの進行モデル（演出専用）

- 各ライバルに「テンポ」（速い／普通／丁寧）と「見せ場の工程」を1つ持たせる。第1章: なる＝速くて静か・見せ場は穴あけ、アダム＝豪快・炭が早い・見せ場は炭焼き、みんと＝丁寧でやや遅い・見せ場は提供。章2以降は `ENTRANCE_CARDS` の人物をそのまま使い、台詞の人物像（`brand/character_profiles.md`）からテンポを決める。
- 進行は**はじめの実工程に相対**して決める（例: はじめが炭焼きに入ると、なるは蒸らし待ち、みんとはまだ穴あけ）。実時間の経過では進めないので、プレイヤーが長く悩んでも置いていかれない。
- 票・順位・採点には一切つながない。中間投票の数字は現行の `interimPointTable` のまま。進行チップはあくまで「会場で何が起きているか」の見せ方。

## 5. 見た目の統一（市販ゲーム並みに見せるための細部）

## 6. 素材計画（gpt-image-2.5-sunburst）

## 8. 決めてほしいこと

1. **ライブ層の置き方**: 左窓を会場カメラにする案（推奨。右パネルを削らない）か、右パネルを狭めて常設の審査員帯を置く案か。
2. **水入れの段取り**: 「注ぐ→ステムを挿して確かめる→直す」の3拍子（推奨）か、最初からステムの影を見せる1段階か。
3. **捨てる操作**: ボトルを傾けてこぼす現行の操作を残すか（着地先を卓から流しへ変える）、別の操作にするか。
4. **ライバルの進行**: 演出だけ（推奨）でよいか。票に少しでも反映させたい希望があるか。
5. **素材の範囲**: 12枚案でよいか。顔は既存立ち絵の合成でよいか（生成した顔は別人になりやすい）。
6. **水入れの採点**: 現行どおり採点に入れない（推奨）か、完成品20%の中で明示的な比重を持たせるか。
