# 大会進行の共通契約（#2031・仕様ドラフト）

状態: **提案・未承認**。2026-11-05 のオーナー決定は「開始・中断復帰・投票時点・保存境界を先に仕様化し、その後に適用スライスを切る」。本書の確定根拠はその作業順と、既存の [VOTE01](../master_spec.md) など採用済み仕様に限る。以下の共通化方針はレビュー対象であり、[未確定点](#未確定点)を確定扱いしない。

## 対象と用語

| 用語 | 意味 |
| --- | --- |
| 大会単位 | 参加条件の成立から結果・報酬・次の物語段階までを結ぶ一試合。第5章は二台と観客挙手からなる一試合。 |
| 試行 | 敗北後の再挑戦で作る新しい一台。第5章の二台目の作り直しを同じ再挑戦と見なすかは未確定点 U5。 |
| 工程確定 | 制作工程が完了し、実績と消費を保存可能にした時点。工程中の操作は未確定。 |
| 投票確定 | 審査員または観客の一回分の票を記録し、以後の画面再表示で再投票しない時点。順位表示と結果発表は確定済みの票を読む。 |
| 保存境界 | ロード後の再開位置と、保持する記録・巻き戻す未確定操作を区切る地点。自動保存と手動スロットの差は未確定点 U4。 |

適用候補は第1章 SMOKE CROWN CUP、第2章県大会、第3章全国大会、第4章 GRAND SMOKE、第5章 SHISHA-9000 戦。第5章の観客挙手に審査員の持ち点規則を適用しない。[master_spec.md](../master_spec.md) の VOTE01 は第1・4章の現行投票規則と旧試合 SAVE の扱いを既に定めるため、本書で上書きしない。

## 共通契約案

### 1. 開始

候補となる状態遷移は `参加可能 → 入場・台本 → 制作可能 → 制作中`。開始前には章固有の日時・前提イベント・課題・必要データを検証する。制作開始を一度だけ確定し、試行番号、適用するルール版、開始時の資源、初期の票と結果、制作状態を関連付ける。再表示や二度押しで試行番号や資源を重複更新しない。入場カードと台本の既読は制作開始とは別に扱い、再開時の再演条件を章ごとに記録する。

適用候補: 第1章は大会当日の `phase=tournament` と一台開始、第2・3章は `entry/ready` から `craft`、第4章は大会開始場面読了後の `match.craft`、第5章は会場入り確認による `part=match` と二台目制作開始。第1章の再挑戦時の資源初期化、第4章の入場再演、第5章の一台目固定票を単一の手順に寄せる範囲は U1・U5 で決める。

### 2. 中断復帰

候補となる状態遷移は `制作中 → 工程確定 → 次工程`、未確定のまま中断した場合は `工程開始時の保存地点 → 同工程の再実行`。ロード時は確定した票・結果・既読・報酬を再計算せず、未確定の工程で生じた資源消費だけを工程前の記録へ戻す。結果発表後は結果を再表示し、勝利後・敗北後の進行は保存済みの段階から続ける。これは共通化の目標であり、第1・5章の現行挙動を変更する判断は U2・U5 に残す。

適用候補: 第2・3・4章の制作工程と投票後の表示、第1章の大会本体と優勝後、第5章の二台目と結果後。台詞の途中、モーダルの途中、タイトルへの離脱は、既読の確定時点と再表示の単位を章別に指定する。表示のみを再実行するとき、票・成績・資源・報酬を動かさない。

### 3. 投票時点

一回分の票は、対応する実績が確定した後にのみ投入する。`未投票 → 投票確定 → 途中順位表示` を一方向とし、同じ回への二重投入と、結果確定後の投票を禁止する。最終結果は全投票と必要な工程が揃った時だけ確定し、保存済みの票・順位・ルール版を使って再表示する。既存試合のルール版を途中で切り替えない。審査員別の配点・重み・同点規則は章固有の既存仕様を保持し、第5章は二台分の観客挙手を保持する。

適用候補: 第1章の4回の工程票、第2・3章の制作／提供／調整／最終の4回、第4章の工程8～11確定に付随する4回、第5章の固定された一台目と二台目完成後の観客挙手。第2・3章では工程確定と台詞読了のどちらで各回を確定するかが異なるため、共通設定の単位は U3 で決める。

### 4. 保存境界

保存すべき最小の意味上の記録は、章・大会段階、試行とルール版、確定済み工程と制作実績、工程前資源の巻戻し情報、確定票と結果、既読・報酬済みフラグ。画面の DOM・音・一時的な配信コメントは再生成してよい。保存からの再開は同じ確定結果を得られる必要があるため、乱数に依存する抽選済み条件も再現できる形で保持する。既存 SAVE のキーや schema をこのドラフトで変更しない。旧試合 SAVE は既存ルールで完走し、確定票・結果・賞金・進行フラグを再計算しない（VOTE01）。

適用候補: 第2・3章の `entry/rollback/craft/votes/result`、第4章の `match` と工程前資源、第1章の `state.tournament` と優勝後の段階、第5章の `part/read/secondCup`。資源復元の対象と手動スロットの扱いは U4、旧 SAVE の移行条件は U6 に残す。

以下はオーナー判断が必要な論点。推奨案は提案であり、現行 SAVE の扱いを変更する承認ではない。

| ID | 論点 | 選択肢 | 推奨案 | 判断が要る理由 |
| --- | --- | --- | --- | --- |
| U1 | 「大会開始」の共通境界 | A: 会場入り時 / B: 制作開始時 / C: 章別に二段階 | C | 第1・5章は会場入りで `phase` が動く一方、第2～4章は入場と制作が別段階。 |
| U2 | 第1章の制作途中再開 | A: 現行どおり大会冒頭 / B: 工程ごと / C: 指定区切りだけ | 保留 | VOTE01 の確定票と一台の状態を保持する保存設計・旧 SAVE 互換・演出再生範囲が変わる。 |
| U3 | 第2・3章の第2・3回投票境界 | A: 工程直後へ統一 / B: 台詞読了後へ統一 / C: 章別の現行順を契約に明記 | C | 台詞前後で保存された場合の票・順位・既読と演出順に影響する。 |

| U5 | 第5章の二台目を工程再開対象にするか | A: 現行の一台丸ごと作り直し / B: 工程ごと / C: 提供後だけ | 保留 | 観客票は完成後一括で、途中保存の導入は資源消費・失敗時・台本の再生を変える。 |
