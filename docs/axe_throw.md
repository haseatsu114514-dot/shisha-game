# 斧投げミニゲーム（#480）

remake/axe-throw.html で、開発コンソールなしで遊べる。
横ゲージ→縦ゲージ→力ゲージを、ボタン／Space／Enterで順に止める。
横・縦はそれぞれ止めた狙いを金色の印で残し、手ブレを含む白い刃先は動き続ける。力は緑の帯が目安。
弱すぎると刺さらず落下、強すぎると回転が合わず落下して0点。
投げる前に通常／4か所のキルショットを選ぶ。構え直しは投数・宣言回数を消費しない。
スマホ縦／横・PCの実操作に対応し、ひより／サメちゃんの立ち絵と前後のコメントが出る。
サメちゃんは遊びに付き添う立場で、物語上の大会ライバルや競争相手には追加しない。
ひよりの大声はキルショット成功時だけの短い反応。素顔発覚や恋愛成立を推定しない。

## 遊び方を読む・手ブレを読む（#522）

練習入口の「遊び方・得点ルール」とゲーム中の「ルール」は、同じ説明を開く。操作順、通常の同心円/外側ブル、宣言した青以外0点、宣言の消費/高さの閉鎖、落下、力による上下ずれ、3投/10投を説明する。PC・タッチ縦横でスクロールでき、見出しと戻るボタンを固定する。本編内でも読める。説明中はゲージ・手ブレ・飛行・集中時間を止め、Tabの焦点を説明内に収める。Esc/戻るで同じ段階へ戻り、callerのAbort/撤去では説明ごと片付ける。

構えてからの実操作時間を横→縦→力で引き継ぎ、約1.5秒後から疲れが増え、8秒で上限に達する。力の緑帯から外れるほど力みも増す。投ごとに位相が異なる連続した手ブレを白い照準に描く。金色の狙いを固定しても刃先は揺れるため、早く構えをまとめるか、揺れが狙いへ戻る瞬間を読む。投げた後に乱数で位置をずらさない。力の段階では既存の上下ずれも白い照準に含め、表示と着地点を一致させる。

「息を整える」は各投1回、1.2秒だけブレ幅を18%に抑える。力を止める直前や小さい青を狙う時に使える。構え直しで疲れを戻せるが、使った集中は戻らず、集中の残り時間も持ち越さない。次の投とゲーム全体の再挑戦で1回に戻る。背景タブと説明中は集中時間を消費しない。動き軽減でも狙いの手ブレは見えるゲーム操作として残し、飛行回転だけ従来どおり省く。

通常得点/落下/キルショットの判定モデルは維持する。結果の各投には実刃先の`aim`と、止めた`baseAim`、実際に表示した`sway`（幅/疲れ/集中状態）を残す。既存のcallerはcompleted/throws/totalを従来どおり使える。セーブやキャラの能力を難易度へ流用しない。

## ラウンジ競技ルール（lounge-2026-v1）

参考: [WATL公式2026ルール](https://worldaxethrowingleague.com/axe-throwing-rules/)
（確認した版は2026-10-07更新）。本ゲームは公式大会シミュレーターではない。

- 3投の練習（最大22点）／10投の競技練習（最大64点）。後半5投でも宣言と閉鎖状態を引き継ぐ。
- 通常はリング1〜5点、中央と4つの外側ブル6点。黒いリング境界は低い側の点、赤いブルの境界はブル。
- 選んだ青いキルショットを投げる前に宣言すると外7点／内8点。宣言した投は選んだ青以外0点。
- 宣言は1ゲーム2回まで。外れ・落下でも消費する。成功するとその高さの左右両方が閉じる。
- 宣言なしで青い場所へ刺さった場合は通常リングの点数。宣言の取消は構える前・構え直し後にできる。
- 力は0〜1、適正帯.54〜.70、刺さる範囲.42〜.82。着地点の上下と斧の回転にも力が影響する。

10投・宣言・7/8点・成功時の高さ閉鎖は競技を参考に採用。
ゲーム用に的の寸法を拡大し、刃の接地面ではなく表示される刃先の座標で判定する。
投距離・左右レーン交代・反則・審判・落下による宣言追加・延長戦は実装しない。
「10投の競技練習」はプレイヤーだけが投げる。キャラクターの投擲と勝敗を含む対戦は未実装。
キャラクター表示と判定モデルを分離し、後の対戦が同じルールと各投の記録を使える構成にする。

## 本編から呼ぶ

前段VNが終わってから js/minigames/axe.js の
runAxeThrow({host, signal, reducedMotion, mode: "practice"|"league", opponent: "hiyori"|"shark"}) をawaitする。
host省略時は既存stage、練習ページではaxe-app。同じhostへの二重呼び出しは同じPromiseを返す。
hostの既存DOMを消さず一時画面を重ね、終了・AbortSignal・host撤去で時計と入力を片付ける。
キーボードの焦点を画面に収め、閉じると元の操作へ戻す。
背景タブでは針・投擲時間を止め、復帰時に大きく進まない。動き軽減時は飛行回転を省く。
サメちゃんは採用済みSHISHARKタイトル絵の登録から現在の持ち主IDを読み、
そのIDの立ち絵を使う。固定の旧IDをコードへ追加せず、改名前／改名後の目録に対応する。
画像の実デコードを待ってから操作を開き、失敗時は再読込／中断ができる。

返り値は {completed, cancelled, throws, total, grade, ruleset, mode, opponent, throwCount, maximum}。
各投は aim / baseAim / sway / power / called / landing / rotation / stuck / score / outcome / dropReason を持つ。
全投の結果を見て「終了」した時だけ completed=true。中断は completed=false、grade=null。
呼び出し元がcompletedを確認して後段VNを再生し、正式台本読了後だけ物語や報酬を処理する。

この機能はセーブ・好感度・お金・体力・恋人／友人・LIME・行動枠を変更しない。
練習の記録とキャラ選択はページ内だけで、既存schemaを変更しない。
正式なひよりの解禁・素顔発覚・台本・報酬は旧 #343 の後継 #492 / PR #495 で実装済み。
`js/daily/hiyori-axe.js` が前段VN→本機能3投→後段VNを呼び、台本を最後まで読んだ時だけcallerが正式な行動・報酬を処理する。本編の後半章への接続は未実装。
生成済みのボード・背景・ひより差分（素材PR #478）を参照し、旧画像は変更しない。横見本の斧PNG/WebPも保存し、正面投擲の描画は厚みのある3D形状を使う。
素材登録のminigame_connected=falseは#477登録時点の履歴で、現在は練習ページと本編ひよりイベントで使っている。

## ゲージと投擲の見える関係（#537）

①横は左〜右、②縦は上〜下。3段階のパネルに動いている値と確定した値（✓）を残し、的のゲージの針から金色のガイドを照準まで伸ばす。③力は0〜100%で、緑54〜70%が適正、茶色を含む42〜82%が刺さる範囲、外は落下。62%を基準とする力の上下補正を緑の線と↑↓の数値で示す。白い照準は手ブレと力の補正を含む予測着地点で、リリース後も着地点の印と全3段階の確定値を保持する。

#537では横見本の画像を画面内で回していたため、#542で正面視点の投擲へ置き換えた。`axe-flight.js` はカメラから的へ向かうZ軸と、横軸まわりの前後回転を扱う。投げ手の頭上・右寄りから離れた斧が的へ進み、柄をカメラ側へ倒して縦に一回転する。回転数のずれは既存の力による判定を表示する。画面内の横回転は行わない。

`axe-geometry.js` は金属の背・薄い刃・木の柄を厚みのある立体面として定義し、透視投影・裏面除去・奥から手前への描画・面ごとの陰影を行う。回転中に柄が短くなり、上下が逆転し、木口や刃の表面が切り替わる。カメラの焦点距離700、的の奥行き650、前進920ms・落下360msはSVG世界の表示単位で、実競技の距離/速度を測る物理シミュレーターではない。元の横見本PNGは編集せず保管する。

接触時は刃の3D中心点を的の平面へ置き、その投影位置を判定した白い着地点へ一致させる。刺さった斧は飛行の最後と同じ3D姿勢で残し、正面からは背と下に伸びる柄が見える。刺さらない斧は接触後に落ちて消える。動き軽減は同じ接触姿勢と結果を直接表示する。背景タブ・ルール表示中の停止、Abort/host撤去の後片付けとcallerの返り値は維持する。

実装・生成元・素材はこのGitHubリポジトリに保管する。画像原データと生成記録は `asset_sources/hiyori-axe-issue477/`、採用PNGは `assets/ui/axe_throw/`、配信用WebPは `remake/img/ui/axe_throw/`、背景とキャラ差分は既存の登録を使う。画像の作り直しは不要で、既存のバイト列を保持する。別のイベントから再利用する時は上記 `runAxeThrow` をawaitし、ゲームの得点と正式台本・好感度処理をcallerで分ける。対戦への拡張は #489 の境界に従う。

## 正式なひよりの寄り道

本編の入口はtonariでの既読段階と夜の条件を満たした時のサブメニュー。`daily/hiyori.js` が正式な前段→`daily/hiyori-axe.js`の実3投→後段を順に待ち、読了後にだけ料金・体力・行動・進行を保存する。ミニゲーム自体は引き続きセーブを扱わない。callerはstate変更を検出してAbortし、同じstageの内容が差し替わった場合もミニゲームがキャンセルとして後片付けする。中断や高得点だけで素顔を知ったことにしない。
