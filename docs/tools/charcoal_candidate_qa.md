# 炭候補PNGの技術検証

`tools/charcoal_qa.py` は、採用前のflat／cube炭候補をローカルで検証するCLIです。入力画像は変更せず、JSONで結果を返します。画像生成やゲームへの組込みは行いません。

## 実行方法

Python 3.9以降とPillowを使用します。Pillowは既存の画像処理でも使用している依存です。リポジトリのルートから実行します。

```sh
python3 tools/charcoal_qa.py path/to/candidates
python3 tools/charcoal_qa.py path/to/candidates --output path/to/new-report.json
python3 tools/charcoal_qa.py --help
python3 -B tools/test_charcoal_qa.py
```

候補ディレクトリは既存の入力先を指定します。レポート保存先の親ディレクトリも事前に用意してください。`--output` を省略すると標準出力だけにJSONを出します。指定時はファイルにも同じJSONを保存します。

| 終了コード | 意味 |
| --- | --- |
| 0 | 技術検査に合格 |
| 1 | 候補不足、形式・品質の不適合、入力ディレクトリなし |
| 2 | 引数やレポート出力のエラー |

保存するレポートは入力ディレクトリ外の新規ファイルに限定し、既存ファイルを上書きしません。出力先のエラーではレポートを保存できないため、標準エラーと終了コードを確認してください。

## 固定6スロット

| 炭種 | ① | ② | ③ |
| --- | --- | --- | --- |
| flat | `flat-1.png` | `flat-2.png` | `flat-3.png` |
| cube | `cube-1.png` | `cube-2.png` | `cube-3.png` |

各番号は候補の識別子です。①②③表記（例：`flat①.png`）、ハイフンなし、アンダースコア区切りも同じ番号へ正規化します。大文字小文字も区別しません。サブディレクトリを含めて走査し、同じ番号が複数あれば重複として扱います。

空ディレクトリは6欠番として不合格です。未知の名前・追加番号・非PNGの拡張子・シンボリックリンク・通常ファイル以外も不合格です。候補ディレクトリには検証対象だけを置いてください。

入力ルートや子ディレクトリの走査が失敗した場合も不合格（終了1）です。JSONの `errors` に `directory_scan_failed`、対象の相対 `path`、例外種別 `exception` を記録し、取得済みの検査結果は保持します。ルートは `.`、対象内のパスと確認できない場合は `null` とし、例外メッセージや外部の絶対パスは記録しません。

## 判定範囲

- PNG署名と実際の形式、画像のverifyと全decode、静止画であること。
- alphaチャンネルまたはパレット透過があり、完全透明の画素を含むこと。
- 既定で1024×1024ピクセル、各辺に10%以上の透明余白があること。
- 空alpha、可視画素が全体の1%未満、alpha最大値が128未満でないこと。
- alphaが0より大きい全画素のbboxが画像端に接触していないこと。端接触はクリップの可能性として報告します。
- ファイルSHA256とRGBA画素SHA256による重複。画素比較では完全透明部分のRGBを無視するため、metadataや圧縮だけを変えた同じ画像も検出します。近似画像の重複検出は行いません。

余白の必要ピクセル数は切り上げます。可視面積・alphaの閾値は空に近い画像を止める技術検査の基準です。炭の物理寸法を推測するものではありません。

`--size N` と `--margin F` でサイズ・余白率を明示変更できます。使用した値はJSONの `policy` に記録します。余白率は0以上0.5未満、画像の検査上限は1ファイル32MiB・16,777,216画素です。

JSONの `ok` は技術検査の結果、`errors` は不適合理由、`missing_slots` は欠番です。各ファイルの `measurements` に寸法・alpha・bbox・ハッシュを記録します。decodeできないファイルにも不適合理由を記録します。

## 合成テストと採用判断

テストは32角のtiny合成fixtureを一時ディレクトリに作り、終了時に削除します。fixtureは生成作品や採用候補ではありません。`--synthetic-fixtures` はJSONの `input_kind` を `SYNTHETIC_TEST_FIXTURES` にし、合成テストであることを明記します。検査条件自体は変えません。

技術合格は採用許可ではありません。炭1個であること、flatの厚み、cubeの立方体形状、文字・ロゴ・炎・器具の有無、実物との照合、縮小時の識別、権利確認は別途レビューが必要です。HMDや他の商品画像の検証・選定には使用せず、ゲームの表示・manifest・保存データは変更しません。
