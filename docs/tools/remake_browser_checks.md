# リメイク版のブラウザ回帰検証

既存の `remake/test/*.mjs` は画面・工程ごとの検証に使う。本書の追加テストは、未完だった開発者ツールのブラウザ確認と、セーブ／ロード画面の回帰に対象を絞る。ゲームコード・シナリオ・恋愛データ・セーブ形式は変更しない。

## ローカル実行

リポジトリのルートでサーバーを起動する。

```bash
python3 remake/tools/serve_preview.py --port 8123
```

別のターミナルで依存を準備し、テストを実行する。

```bash
npm ci --prefix remake/test/browser
cd remake/test/browser
npx playwright install chromium
cd ../../..
node remake/test/browser/save_load.mjs
```

Chromeが既にある環境では、ブラウザを追加ダウンロードせず指定できる。

```bash
CHROME_EXECUTABLE_PATH=/usr/bin/chromium node remake/test/browser/save_load.mjs
```

`BASE_URL`で確認対象サーバーを、`TEST_REF`でそのサーバーが配信しているコミットを記録できる。`TEST_REF`は報告用のラベルであり、配信コミットを自動検出するものではない。対象を変えるときは、サーバーの作業ツリーとSHAを照合する。テスト用ブラウザは各ケースで新しいコンテキストを作り、プレイヤーが普段使うブラウザや保存領域を開かない。

## 対象と限界

`save_load.mjs`は次を確認する。

- オートセーブと手動3枠の状態保持、枠ごとに異なる保存内容、設定・無関係な保存キーの保持。
- スキーマ5の代表的な保存の移行。能力・経験値の端数・在庫・既存の恋人関係・進行の保持と、DAY15／所持金の正規化。全スキーマの全組合せを保証するものではない。
- 未保存・壊れたJSONを読んでも、現在の状態を変更しないこと。
- 本編タイトルからのロード、マップのMENUからの手動セーブ、上書きの確認とキャンセル、ロードの確認とキャンセル、実際のページ再読込後のマップ復帰。
- PC 1280×720とタッチ端末の横向き844×390で、タイトル・保存枠・MENUの操作が画面内に収まり文字が欠けないこと。縦向き390×844では既存の横向き案内を検査し、回転して操作に戻れること。

固定画像との比較や全画面の表示保証は行わない。タッチ設定を持つChromiumによる確認であり、iPhone実機・Safari・安全領域・実機性能の検証は別途必要。第1章の通しプレイは既存の `playthrough.mjs`を必要なときに使う。

## 開発者ツールの検証

対象ツールの実装があるブランチを**読み取り用の作業ツリー**で配信し、追加テストをそこへ向ける。既存PRのブランチを書き換えたり、未マージ機能をmainへコピーしたりする必要はない。

```bash
# #278相当
BASE_URL=http://127.0.0.1:8124/remake/ node remake/test/browser/dev_tools.mjs --tools=inspect
# #279相当
BASE_URL=http://127.0.0.1:8124/remake/ node remake/test/browser/dev_tools.mjs --tools=inspect,preview
# #280相当（引数を省略すると3機能すべてを検査）
BASE_URL=http://127.0.0.1:8124/remake/ node remake/test/browser/dev_tools.mjs
```

指定したツールが公開されていなければ失敗する。mainに未実装の機能を検証済みとして扱わない。

検証するのは、インスペクターのコピーと検索、台本プレビューのHTML非実行と開閉、隔離試写の2つのローカル分岐・再開始・終了・別イベント遷移の案内、sandboxによる親画面／localStorage／sessionStorageへのアクセス拒否。すべてについてゲーム状態・台本データ・保存内容が変わらず、保存APIへの書き込みと本番VNの行／選択肢フックが発火しないことを確認する。データはテストブラウザ内のDBに一時的に加え、ファイルには書かない。

**#279は静的な台本表示、#280は対話式の台本試写。** #280で確認できるのは1行ずつの表示と同じイベント内の選択肢分岐で、`next_id`は案内だけ表示する。本番VNエンジン、立ち絵、背景、BGM、条件の評価、報酬・フラグ処理、別イベントへの実遷移、台詞組版は再現しない。このテストの成功から本編の発火条件や演出の正しさを結論づけない。

既存の `__remake.dev`はセーブを書き換える操作を含む。このテストは#278〜#280の読み取り用APIだけを対象にし、既存のジャンプ機能が保存を保護するとは主張しない。

## CIと結果

CIは[1本のworkflow](../../.github/workflows/ci.yml)で、テストの一覧は[`tools/ci/suites.json`](../../tools/ci/suites.json)にある。Node 22・固定バージョンのPlaywright・Chromiumを使い、各グループ内でブラウザ検証を直列に実行する。開発者ツールのテスト（`dev-tools`）はチェックアウトにある実装を選択し、実装がなければ未実行と明記する。

JSON結果と各ケースの画面は `.codex/artifacts/remake-browser/`へ保存する。`ARTIFACT_DIR`で保存先を変えられる。GitHub Actionsでは各グループの`browser-<番号>`にサーバーログも含めて7日間保存する。失敗したケースは成功として集計せず、終了コードを非0にする。

再開時のPR／Issue／CIの照合結果と追加の軽量化候補は、この変更のPR本文に記録する。日時付きの状態一覧を複数の正本へ複製しない。
