## 前提: 既存基盤（#1038）の範囲

`remake/js/core/loading.js` の `withLoading()` が、入力ブロック・漫画2枚ゲート付きの本格ロード画面。
実際の呼び出しは **1箇所だけ**: `remake/js/craft/loading.js` の `prepareBenchEntry()`（作業台の初回入店）。
これ以外の場面は、もっと軽い2系統の既存機構で個別にカバーされている。

1. `remake/js/vn/engine.js` の `waitSceneAssets()` — 会話中の背景・立ち絵・CG・導入カットインの素材待ちが**500ms超**になったときだけ `role=status` の通知を出す（`.vn-loading`）。5箇所の呼び出し（`play()` 初期化・会話中bg切替・jump先・CG表示・intro画像）が共通の固定文言 `"場面を準備しています…"` を使う。
2. 各画面が独自に用意した `role=status` の案内（例: `remake/js/daily/map.js` の `"マップを準備しています…"`、`remake/js/chapters/ch2.js` の `"街の台本を準備しています…"`、`remake/js/minigames/axe.js` の `"準備しています…"`）。いずれも「500ms〜2秒待っても表示が崩れなければ出す／完了したら消す／中断時は入力が戻る」という同じ型。

この型自体は既存のまま再利用できる。新候補は「この型が**どこにも無く**、素材/モジュール待ちが無表示で起きている場所」を探す調査である。

## 調査方法

- コードリーディング: 章開始・SAVE再開・大会・ミニゲーム初回・街移動の各入口から、素材/台本/JSモジュールの読込とその表示方法を追跡（`grep` で `withLoading`/`waitSceneAssets`/動的 `import(` の全呼び出しを洗い出し）。
- 実測: ローカルの `remake/tools/serve_preview.py`（`python3 remake/tools/serve_preview.py --port 8142`）を立て、`/home/box/repos/logs/browser-sem.sh` 経由で Playwright（`remake/test/browser/node_modules/playwright`）をヘッドレス起動。CDP `Network.emulateNetworkConditions` で起動後の遷移だけを `latency 150ms / 128KB/s`（既存 `remake/tools/measure_loading_matrix.mjs` と同条件、低速3G相当）に制限し、章モジュールの動的 `import()` 中に `.vn-loading` / `.loading-gate` / `[role=status]` が出現するかを `MutationObserver` で監視。計測用スクリプトは `remake/test/browser/_tmp_1060_measure.mjs` に一時作成し、結果記録後に削除済み（コミット対象外、恒久ツールとして追加はしていない）。
- 起動直後のタイトル表示までの読込（`remake/js/main.js` の `boot()`、`#boot` の進捗バー）は既存の表示付き処理のため対象外。

## 完了条件との対応

- 優先順位付き一覧と最小の導入単位: 上記A/B/C表。最小単位はA-1〜A-3（既存の軽量「500ms超で文言」パターンの横展開のみ、新しい見た目や基盤は作らない）。
- #1038既存接続と新候補の分離: 「前提」節で明記。新候補（A/B/C）はいずれも `withLoading()` の漫画ゲートを使わず、既存の軽量通知パターンの横展開として提案（過剰な演出を増やさない）。
- 根拠の区別: 各表の「根拠」列で実測／コードから推定／未確認を明記。実測はA-1・作業台・会話中bg切替の3件のみ（他は同一コード形状からの推定）。
- 不要な固定待ち・過剰一括取得・無期限待機を避ける: A/B候補はいずれも「素材/モジュールが揃うまで」の可変待機で、固定msの待機を追加する提案はしていない。一括prefetchの提案もしていない（モジュールは必要になった時点でのみ読む既存方針を維持）。
- 中断/失敗時の入力・フォーカス復帰: A-1〜A-3は「`import()` 失敗時にtoast等で案内し、操作可能な状態に戻す」既存パターン（A-2の `catch` 節が参考実装）を踏襲する前提。A-1（SAVE再開）は現状失敗時のcatchが無く、`import()` が reject すると `resumeGame()` 自体が例外で止まる経路になっている点は、ロード表示の追加と合わせて確認が必要（本調査の範囲では未実装・未実測）。
