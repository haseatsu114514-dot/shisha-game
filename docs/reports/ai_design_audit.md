# ai-design-check による現行UIの点検

未採用の改善提案。2026-11-02、main `e78eec552dc7aafb17b88d0f9100b991bec665d5` を対象に実施。ゲーム本体の見た目・挙動・台詞は変更していない。

## 結論と残すもの

**「全面的にAI製のテンプレートに見える」という評価ではない。通常の情報UIの強調と、制作画面の装飾の重なりが主な見直し候補。** 紙とラベンダー、制作の紫×白＋金は採用済みの仕様であり、紫色そのものを問題にはしない。

タイトルの人物・煙とロゴ、街の地図、人物ごとの顔、紙の質感とシーシャの線画、制作時の手元と器具は、このゲームの個性として残す。ダッシュボード向けのルールを一律適用して、ゲームの演出を消さない。

## 使用したもの・対象

- [enmerasoftware/ai-design-check](https://github.com/enmerasoftware/ai-design-check) の `ai-design-check` / `ai-design-fix` を、`npx --yes skills add enmerasoftware/ai-design-check --agent codex --yes` でプロジェクトへ導入。実際の取得元とハッシュは `skills-lock.json`。
- チェッカーは再現性のため `@enmera/ai-design-check@0.10.0` に固定。ルール一覧と `inventory` も実行した。レビューは導入したスキルの「測定してから評価」「既存の個性を残す」「件数を減らすために内容を消さない」に従った。
- ソース検査は `remake/css`（63 CSS）・`remake/js`（376 JS）・`remake/index.html`。旧版、台詞JSON、試作HTML、外部ライブラリ、資料は対象外。CSSフォルダ内のプレビュー用CSS・他テーマ・演出も生の件数には含まれる。
- 実画面は既定の紙テーマでタイトル・第1章DAY5の地図・MENUの4タブ・設定を1280×720、390×844、320×568で確認。スマホは通常タイトルの横向き案内を確認した後、表示設定からDS風へ切り替えた。制作は本編と同じ実装を使う `craft-preview.html` のパッキング・穴あけ・炭焼きを1280×720で確認。合計26表示状態。
- 人物・持ち物・所持金は既存の `daily_menu.mjs` と同様の検査用データで用意。独立したブラウザコンテキストを使用し、実プレイヤーのセーブは使っていない。未公開の心得の盤は有効にしていない。
- 最終確認で可視IMGの読込失敗は0。第1章の地図・MENU・設定の3サイズでページ例外は0。全章通し・全テーマ・全ゲーム工程の確認ではない。

### チェッカーの限界

この版のカタログは87ルールで、37ルールが目視、50ルールが自動扱い。そのうち4ルールは別コマンド `narrow` の描画専用。今回のソース検査で全50ルールを検証したわけではない。

本作は `el()` とJavaScriptによるDOM生成が中心。検査器の `src/check.js` は通常のHTML/JSX等のclassを解析し、`.js` には一部の正規表現ルールだけを適用する。CSSに対応する検査も限定的で、CSSに書いたフォントサイズ・4pxグリッド・紫グラデーション・フォーカスリングを網羅しない。実際に `inventory` は **ボタン1、入力0、見出し0** と返した。これはゲームにボタンが1個しかないという意味ではなく、主に起動HTMLしか数えられていない証拠。

したがって **error 0 はアクセシビリティやデザインの合格証ではない**。通常のCSSと生成後DOMを実画面で照合して補った。`narrow` とbefore/after動画は今回未実施。見た目を変更していないのでbefore→afterの改善件数もない。

### 補足の使いやすさ

スマホDS風の設定画面は下画面内に収め、`.modal-body` をスクロールする実装。390×844の初期表示ではUIデザイン・ミュート・BGMの見出しまでが主に見え、残りはスクロール先になる。「項目が消えている」という不具合ではないが、設定を音・文章・演出等で区切る／下にも続くと分かる表示を付ける余地がある。これはデザインルールの点数とは別の提案。

## 適用しない機械的な修正

- 紫・ラベンダー、紙のテクスチャ、金の決定操作を禁止しない（[採用済みUI仕様](../spec/ui_paper_lavender.md)を優先）。
- 章題・大会・スロット・カウントダウンの太字や弾む演出を一括削除しない。
- 4pxの倍数ではない値、角丸、字間を、画面上の役割を見ず一括置換しない。
- フォーカスの `outline: none` だけを見て不具合としない。紙テーマ・MENU・制作には置き換えの `:focus-visible` がある。今回は全操作のフォーカス検証を完了したわけではない。
- 台詞の感嘆符・好感度のハート・ゲーム内の星等を、ダッシュボード向けの禁止ルールで消さない。
- baselineやルール無効化で警告を0にしたことにしない。今回はどちらも追加していない。

次に着手するなら、LIMEの札の読みやすさと役割の整理、通常MENUの文字階層、制作の内側の装飾整理の順で小さく比較する。修正案を実装した時点で同じ画面・サイズを撮り直し、機能と情報を保持したbefore/afterを評価する。
