# 添削で見つかった再発防止ルール集

**この文書の使い方: 台詞の執筆・修正単元は着手前にこの文書を読むこと。** 書き終えたら、各ルールの「チェック方法」で自分の変更分を grep・目視確認してから提出すること。

## 出典と読み方

- 本書は、Neon（Gemini 4 Neon・XHigh）による添削パックのうち、裏取り（原文照合＋正本照合、誤検出0件）まで完了した6件から、「一回きりの誤字脱字」ではなく「ルールとして一般化でき、今後も再発しうるもの」だけを抽出したものである。
  - パック6: 第1章（指摘101件）／パック7: 第2章（93件）／パック8: 第3章（118件）／パック5: TRPGシナリオ9冊（539件）／パック9: 第4章（327件）／パック10: 第5章（76件）
- 違反例の「第N章 [x-y]」は各パック RESULT.md の項目番号を指す。原文の確認はそちらを引くこと。
- 正本の表記: `data/characters.json`（キャラの voice・設定）、`docs/master_spec.md`（仕様）、`docs/gameplay_agent_reference.md`（再発防止ルール・時系列ルール・用語統一。以下 gref）。
- 既存の再発防止策（設定の一元管理、改行の一本化、報酬キューの扱い、編集後セルフチェック）は gref「矛盾・改行崩れの再発防止ルール」に既にある。本書はそれを置き換えず、今回の添削で新たに具体化された分だけを足す。
- 根拠が確認できなかった項目は、末尾の「要確認」に分けてある。断定して直さないこと。

## A. 文体・表記（本編共通）

### A1. 台詞・選択肢・心の声（inner）は「。」で終わらない／地の文は「。」で終わる
- 根拠: 執筆正本ルール（第1章テイスト基準。パック6〜8の照合基準として全章・全行を照合済み。台詞側は第1〜3章とも違反0件だった一方、地の文側は毎章まとまって崩れた）
- 違反例: 第1章 ch1_minto 5場面・計21行と ch1_ageha 3場面・計15行に地の文の句点欠落が集中／第2章でも地の文29行／第3章 [1-2] ほか
- 追補（第4・5章）: 引用文（「〜」『〜』）で終わる地の文で句点が落ちる型が両章で再発した（第4章 [1-17] 5行・[14-8]・[14-9]／第5章 [M-01]〜[M-03]・[S-01]）。引用で終わる地の文行は特に確認すること
- チェック: 触ったファイルで `"speaker": ""` の行の末尾が「。」で終わるか確認する。`python3 tools/lint_dialogue.py <ファイル>` と `node remake/test/text_wrap.mjs` を通す

### A2. 文が完結した直後に「、……」を付けない
- 根拠: 同上（読点と三点リーダーの重複は誤り。第3章では「文完結後の使用は確実な誤り」と整理された）
- 違反例: 第1章 ch1_bonds L69「初めてです、……」／第3章 [1-11]・[3-8]（計7箇所）
- 追補（第4・5章）: 第4章では9ファイル（[1-1]・[2-1]・[3-2]・[4-3]・[5-1]・[6-1]・[8-1]・[9-1]・[13-1]）、第5章でも [M-18]・[D-06]・[S-06]・[T-05] に散在した。章をまたいで最も再発した表記ミスの一つ
- チェック: `grep -n '、……' data/dialogue/<ファイル>` で拾い、文完結後のものは除く（「間」を示す用法の可否は本書「要確認」Y4）

### A3. 2倍ダッシュは「──」（U+2500×2）に統一し、「――」（U+2015×2）を使わない
- 根拠: 第1章15ファイルの既存表記（35箇所が U+2500×2 で統一されていた）
- 違反例: 第1章 [1-4] ch1_main `ch1_day7_last_night` 3行＋ ch1_tournament 2箇所のみ U+2015×2
- チェック: `grep -P '\x{2015}' data/dialogue/<ファイル>` が0件であること

### A4. 感嘆符・疑問符の直後は全角スペース「　」で統一する（半角スペースを混ぜない）
- 根拠: 台本内の既存表記（同一ファイル・同一話者の他の行はすべて全角スペース）
- 違反例: 第3章 [1-5] ch3_main のパッキー3行だけ「！ 」（半角）
- 追補（第4・5章）: 第4章 [1-6]・[8-3]（ファイル単位で全角に寄っている例もある）、第5章 [D-05]・[S-04]・[E-05] でも混在が多発した。ファイルによって多数派が異なるため、統一先はそのファイル・同一話者の多数派に合わせ、少なくとも同一ファイル・同一場面・同一話者の中では割らないこと
- チェック: `grep -n '！ \|？ ' data/dialogue/<ファイル>` が0件であること

### A5. 引用は一重の「」に統一し、「『』」は「」で囲まれた内側でのみ使う
- 根拠: 台本内の既存表記（同一場面の他の行・看板や黒板の文字引用はすべて「」）
- 違反例: 第3章 [1-9] ch3_main 5箇所で、外側に「」がないのに『』を使用
- 追補（第4・5章）: 第4章 [1-9] では地の文の観客の声の引用が隣接場面で「」と『』に分裂し、[3-5] では台詞内引用に単独の『』が使われた。地の文で他者の声を引用する場合も一重の「」に統一する
- チェック: `grep -n '『' data/dialogue/<ファイル>` を拾い、二重引用の内側かどうかを確認する

### A6. 同じ対象・同じ文脈の数や量の表記は、ファイル内の既存表記に統一する
- 根拠: 表記ゆれ照合の原則（同一文脈の多数派・既存表記が正。パック5の表記方針も同じ）
- 違反例: 第3章 [1-8] 課題条件の数値表記が算用数字と漢数字で混在／第1章 みんとの自称年齢「20歳」と「二十歳」がほぼ同文で混在
- チェック: 同じ数量表現を grep で並べ、表記が揃っているか目視確認する

### A7. 形式名詞・和語の漢字／ひらがな表記は、ファイル内の多数派に統一する
- ルール本文: 「ほう／方」「とき／時」「あいだ／間」「一つ／ひとつ」「いちばん／一番」「ない／無い」「頷く／うなずく」「揃える／そろえる」「分かる／わかる」など、意味の変わらない漢字・ひらがなの選択は、同一ファイル（最低限、同一場面・同一話者・同一会話）の中で割らない。統一先はそのファイルの多数派に合わせる
- 根拠: 第4章・第5章の表記ゆれの大半がこの型だった（パック9 観点2 73件・パック10 観点2 23件の中心）。正本に個別の指定がある語（B1 のハガル等）はそちらが優先
- 違反例: 第4章 [2-9] 同一会話内で「なんて／何て」「柔らかい／やわらかい」／[5-4] 「〜のほうが」と「〜の方が」が同一ファイルで混在／第5章 [C-11] 同一依頼イベント内で「汗がひく／汗が引いた」
- チェック: 触ったファイルで対象語の両表記を grep し、混在していたら多数派に寄せる

### A8. 「書かれた文字」を地の文に出すときは鉤括弧で括り、場面内で形式を統一する
- ルール本文: メモ・手紙・寄せ書き・ノートの文面など、作中で書かれた文字を地の文に埋め込むときは「」等で括って引用だと分かる形にし、同じ場面の中であり／なしを混ぜない
- 根拠: 執筆手順の教訓（括弧がないと、出来事の描写と誤読される。第4章の指摘）
- 違反例: 第4章 [14-7] 寄せ書きの文言に鉤括弧あり／なしが同一シーンで混在／[2-23] ノートに書いた文言が括弧なしで、「書いたら隣の客が笑った」という出来事に誤読される形になった
- チェック: 「書いた」「書いてあった」で文面を出す行は、鉤括弧の有無が場面内で揃っているか確認する

### A9. 言いよどみは断片吃音で書かず、「…」表記で書く
- ルール本文: 言いよどみ・言いかけは「く、来るかと思った」のような「かな1文字＋読点」の断片で書かず、「…来るかと思った」のように「…」で書く（2026-11-24 オーナー決定）。断片の形は、語頭が後続の語と一致しない誤字（「き、来る」= 来るは「くる」）が演技の吃音に紛れて見逃されるため
- 根拠: 2026-11-24 の全テキスト仕分け（言いかけ断片970件を抽出して判定。誤字は2件のみだったが、どちらも断片の形だった）。対象は台詞 JSON だけでなく、プログラム内文字列も含む（誤字の1件は JS 内の台詞リストにあった）
- 違反例: `remake/js/daily/reel.js`「き、来るかと思った」（語頭不一致の誤字）／旧 `data/baito_events.json`（2026-11-25 に旧バイトと一緒に廃止）「し、識った……」（「識った」は語の誤り、正しくは「知った」）
- チェック: `tools/check_hesitation_fragments.py` が CI（dialogue-lint）で自動検査する。感嘆・相づち・擬音など言いよどみでない断片だけが許可リスト（`tools/hesitation_fragments_allowlist.txt`）に残る。新しい言いよどみは許可リストへ足さず、「…」表記へ直す

### B5. 大会の採点は現行仕様で書き、旧仕様（10点一括・別枠）を残さない

- チェック: `python3 tools/check_legacy_terms.py` と、変更した語の grep を全 `data/dialogue/` に対して行う

## C. キャラの口調・呼称（正本は characters.json の voice）

### C1. コロちゃんは本人の語尾「じゃ」「のう」「おる」を使わない
- ルール本文: コロちゃんの一人称は「余」、はじめは「勇者はじめ」、サメちゃんは「側近」と呼ぶ。王らしく短く断定する調子で、本人の古風な語尾は混ぜない
- 根拠: `data/characters.json` の `speech_style.korochan`（「本人の『じゃ』『のう』『おる』を使わず」と明記）
- 違反例: 第3章 [8-4]「毛布を頭までかぶっておる」／TRPG mist-kingdom 9.3.1「余がここにおるのに」
- 追補（第4・5章）: 第4章でも [5-5]「よく働きそうじゃ」／[18-4]／[18-5]「拭き直しておった」（禁止語「おる」の過去形「おった」も含む）と再発した
- チェック: コロちゃんの台詞を書いたら「じゃ／のう／おる」で grep し、本人の台詞と混同していないか確認する

### C2. 腹話術の行には必ず `"voice": "korochan"` を付ける
- 根拠: 台本の既存運用（同一ファイル内の他の腹話術行には付いている）。付け忘れると C1 の口調も表示も崩れる
- 違反例: 第2章 [3-10] ch2_home で欠落／第3章 [8-4] ch3_home_calls では腹話術行3箇所すべて欠落
- 追補（第4・5章）: 第4章でも [5-7]・[9-8]・[10-2]・[19-4] と欠落が再発し、いずれも後から追加した場面群（`samechan_3`・`4` 等）に集中した。場面を追加したら、その場面群の腹話術行をまとめて grep で確認すること
- チェック: `grep -n 'ventriloquism' data/dialogue/<ファイル>` の各行に `"voice": "korochan"` が伴うか確認する

### C3. サメちゃんの一人称は「わし」、はじめへの呼びかけは「お主」
- 根拠: `data/characters.json` の `speech_style.samechan`（「はじめへの呼びかけは『お主』」と明記）
- 違反例: 第2章 [3-8]・[3-9] ch2_home の4箇所で「はじめ」「勇者よ」に崩れた（C1・C2 の欠落と同じ場面群に集中した）
- 追補（第4・5章）: 第4章 [11-4]・[11-5] では同一会話の中でも「お主」と「はじめ」が混在した。追加・修正した会話は1本を通して呼びかけを確認すること
- チェック: サメちゃんの台詞のはじめへの呼びかけを grep で確認する

### C4. 組長のはじめへの呼びかけは必ず「あんちゃん」
- 根拠: `data/characters.json` の組長 `voice.hajime_address`（「はじめへの呼びかけは必ず『あんちゃん』（#1194）」と明記）
- 違反例: 第3章 [8-5] ch3_home_calls「あんたも探すか」

### C5. チャコール博士は丁寧語が基本で、はじめは「逢縁くん」、一人称は「私」
- 根拠: `data/characters.json` の dr_charcoal（`voice.hajime_address` は「逢縁くん」、description は「温和で紳士的」）／gref 固定事項（博士は「私」。例外は持ちネタ「それ作ったの、俺だもん」の時だけ）

- 追補（第4・5章）: 第5章 [M-19] では全編16箇所すべて「君」で、「逢縁くん」が一度も出なかった（要確認として指摘）。章単位で見ると、呼びかけ自体が消える形のぶれも起きる

### C6. 分岐（恋人分岐など）でも口調・呼称・敬語は本線と変えない
- 根拠: `data/characters.json` の voice 仕様は分岐で切り替わるものではない。gref §5（言い換えで canon から逸れる事故の型）

### C7. はじめの敬語・呼称は相手ごとに固定する（characters.json の voice / hajime_address を引く）
- 根拠: `data/characters.json` の各キャラ voice（例: つむぎへの対応は gref 固定事項でも「つむぎは『はじめさん』」と明記）
- 違反例: 第3章 [4-3] はじめが同い年のましろに敬語／[8-6] はじめがつむぎに完全敬語／[3-3] ましろがてつこを呼び捨て
- 追補（第4・5章）: 地の文の呼称・敬称も台詞と揃えること（第4章 [8-2] ハリールの地の文だけ敬称欠落／[16-1] クラウドだけ地の文で呼び捨て／第5章 [P-03] ましろの地の文表記がファイル間で分裂／[M-20] 千須の地の文呼び捨て）。また、つむぎへの呼び方は章の既存運用が正本で、第4章（台詞は「つむぎちゃん」、地の文は「つむぎ」）と第5章（「つむぎ」呼び捨て）で基準が異なる。第4章 [2-15]・第5章 [M-05] はそれぞれ逆側へのぶれ
- チェック: 敬語で書く前に、その相手との既存場面の敬語運用を grep で確認する

### C8. ひよりの台詞には `inner`（本心）を要所に付け、全行には付けない
- ルール本文: 儚い芝居・照れが出る要所にだけ `inner` を添える。場面を通して1行も無い付け忘れと、全行に付ける付けすぎの両方を避ける
- 根拠: `data/characters.json` の hiyori `speech_rules`（「全行に本心を付けない」と明記。恋人後も `inner` に本心を書く運用）
- 違反例: 第4章 [5-8] 追加分の `hiyori_3`・`hiyori_4` は `inner` が全欠落（同じファイルの `hiyori_1`・`2` にはある）／[5-9] `hiyori_1` は全4行に付与され正本ルールに抵触／第3章 ch3_home_calls 後半でも全欠落が起きた（E1 の違反例）
- チェック: ひよりの場面を書いたら、その場面の `inner` の有無と密度を前後の場面と並べて確認する

## D. 設定の一貫性

### D1. スティーブのタイマーは1つだけ
- ルール本文: タイマーを複数並べる描写や、予備タイマーの授与・返却を新たに書かない（予備ははじめに貸したもの、という既存の扱いまで）
- 根拠: `data/dialogue/bond_after.json` の場面コメントに「タイマーは一つ（予備ははじめに貸したもの）」と明記（2026-11-13 の設定訂正の反映）
- 違反例: 第3章 [12-1]「小さなタイマーが三つ、きっちり等間隔に並んでいた」／[5-6]・[4-4] 予備タイマーの授与・返却が3ファイルに残存
- チェック: スティーブの場面で `grep -n 'タイマー' ` を拾い、個数の表現を確認する

### D2. ヴォルクの記録は紙のノートに書く（モニターや端末に打ち込ませない）
- 根拠: `data/characters.json` の volk `background_secret`（「紙のノートに日付・室温・湿度・炭の数・HMDの温度を書く」と明記。計測を盛りすぎない訂正も同所）
- 違反例: 第3章 [6-1] ch3_volk「モニターに短く打ち込んだ」
- チェック: ヴォルクの記録描写は「ノートに書く」形で統一する

### D3. 上園はシーシャ情報サイト『HOOKAH PRESS』の編集長（「雑誌」「雑誌編集」と書かない）
- 根拠: `data/characters.json` の uezono（description「日本最大のシーシャ情報サイト『HOOKAH PRESS』の編集長」、title「HOOKAH PRESS編集長」）
- 違反例: 第1章 [10-9] ch1_spots の自己紹介「HOOKAH PRESSって雑誌で、編集をやってまして」
- チェック: 上園の肩書きに触れる台詞は characters.json の表記そのままに写す

### D4. あげはの端末は「デコケータイ」（「スマホ」と書かない）
- 根拠: 台本側の既存描写が正本（`data/dialogue/ch2_preparation.json`・`ch2_city_guests.json` で、あげはの端末は一貫して「デコケータイ／デコられたケータイ」）
- 違反例: 第2章 [2-7] ch2_tournament の1箇所だけ「スマホ」
- チェック: キャラの持ち物は、そのキャラの既存場面での呼び方を grep してから書く

### D5. 名前認知・面識の段階を守る（既知の相手を初対面のように書かない）
- 根拠: `data/characters.json`（つむぎ description「はじめは物語開始時から名前を知っている」、なる background_secret「前に店に寄ったとき見た顔」）／gref「交流の時系列ルール」（初対面・初入店・初めての交流は区別し、会ったことがあれば初対面の挨拶を繰り返さない）
- 違反例: 第1章 [2-12] つむぎ未交流分岐だけ「窓際の席の、いつもの女の子だ」と名前を知らない扱い／[15-11] なる「おー、ここがtonariか」／第2章 [3-15] PEPPERMINT とみんとのミント特化が既知のはずなのに初来店のような独白
- チェック: 分岐側の行を書くときは「この分岐でも面識・認知は同じか」を確認する。認知の条件フラグがある場面は全分岐で照合する

### D6. みんとの正体・本名の開示段階を崩さない
- ルール本文: 正体判明までは、私服・素のみんとをはじめが同一人物と気づく前提の場面を作らない。本名（木成頼 栞）は `ch1_minto_fifth` で明かす
- 根拠: `data/characters.json` の minto description（私服のお姉さんと正体がつながる場面の段取り、`private_name` の扱い）
- 違反例: 第1章 [11-2] `outing_minto_1` で、判明前でも私服・素の声のみんとと待ち合わせて買い物するのにはじめが気づかない
- 追補（第4・5章）: ①私服・素の場面には `"metadata": { "private_scene": true }` を付け忘れない（第4章 [19-2]。欠落すると名前欄が「みんと」のまま出る）。②営業の場面（電話を含む）では素の口調・一人称「私」へ無断で切り替えない（第4章 [6-5]）。③公の場ではじめが本名を口に出す・私服姿で登場させるのも開示段階の違反（第5章 [P-01] 打ち上げ場面）
- チェック: みんとの場面は `_minto_identity_revealed`／`_minto_name_known` の段階と照合してから書く。あわせて private_scene の有無と立ち絵（ura_* か営業姿か）を場面ごとに確認する

### D7. 初出の描写を事実として固定し、後続の場面で矛盾させない
- 根拠: gref §1「設定の一元管理」（各事実の正本は1つだけ。他は参照し、書き直さない）
- 違反例: 第3章 鉄の煙の看板の上下が初来店と後日訪問で180度逆転（どちらが正かは「要確認」Y2）／第2章 [3-13] 店舗ごとの独自要素（帰りの飴）の扱いが他場面と食い違う
- チェック: 物の配置・店の特徴を書く前に、初出の場面を grep して描写を写す

### D8. 時系列（何を・いつ知るか／出来事の前後）を場面コメントや既存場面と矛盾させない
- 根拠: gref「交流の時系列ルール」（段階と進行を独立させ、遅れて読んでも成立させる）
- 違反例: 第2章 [3-11]＋[13-1] 課題ストロベリーは「DAY9の試煙会で知る」と場面コメントにあるのに試煙会前の場面で既知扱い／第1章 [13-1] 大会の翌々日の場面で大会を「今日」と扱う／第3章 [1-14] 夕食を食べ終えた直後に弁当を温め直す、[3-9] 茶葉缶のふたを開ける前に中身が見えている
- 追補（第4・5章）: 固定イベント（前夜祭など）のある時間帯に、成立しない約束・予定を足す型が繰り返し起きた（第4章 [18-8]・[10-8]・[24-2]。場面コメントに「夜の約束は足さない」と明記された運用もある）。また第5章 [M-04] では、自由行動の開始場面で初めて明かされる前提（出張事業）を、それより前に再生される場面で既出扱いしていた。前提の初出は、その前提を明かす場面より後ろの場面でだけ使うこと
- チェック: 知識の初出（場面コメント含む）と出来事の順序を、関連場面を並べて確認する

### D9. 分岐の合流後は、通っていない分岐の出来事を前提にしない
- 根拠: gref「交流の時系列ルール」（分岐の外に共通処理を置き、どちらでも成立させる）
- 違反例: 第3章 [14-1] `branches.heat` を通らないと客は「熱い」と言っていないのに、合流後の台詞が「熱いって言ったあとの顔」と回想する
- 追補（第4・5章）: 分岐「前」の共通部に、片方の分岐でしか成り立たない前提を置く型も起きた（第4章 [3-9] 大会前後を分岐する直前の共通部に大会前前提のモノローグ／[12-12] `failed` 分岐では発生していない「戻したあとの返事」を合流部が前提）。共通部と合流部は、どの分岐から来ても成り立つ文だけにすること
- チェック: 合流後の行は、全分岐を通った場合でも読めるか1本ずつ確認する

### D10. 小道具・状態の継続性を保つ（受け渡し・開閉・着用は後続場面で引き継ぐ）
- ルール本文: 物を受け渡したら持ち主が移る。開いた物は閉じる描写なしに「もう一度開く」ことはなく、掛けた・着た位置も描写なしに変わらない。包みの中身は、解く・開ける描写の前に地の文で断定しない
- 根拠: gref §1「設定の一元管理」の場面内版（物の状態も事実として固定される）
- 違反例: 第4章 [22-1]・[22-2] 差し入れとして渡した袋を別れ際に本人が振っている／[23-3] 開いたままのスケッチブックを「もう一度開いた」／[21-4] 腕に掛けていた上着が「肩に掛け直して」に変わる／[4-11] 包みを解く前に中身をボウルと断定
- チェック: 小道具の登場場面では、所持者と状態（開閉・着用位置）を前後の行と照合する

### D11. 通話場面は「音」で描写し、開始・終了の区切りを入れる
- ルール本文: 電話・通話の場面では、相手側の様子は音（声・物音）で書き、目の前で見ているような視覚描写にしない。通話の始まり（着信に出る・かける）と終わり（別れの挨拶・「通話が切れた。」等）の区切りを入れてから、余韻描写や次の場面へ移る
- 根拠: 執筆手順の教訓（第4章 `ch4_home_calls.json` の電話場面群で集中発生）
- 違反例: 第4章 [6-15] 通話中に「紙の上で鉛筆の先が止まった」と相手側を視覚描写／[6-16] 自転車が通り過ぎる様子を通話越しに視覚で描写／[6-19]・[6-20] 通話が切れないまま場面が終わる・景色へ飛ぶ
- チェック: 通話場面は「電話の向こうで〜音がした」の形になっているか、終了の区切りがあるかを確認する

### D12. 使い回される汎用場面に、時間帯・個別経路を固定する描写を入れない
- ルール本文: 昼夜の両方・再訪・複数ルートの合流など、条件の違う状況で再生されうる場面（自由行動の日常会話、汎用の移動・帰路テキスト、共通の締め等）には、その条件と衝突しうる描写（「昼の熱」「昼下がり」、特定ルートでしか起きない身体状態など）を入れない
- 根拠: gref「交流の時系列ルール」（遅れて読んでも・どの順で読んでも成立させる）の時間帯・経路版
- 違反例: 第4章 [1-45] 昼夜両用のスーク場面で「昼の熱」／[2-37] 昼休み寄りの休養会話で「夜を横切る」／[3-25] 夜来店でも再生される場面で「昼下がりのカフェ」／[7-13] 海に入らないルートでも共通締めが「濡れた髪のまま」
- チェック: 汎用場面を書くときは、発火しうる時間帯と全ルートを通して矛盾しないか確認する（発火制限がコード側にある場合は場面コメントに明記する）

### D13. シーシャの実務・物理描写は実際の構造に合わせる
- ルール本文: 熱い炭はトングで扱い、素手で持たせない・かざさせない。葉はハガルの中（炭の下）にあり、外から色の変化は見えない。吸うのはホースからで、台本体に口を付けない。火のついた台を持ち上げて見せない。シーシャの単位は「一台」（「一杯」と数えない）、感想は「吸いやすい」（「飲みやすい」と言わない）
- 根拠: 作中のシーシャ描写の一貫性（他場面の正しい描写が正本。第4章・第5章で物理的にあり得ない描写が繰り返し見つかった）
- 違反例: 第4章 [16-4] 赤熱した炭をトングの描写なしに手渡しし箱の脇へ置く／[2-12] 火のついた台を手元で持ち上げて見せる／[4-19] 炭の上で指が止まっている／第5章 [D-02]「炭の上で、葉がゆっくり色を変えていく」／[C-03]「飲みやすい」／[C-04]「もう一杯」
- チェック: 炭・葉・ホース・台の動作を書いたら、熱い物を素手で触っていないか、上下関係（葉→ホイル／HMD→炭）が合っているかを確認する

### D14. キャラの持ち物・道具は正本の形態で統一し、別の道具に置き換えない
- ルール本文: 正本や初出で定まったキャラの道具（形態・媒体）は、説明なしに別の道具へ切り替えない。紙かタブレットかのような媒体の違いも含む
- 根拠: `data/characters.json`（つむぎの画材はタブレットと明記）／D4（あげはの端末）の一般化
- 違反例: 第4章 [9-7] つむぎが友人版ではタブレット、恋人版では紙のスケッチブック（同じ会場・同じ直後の場面）／[7-7]・[10-5]・[13-9] でもタブレット／スケッチブック／鉛筆がファイル間で割れた
- チェック: キャラの持ち物を書く前に、そのキャラの既存場面での道具を grep して形態を合わせる

### D15. クライマックスで初めて見せる表情・反応を、通常場面で先出ししない
- ルール本文: 物語の到達点として用意された「初めて」の表情・反応（初めて笑う、初めて本名を名乗る等）は、それ以前の通常場面で先に使わない。立ち絵の `face` 指定も同じ扱いにする
- 根拠: `data/characters.json`（鉄仮面さんは「感情を全く顔に出さない」）と `ending.json` の構成（会計後に初めて口元が緩み、本名を名乗る）
- 違反例: 第5章 [M-07] 本編の通常場面3箇所で鉄仮面さんに `"face": "smile"` が先行し、エンディングの「……笑いました？」の到達点と矛盾した
- チェック: 到達点を持つキャラの `face` と反応を書くときは、その「初めて」がどこかを確認してからにする

### D16. 現地語圏では通訳等の媒介なしに会話させない／心の声に他人を反応させない
- ルール本文: 言葉が通じない相手とは、通訳アプリを向ける・身振りで伝える等の媒介を描いてから会話に入る。はじめの心の声（inner・独白）は他者に聞こえないので、それに現地の人間が反応する形にしない
- 根拠: 作中の言語設定（ドバイ編では通訳アプリが前提として描かれている場面が多い）
- 違反例: 第4章 [17-7]「身振りで聞くと」とした直後に現地男性が日本語で語り、はじめも通訳なしで理解して反応／[17-6] 心の声の直後に作業員が日本語で返答／[2-13] 通訳アプリの描写がない場面群と不通の場面が混在
- チェック: 現地の人間との会話場面では、媒介の描写があるか、心の声への反応になっていないかを確認する

## E. 執筆手順

### E1. 場面群の後半で水準が落ちていないか、前半と見比べる
- ルール本文: 1ファイル・1場面群を書き終えたら、後半の場面について face の付け忘れ・地の文の呼称（さん付け等）・口調・inner の有無が前半と揃っているか見比べる
- 根拠: 執筆手順の教訓（パック8の横断課題。後半だけ水準が落ちる事故が2ファイルで同時に起きた）
- 違反例: 第3章 ch3_home_calls 後半7場面は全114台詞行が `"face": "normal"` 固定になり、地の文はさん付け化、ひよりの inner は全欠落、口調不整合も同区間に集中／ch3_mashiro 後半 `mashiro_time_*` は地の文が「ましろちゃん」に変化
- 追補（第4・5章）: 第4章 `ch4_home_calls.json` 後半8本では face 全行固定（95行超）に加え、凛想のマダム口調化・サメちゃんとあげはへの方言混入・みんとの素の口調への切替まで同区間に集中した（[6-4]〜[6-10]）。第5章でも `ch5_catering.json` 後半10件が3行定型に痩せ、前半との密度差と仕様（master_spec の「客の温かい一言で終わる」）違反が重なった（[C-01]）。追加分の場面群は、既存分の密度・口調・face・inner の付け方と並べてから提出すること
- チェック: 後半の場面の `"face"` の分布と地の文の呼称を、前半と並べて確認する

### E2. 地の文に台詞を台本調で直書きしない（話者は speaker で表す）
- 違反例: 第3章 [2-1]・[16-1] 地の文（`speaker: ""`）内に「少年『〜』」と直書きし、地の文の句点ルール（A1）にも触れた
- チェック: `grep -n '「' ` で地の文行を拾い、台詞が混入していないか確認する

### E3. 心の声は各行を「（……）」で囲む
- 根拠: gref §2・固定事項（「心の声は各行を（）で閉じる」。色付けは「（」で始まる行にだけ付く）
- 違反例: 第2章 [7-5] ch2_deliveries の単独訪問5場面・12行だけ括弧がなく、独り言を声に出しているように見えた（同ファイルの他の単独訪問場面はすべて括弧付き）
- チェック: はじめの心の声の行は「（」で始まるか確認する

### E4. 背景指定は場面の場所と一致させる
- 違反例: 第3章 [14-5] mukai 店内の2場面で地元店の `bg_tonari_inside.png` を指定
- 追補（第4・5章）: 背景の「順序」も場面と一致させること。第5章 [M-23] では到着後の室内描写の後に `type: "bg"` が来ており、前の背景のまま到着文が表示された。背景切替は、それを前提とする描写より前に置く
- チェック: `metadata.bg` を場面の場所と照合する（代用が意図的な場合は場面コメントに理由を残す。要確認だった例は [3-10]）

### E5. 設定・固有名詞は創作せず、正本からそのまま写す
- 根拠: gref §5（文章を「良くしようと」言い換えると canon の固有名詞・言い回しから逸れて矛盾や旧名復活が起きる）
- チェック: 固有名詞・肩書き・呼び方を書く前に、正本表（gref §1）と characters.json を引く

### E6. 汎用モブ話者IDを使うときは、表示名と役割の一致・話者の切り替わりを確認する
- ルール本文: `customer`・`shop_clerk` 等の汎用IDは、表示名（「お客さん」「店員」）がその場面の人物の役割と合っているか確認する（違う場合は表示名の上書きや専用IDを使う）。同じIDで複数人を続けて喋らせる場合は、発言が移る箇所に地の文を挟んで誰の発言か分かるようにする
- 根拠: 執筆手順の教訓（同一表示名のまま一人称・敬語が切り替わると、同一人物の口調が壊れたように見える）
- 違反例: 第5章 [C-05] `customer` 5行連続でタメ口「俺」と敬語「私」が地の文なしに混在／[E-03] 2組の客が同一IDで続けて登場し会話相手が判別できない／第4章 [17-6] 貨物船の作業員が「店員」表示／[12-6] 本文は「スタッフ」と呼ぶのに表示名が「店員」
- チェック: 汎用IDの連続行は、表示名と役割の一致と、人物の切り替わりが地の文で示されているかを確認する

### E7. 反復再生される場面群では、書き出し・締めの台詞を相手ごとに変える
- ルール本文: 到着挨拶・日常ループ・試飲など、複数本が連続再生されうる場面群では、冒頭の書き出しと締めの台詞を全員分コピーで済ませず、相手や状況に応じた差をつける
- 根拠: 執筆手順の教訓（同一文の反復はテンプレート感として読者に強く残る）
- 違反例: 第4章 [15-3] 到着5場面の締め台詞が一字一句同一／[13-12] 友人夕方6場面すべてが同じ書き出し「前夜祭へ出かける前、ロビー〜」／[2-31] 試飲4本すべてで冒頭2行がフレーバー名の反復
- チェック: 場面群を書いたら、各場面の冒頭1行と最終行を並べて比較する

## F. TRPGシナリオ

### F1. バリアントを作るとき、元話者の台詞をコピペしたままにしない
- ルール本文: `regulara`／`regularb` バリアントは、口調・一人称・呼び方をバリアントの話者に合わせて書き直す。元台詞とバイト単位で同一の行が残っていないか照合する
- 根拠: パック5の添削基準（`data/characters.json` の口調仕様＋同一シナリオ内の常連の一貫性）。口調・設定の不整合209件の中心がこの型だった
- 違反例: shark-last-order 4.3.1（ひよりの行が regulara に残留）／ordinary-cup 3.3.1（アダムの行が残留）／apple-thief 6.3.1（ひよりの行が残留）。いずれも元台詞とバイト単位で同一と実証された
- チェック: バリアント作成後、元ノードとバリアントの text を diff し、同一行があれば口調を直す

### F2. GM の待機文（*Idle）や定型文にも、GM の口調を適用する
- 根拠: `data/characters.json` の GM の口調仕様（六角サイは常時敬語、クラウドは文頭「……」等）。共通テンプレートのまま残すと口調が崩れる
- 違反例: regular-harbor 1.3.20 `listenIdle` だけ常体（同じGMの regular-mail は敬体）／クラウドがGMのシナリオで `prepareIdle`・`endingIdle` だけ文頭の「……」が抜けてテンプレートのまま残った
- チェック: シナリオ内の全 *Idle 文を並べ、GM の口調要素が全てに付いているか確認する

### F3. 役割表示（PL／卓の会話）と発言内容を一致させる
- 違反例: regular-harbor 1.3.17 役割表示が「PL／卓の会話」なのに、物語内の行動を一人称で語っている
- チェック: 役割表示が卓側の行に、物語内の一人称の行動描写が混ざっていないか確認する

### F4. TRPG の表記は、全シナリオの多数派表記に統一する
- 根拠: パック5冒頭の正本方針（全9シナリオでの多数派表記・常用漢字を正本とし、非統一側だけを直す）
- 具体例: 個数は漢数字「三つ」（算用数字「3つ」にしない）／単独の明かりは「灯り」／補助動詞は「〜てくる」／単独の動詞は「できる」
- 違反例: regular-harbor 1.2.1 1箇所だけ「3つ以上の手がかり」（同ファイルの他は「三つ以上の手がかり」）
- チェック: 新規シナリオ・追加文は、既存9シナリオでの表記を grep して多数派に合わせる

### F5. GM の地の文の文体（敬体／常体）をシナリオ内でぶらさない
- 違反例: purikura-hero 8.5.1 ほか（GM 地の文だけ常体になる行が散在し、「場面転換の不自然さ」30件の実質はこの文体ぶれだった）
- チェック: GM の地の文の文末を場面ごとに並べて確認する
