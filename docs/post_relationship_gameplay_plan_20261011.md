## 基本方針
- ♥1〜5の段階制は維持。**♥5で交際するかどうか決定**し、交際後も♥5のまま。
- 交際後もゲーム内の日常・店への訪問・他ヒロインとの交流を継続できる。「恋人になったらコンテンツ終了」にはしない。
- 交際後は**恋人固有イベント（各3本程度）＋繰り返し遊べる汎用デート＋恋人専用LIME・来店会話＋節目イベント**の二層以上の構成。
- デートは店外・営業時間外を中心に。仕事中のキャラは店の仕事を優先する。
- 交際後のイベント進行度は好感度♥5とは別に管理。交際日、デート既読、記念日、予定、関係状態を保存。
- 恋人限定のイベントは親友ルートでは出さない。親友ルートも専用の交流を用意する。
- 複数恋人が成立するゲーム仕様を尊重。予定重複を防ぎ、既存の修羅場イベントとの整合を取る。恋愛関係の重複に関する分岐・罰則は別途設計。

## 交際後の遊びのループ（提案）
1. いつもの店に訪問すると、交際状態に応じた専用挨拶・短い会話が時々発生。
2. LIMEで恋人に連絡・デートに誘う／相手から誘われる。
3. デート場所・日付を選び、他の予定と衝突しなければ実施。
4. 固有デートが条件に応じて解放される。終了後も汎用デートを繰り返せる。
5. 一定期間・記念日に特別な短い会話やイベントを解放。頻繁な通知や毎日必須の作業にはしない。

### 4. 所在地・訪問の状態遷移

常住地は設定データ、一時所在地は保存された旅程から求める。キャラ設定の常住地を東京へ書き換えない。マップ、LIME、予約確認、イベント実行は共通の所在関数を使う。

`offered（予告）→ booked（承諾・日程確定）→ arrived（到着・合流待ち）→ staying（合流・滞在）→ returned（帰郷済み）`

- 予告では訪問日・滞在期間を見せ、承諾時に全日程と集合枠の衝突を検査する。衝突なら別日を提案し、本人への辞退扱いにしない。
- 「その日は都合が悪い」は保留し、数日後に再提案。「また今度にしよう」は自動再招待を止める。予定の都合で2回連続明示的に断った場合も停止し、「保留中のお誘い」から手動再開できる。
- 承諾で連続辞退回数をリセットする。未読・期限切れ・体調不良・強制ストーリーによる延期は明示辞退に数えない。関係分岐や好感度罰にしない。
- 到着通知から既存の行動枠で合流する。合流待ちは対面の入口を合流イベントに向け、合流後は東京のデート・短い滞在会話を選べる。
- 滞在中の「デートに誘う」は東京の実在するデート先へ接続する。通常の地元店舗の固定会話へ転送しない。
- 帰郷の短い台詞は最後の交流または日末に添える。読み逃し・未合流でも旅程の終端で帰郷処理を行い、東京に残り続ける状態を作らない。遠距離LIMEへ戻る。
- はじめの地域移動・章移行で滞在条件が崩れた場合は、旅程を整理・延期し、確定済み予定を黙って捨てない。海外同行と固定応援には専用の終端を用意する。

初期の調整候補は**訪問予告2日前、滞在2〜3日、再訪間隔は恋人約7日・友人約14日**。数値は固定の世界設定ではなく、テンポを見て調整するデータ値として扱う。合流と通常デートはそれぞれ1行動。短い見送りに追加の行動を要求せず、閉店後を第3の自由行動枠にしない。

### 5. LIMEの入口・予定・複数交際との統合

- 「話しかける」：所在地を問わず短い交流。無料LIME・到着通知だけでは能力・スロット経験値を付けない。
- 「デートに誘う」：成立済みの恋人用。同じ地域なら対面デート、遠距離なら訪問の相談・日程調整へ接続する。遠方から即座に対面イベントを開始しない。
- 「遊びに誘う」：既存の友人判定に該当する相手用。同じ地域なら外出、遠距離なら低頻度の訪問相談。
- 「保留中のお誘い」：攻略途中の固有イベント、デート、訪問の未完了分を共通表示する。元の固有イベント順序を維持し、保留を理由に次の必須イベントへ飛ばさない。
- 受信履歴がない連絡先からも発信できる入口を作る。みんとの店用・私用アカウントなど、既存の正体・連絡先の開示順は維持する。
- 通知は本筋→確定旅程の到着・変更・帰郷→保留固有イベントの再招待→恋人の日常→友人の日常の順で抑制する。既存の1日上限・同一相手の未返信制御を共通利用し、訪問通知を加えて連発させない。
- 永続招待・旅程を正本とし、当日実行する1件だけを既存`pendingInvite`へ渡す。未読／返信済みと、約束の実施済みは別状態にする。
- 複数恋人の通常訪問は滞在期間全体を比較して順番に予約する。対面予定だけでなく合流・強制イベント・地域移動と競合しないことを承諾時と実行時に確認する。
- 修羅場は、成立済みの複数交際と**実際にその場にいる人物**で既存の発生条件を確認する。訪問延期だけでは罪悪感や破局を発生させない。固定のドバイ応援参加と通常訪問の同時1人制限を混同しない。

### 6. 第4章の同行と既存ストーリーへの影響

- 出発前に候補の恋人と「同行なし」を明示し、選択結果を保存する。サメちゃんも恋人なら選択できる。友人を親友という別ランクで同行候補に加えない。
- 同行者は同じ旅程で渡航する1人。それ以外のヒロインは、`CLAUDE.md` のドバイ登場条件を満たせば別便で応援に来られる。同行者に選ばなかったことを不参加・破局にしない。
- ましろは第3章クリアで既存どおり登場し、恋人でなくても参加する。同行選択と参加条件は別判定。
- 既存の「どうしてここに？」などの独立到着台詞には、同行時の差分・スキップが必要。出発、移動、合流、滞在、帰国の接続はキャラ別台詞データで補う。
- アゲハの真相開示など、既存の感情回収は適切な関係条件で残す。本筋の回復・作戦会議・大会参加を、同行者の選択や恋人の有無で封鎖しない。
- 第4章に新規恋愛ルートは追加しない。サメちゃんの恋人成立は第3章までに接続し、その関係を第4章で回収する。
- 海外の固定本筋・師匠枠・大会規則は維持する。渡航するだけの無料・強制場面に成長報酬を加えない。

### 7. Claudeがイベントを追加するためのデータ構造案

以下のパス・フィールド名は**実装時の候補**。今回ファイルを新設したり、実装済みスキーマとして扱ったりしない。

| データ候補 | 内容 |
| --- | --- |
| `data/character_presence.json` | キャラID→常住地域・通常の対面場所・章別の登場制限。人物名・プロフィールは複製しない。 |
| `data/relationship_policies.json` | 恋人／友人の連絡・訪問頻度、滞在期間、再招待間隔、関係恩恵。親友用の関係enumを足さない。 |
| `data/relationship_events/index.json` | 明示的に読み込むイベント定義ファイルの一覧。 |
| `data/relationship_events/<char>.json` | 安定したeventId、対象人物、種類、関係・章・段階・地域の条件、初回／反復、予定制約、台詞参照。 |
| `data/dialogue/visits_<char>.json` | 予告、再予告、保留からの再開、承諾、合流、滞在デート、見送り、帰郷、同行差分のキャラ固有台詞。 |

定義例（台詞IDは説明用の仮IDであり、存在する台詞ではない）：

```json
{
  "eventId": "visit.tsumugi.tokyo.first",
  "characterId": "tsumugi",
  "kind": "visit",
  "conditions": {
    "relationship": "lover",
    "chapters": [3, 4, 5],
    "stages": ["tokyo_daily", "tokyo_preparation", "free_roam"],
    "playerRegion": "tokyo"
  },
  "repeat": { "mode": "once" },
  "schedule": { "leadDays": 2, "stayDays": 2 },
  "dialogueIds": {
    "offer": "visit_tsumugi_tokyo_offer",
    "retry": "visit_tsumugi_tokyo_retry",
    "meetup": "visit_tsumugi_tokyo_meetup",
    "stayDate": "visit_tsumugi_tokyo_date",
    "farewell": "visit_tsumugi_tokyo_farewell",
    "returned": "visit_tsumugi_tokyo_returned"
  }
}
```

状態は定義JSONに書き戻さず、セーブの共通領域に分ける：

- `world`：単調増加する通算日、現在地域、章内段階。既存の章内day・slotとは役割を分ける。
- `relationshipEventProgress[eventId]`：解放・招待・保留・予約・完了、連続辞退数、次の再招待日、自動再招待停止。
- `travelPlans[occurrenceId]`：人物、行き先、到着日、帰郷日、集合予定、旅程状態、元eventId。反復訪問にも固有の実施IDを付ける。
- `overseasCompanion`：選択した人物または同行なし、選択・出発・帰国の進行。
- 既読・反復履歴：初回完了、前回実施日、直近会話の履歴。イベントと通知の既読を分け、同一会話の連続抽選を抑える。

Claudeは既存キャラID・台詞形式に従って定義と台詞を追加し、共通コードの分岐を増やさずに訪問・再会を制作できる形を目指す。未知のキャラ・台詞ID、条件不足、未ロードの定義は検証で検出する。他キャラのデート台詞を代替再生しない。

### 8. セーブ・章移行・第5章の扱い

- 調査時のsave schemaは11。実装開始時に最新版を確認してから次の版へ移行する。既存の好感度、恋人、分岐、能力、所持品、贈り物・既読、手動3枠を保持する。
- 新項目は空の履歴・旅程・同行なしで安全に初期化する。既存の好感度や訪問回数から、新しい訪問・会話・関係の記憶を実施済みにしない。
- 章内dayのリセットで通算日を戻さない。新規通知と実施IDは章や通算日を含め、同じDAYの再登場による重複を防ぐ。
- 約束承諾、合流、デート完了、帰郷、同行選択、地域移動、章移行ごとに保存し、途中ロードでも二重再生・二重報酬を防ぐ。新規訪問を従来の攻略固有イベント数へ加算しない。
- 第5章は自由行動の残り日数表示を外し、地域と日付に合わせたHUD・マップを使う。第1章の固定朝イベントや14日終了処理を再発火させない。
- 第5章の本筋開始と真エンディング移行は明示的な場面状態にする。スタッフロール後はタイトルへ復帰し、通常日常ループへ自動で戻さない。タイトルからのロードは保存された場面・章から復帰できるようにする。
- 関係恩恵は既存の能力・体力・作業効率等の範囲で設計し、地域に依存させない。贈り物の既存効果を取り消さず、関係成立の恩恵と二重加算しない。無料交流に経験値を付けない現行ルールを守る。

### 11. 残る調整点・実装上の注意

方針の承認待ちは解消した。今後調整するのは、地域移動の消費時間・料金、通知や再訪の具体的間隔、各関係恩恵の効果量、キャラ別の台詞・滞在期間、同行選択UIの見せ方。未提示の数値を今回の保存で固定しない。
