## 0. 「シーシャ作り」が走る2つのコンテキスト

| | 大会パート（本番） | 練習パート（日常） |
|---|---|---|
| ファイル | `scripts/tournament/ch*_tournament.gd` | `scripts/daily/practice.gd` |
| ステップ数 | **16** | **10**（TUTORIAL表記） |
| 採点 | あり（専門点/観客点→順位） | なし（ステータス育成・機材練習ボーナス） |
| フレーバー | 在庫から1〜3種を選ぶ | チュートリアル固定（ダブルアップル+ミント 各6g） |
| プレゼン | あり（手札プレゼン） | なし |
| 役割 | 勝敗を決める本番 | 作りの手触りを練習＆育成。**新メカニクスの試作場としても最適** |

両者は同じ「作りの工程」を共有している。**まずモックは大会16ステップを基準**にし、練習はそのサブセットとして設計するのが効率的。

各ステップの「目的 / 操作 / 読む状態 / 書く状態 / 採点寄与」。`_show_*` は実装関数名。

|---|---|---|---|---|---|

| 4 | 盛り方選択 `_show_packing_style_step` | ふわふわ/ふつう/しっかり | ― | `_packing_style` | 味/煙寄り＋後続補正 |

| 9 | 思考の暴走弾幕 `_show_mind_*`（STEP9） | 弾を避けて耐える | ― | `_mind_*`（被弾→吸い出し速度劣化等） | 失敗で後続ペナルティ |

## 2. 共有状態モデル（作りを貫く変数）

シーシャ作りは**1つの状態が工程をまたいで変化していく状態機械**。設計の核はここ。`ch1_tournament.gd` の実変数名で整理。

### A. プレイヤーの選択（入力）
- `_selected_bowl` / `_selected_hms`（機材）
- `_selected_flavors`（1〜3種）/ `_manual_packing_grams`（合計12g配分）
- `_packing_style`（airy/normal/dense・計画では firm_taper 等の派生も）
- `_selected_charcoal_count`（3 or 4）/ `_steam_minutes`（5-10）
- `_hms_lid_state`（open/half/closed・調整フェーズ）

### B. 内部状態（数値・**プレイヤー非表示**）
- `_heat_state`（熱状態。-3〜+3。煙の様子テキストで表現／数値は出さない）
- `_zone_bonus`（穴の均一さ＝熱分布）
- `_charcoal_stage`（1-5 焼き段階）/ `_charcoal_back_stage` / `_charcoal_flipped`
- ミックス特性: `heat_tolerance` / `smoke_weight` / `steam_bias`（フレーバーのグラム加重平均）
- `_special_mix_name`（レシピ成立名）/ `_ash_cleared`

### C. ミニゲーム成績（中間出力）
- アルミ: 精度（perfect/good/near/miss → accuracy）
- 弾幕: `_mind_lives_remaining` `_mind_hits`（被弾で吸い出し速度劣化 `_mind_pull_speed_adjust`）
- 吸い出し: `_pull_hit_count` `_pull_quality_total`

### D. スコア（最終出力）
- `_technical_points`（専門点）/ `_audience_points`（観客点）
- `_presentation_cards`（手札）/ `_played_cards`（出した手札）→ プレゼン加点
- `_player_rank`（最終順位）→ ShishaRank

### 状態の流れ（要点）
```
機材 ─┐
      ├→ 許容幅(heat_tolerance補正) ─┐
フレーバー特性 ─┤                    │
盛り方 ────────┼→ 蒸らし最適レンジ ──┼→ 各工程の判定 →（delta_spec / delta_aud 加算）
              ├→ 吸い出しゲージ速度 ─┤                    ↓
炭(焼き/数) ──┘                    │            技術点 / 観客点
                                   └→ 手札生成 → プレゼン → 一貫性ボーナス
```

## 3. 各ステップ詳細（モックアップ用・画面と演出）

> 全ステップ共通HUD: 上部に `STEP n / 16` ＋ ステップタグ、左に **ボウル上面ビジュアル（`_BowlVisual`）**、中央に操作UI、下部に **情報テキスト（ページ送り `_info_pages`）**、要所で **審査員リアクション**。数値は出さず煙の様子・反応で状態を伝える。

### STEP1 セッティング（機材）
ボウル/HMSを選ぶ。テーマ名を表示。機材の練習ボーナス・相性（素焼き×タヌキッシュNG）に注意。コンボ名表示あり。

### STEP2 フレーバー選択
在庫から1〜3種チェック。**特性ヒントを定性表示**（例: 「清涼系｜熱に強い｜軽い煙」）。数値は出さない。テーマ一致でボーナス。

### STEP3 パッキング配合（12g）
各フレーバーのゲージで配分、合計12gで確定。確定時に**レシピ判定**（覚えたレシピの組み合わせ＋比率tolerance内なら成立→`_special_mix_name`、専用手札追加）。未習得で近い配合なら伏線テキスト。

### STEP4 盛り方選択（3択）
ふわふわ/ふつう/しっかり。選択で独白＋`_BowlVisual`のフレーバー層密度が変化。後続（heat_state, 蒸らし最適, 吸い出し速度, プレゼン味/煙）に波及。**最も軽い実装**。

### STEP5 アルミ穴あけ（タップ式）★モック重要
円形アルミ上面に穴ガイド（24〜28・HMSで増減）。1つずつ光る→光っている間にタップ。PERFECT/GOOD/NEAR/MISS。残り表示・精度★表示。終了後パターンが結果ビジュアルに残る。操作は「光ったら1ボタン」でも可（座標タップは任意）。

### STEP6 炭焼き判定★モック重要
バックグラウンドで炭が焼ける（右上に小アイコン、各ステップで色が黒→赤→白灰へ）。判定画面で炭3個を表示し「もう少し待つ／ちょうどいい！／裏返す」。5段階（3=ベスト）。色は `Color.lerp(#2a2a2a→#cc3300→#999999)`。裏表の焼きムラでペナルティ。

### STEP7 炭の配置
3個 or 4個。機材と好みに合わせる。熱の土台。

### STEP8 蒸らしタイマー
5〜10分から設定。最適レンジは **特性(steam_bias)＋盛り方** で変動（例: cooling/fruit＋ふわふわ→4-6分、spice/sweet＋しっかり→7-9分）。

### STEP9 思考の暴走弾幕（現状維持）
東方風STG。主人公の迷いの言葉が弾に。ライフ制（基本3）。被弾で吸い出し速度が劣化。グレイズ/コンボ/フォーカス有り。**変更しない**。

### STEP10 吸い出し（現状維持）→提供
ゲージを最適帯（`_pull_target_center/width`）で止める。重い/軽いドローは特性smoke_weight＋盛り方で変わる。複数回で完成（最短ボーナス）。提供でお客の反応。

### STEP11-12 調整フェーズ（炭の世話）★要改修
**数値表示を撤廃**し、煙の様子テキスト（-3「煙がほとんど見えない」〜0「もくもくと白い煙」〜+3「焦げた匂い」）で表現。行動5種: 灰を落とす/炭を回す/炭を交換/HMSフタ調整/終える。「最低2回」撤廃、何もせず終えると自然悪化。各行動後に審査員リアクション。灰落としは小タップアクションにできる。

### STEP13 ラウンド結果
暫定スコア・順位。

### STEP14 プレゼン（手札）★体験の核
工程の選択履歴から手札5〜8枚を自動生成（各手札に味/煙/吸いやすさ/個性の隠し値）。審査員が3回質問→手札を1枚ずつ出す→相性でリアクション（大正解/まあまあ/的外れ/矛盾）。3枚が同軸に揃うと一貫性ボーナス。使用済み手札は再利用不可。レシピ手札は個性に強い。

### STEP15 最終発表
技術点＋観客点で順位確定→ShishaRank表示。

## 4. データ依存（作りに効く外部データ）

### フレーバー特性 → 工程への影響
| 特性 | 効く工程 | 効き方 |
|---|---|---|
| `heat_tolerance` | 温度管理 | 高いほど heat_state の許容幅が広い（減点しにくい） |
| `smoke_weight` | 吸い出し | 重いほどゲージ速度が遅い（重いドロー） |
| `steam_bias` | 蒸らし | +で長め最適、-で短め最適 |
| `category` | プレゼン | 手札名と属性値が変わる（cooling=吸いやすさ寄り 等） |

### 機材 → 作り
ボウル/HMSで練習ボーナス枠・アルミ穴数・相性が変化。キャラ印素焼きは対応フレーバーで加点。

### レシピ → 作り
習得済みレシピの配合（±tolerance）成立で spec/aud ボーナス＋専用プレゼン手札。**未習得だと成立しない**（偶然成立はさせない）。

### 味スコアの3層（確定方針）
デフォルト=補正なし／レシピ成立=加点／NGミックス（手動少数）=減点。カテゴリ自動相性は廃止。

## 5. 採点モデル ⚠️見直し中

二軸（専門点 `_technical_points` / 観客点 `_audience_points`）に各工程の `delta_spec`/`delta_aud` を加算。審査員は4軸（味/煙/吸いやすさ/個性）のうち2つを重視。最後に章別最大値との比率で ShishaRank（SSS〜C）。**式・配点は変更前提**だが、各ミニゲームが `delta_spec`/`delta_aud` を返す契約と審査員嗜好・ランクのI/Oを保てば差し替えは局所で済む（モック段階では各ステップが「±スコアを返す」前提で組めばよい）。

## 6. 練習パート（日常の作り・10ステップ）

`practice.gd`：TUTORIAL表記の10ステップ。配分→詰め方→穴あけ→炭準備→炭配置→蒸らし→（弾幕）→吸い出し→提供。
- チュートリアル配合: `double_apple + mint`（各6g, 在庫50g）。
- **温度ゲージ**: `TEMP_PASS_LINE=0.56` / `TEMP_TOP_LINE=0.78`（status_panelに帯表示）。
- 調整は `ADJUST_TOTAL_ROUNDS=3`。弾幕はライフ3。
- 採点なし→ステータス育成＋装備の練習ボーナスが乗る。
- **新メカニクスの試作はここでやると安全**（採点・順位に影響しないため壊しても被害が小さい）。

## 8. 設計時に決める/守るポイント

- **数値は絶対に出さない**（heat_state等）。煙の様子テキスト・審査員反応・ビジュアルで状態を伝える（調整フェーズの数値表示は違反なので要修正）。
- **採点ロジックは見直し中** → 各ステップは「±スコアを返す部品」として疎結合に作る。
- **ch1フレーバーは検討中**（現6種ベース）。モックは6種前提でOK。
- **大会画風は保留** → モックはプレースホルダ（単色矩形・簡易図形）で構造優先。確定後に差し替え。
- **練習パートで試作 → 大会へ移植**の順が安全。
- ch2〜ch4は同構造の難度違い（穴数増・グロウ短縮・ダブルグロウ/パターン・盛り方派生・テーマ/機材シナジー）。ch1の部品を素直にパラメータ化しておくと展開が楽（計画書「各章への展開」参照）。
