# 泡沢ひより・実装基盤と台本の接続仕様

オーナー依頼による追加ヒロイン。初遭遇はtonari以外のシーシャ店で、元tonariバイトの先輩としてはじめに会う構成がオーナー指定。店名・日時・正式台本・本編への接続は未決のため、現段階では本編へ自動登場させない。長文シナリオはClaude制作予定。
キャラクターの正本は [`data/characters.json`](../data/characters.json) の `hiyori`。年齢・外見・職歴などの事実はそこだけで管理する。

## 現在できること

- 起動時にキャラ・表示確認用台本・未接続のルート定義を読む。名乗る前は既存仕様どおり「？？？」、名乗った後は「ひより」。
- 台詞行の `inner` を表の台詞の後に、小さめの淡いピンク・括弧付きで出す。クリック・Enter・Space・AUTO・SKIP・ログ・長文の改ページに対応。
- 本心は発話・報酬キュー・知識フラグ・演技の崩壊演出として処理しない。主人公が知るのは、表の言葉・表情・行動だけ。
- 既存の好感度、隠し恋愛値、恋人、友人、LIME、私的デートの形式に対応。短い恋人／友人の会話を追加済み。
- イベントを実際に読み終えた後に既存の `flags` と `story.hiyori` へ記録。再読・同時呼出しで二重に報酬を受け取らない。
- 専用ハガルと正式台本が揃うまで締めくくりと告白を起動しない。好感度MAXだけで告白しない。
- 人間関係の画面は面識を得た後だけひよりの行を出す。顔アイコン・立ち絵が無い間は画像URLを作らない。

[`remake/hiyori-preview.html`](../remake/hiyori-preview.html) は本番VNを使う別ページの試写。メモリ上の仮状態だけを使い、本編のセーブや設定を読み書きしない。
5本の短い例は正式な登場シナリオではない。斧投げの背景は未制作のため、他の店を斧投げバーとして代用せず暗い背景で表示する。

## 台詞形式

```json
{
  "speaker": "hiyori",
  "face": "sad",
  "text": "明日のことは、煙に預けて……",
  "inner": "交通費の申請二十件。煙では承認できない"
}
```

`inner` はひよりの通常台詞行だけに置く。他キャラ・制御行・本心だけの行には付けない。
括弧はUIが付ける。既に全角括弧で閉じた文字列も二重括弧にしない。HTMLはエスケープし、装飾タグは既存のものだけを使う。
手動改行なし、表の台詞は全角48字以内、本心も括弧込みで48字以内を目安にする。
長い本心は2行ごとにページを送り、各ページで括弧を閉じる。表の台詞が複数ページなら最後のページの後に本心を出す。
本心の続きのページでは、最後の表の台詞を残す。AUTOの待ち時間は両方の文字数を使い、本心には発話の文字送り音を付けない。
ログは1発言を1件にまとめ、下段に本心を別色で表示する。ログを開いている間は自動送りとキーボード送りを止める。

強弱を付け、全行に本心を付けない。元スタッフの知識、経費精算、通知、食べ物、斧投げ、好意を使った独自の状況を作る。
はじめの返事は、聞こえた言葉や見えた行動だけに対応させる。スミさんがすぐ正体を説明する構成にしない。
特定の動画の台詞・構成・固有のギャグは転用しない。
恋愛の見せ場は、普段は `inner` にあった「好き」「会いたい」「帰りたくない」が初めて `text` になる瞬間。その行に同じ内容の本心を重ねない。

## イベント・フラグ

接続条件の正本は [`data/dialogue/hiyori.json`](../data/dialogue/hiyori.json) の `route`。
`enabled: false` を初期値とし、登場日やマップへの入口はまだ追加していない。
`events[].dialogue` はこれから制作する台本の予約ID。未制作のIDを再生しようとしても、表示サンプルを正式台本の代用にしても発火しない。

| 段階 | 台本の予約ID | 読了フラグ | 条件の骨格 |
|---|---|---|---|
| 出会い | `hiyori_meeting` | `_hiyori_meeting_done` | 第1〜2章。初遭遇はtonari以外のシーシャ店。元バイトの先輩ぶりを見せる。具体的な店・日付は未決 |
| 綻び | `hiyori_cracks` | `_hiyori_cracks_done` | 出会い読了、面識、好感度♥1以上 |
| 斧投げで正体発覚 | `hiyori_axe_reveal` | `_hiyori_real_self_known` | 綻び読了、面識 |
| 素顔と仕事 | `hiyori_work_talk` | `_hiyori_work_talk_done` | 正体発覚読了、面識、好感度♥2以上 |
| 東京からの連絡 | `hiyori_tokyo_contact` | `_hiyori_tokyo_contact_seen` | 第3章、仕事の話読了、連絡先あり |
| 本心が声になる | `hiyori_feelings_spoken` | `_hiyori_feelings_spoken` | 第3章まで、仕事の話読了、恋人の絆Lv2以上 |
| 海外大会への応援 | `hiyori_dubai_support` | `_hiyori_dubai_support_seen` | 第4章、仕事の話読了、連絡先あり。現地同行とは別 |
| 友人として継続 | `hiyori_ch5_friend` | `_hiyori_ch5_friend_seen` | 第5章、仕事の話読了、友情の着地済み |
| 恋人として継続 | `hiyori_ch5_lover` | `_hiyori_ch5_lover_seen` | 第5章、仕事の話読了、恋人 |

これらは順序と接続条件の基盤。好感度の数値、繰り返し交流、具体的な発火日、場所、消費行動数は登場設計と合わせて調整する。
正体が分かっても儚い演技は継続できる。プレイヤーが本心を見たことだけでは `_hiyori_real_self_known` を立てない。

名乗りの瞬間には既存形式の `{ "type": "set_flag", "flag": "_met_hiyori" }` を置く。
連絡先を実際に交換した箇所には `_lime_contact_hiyori` を立てる。後続の章へ移ってもこの面識・連絡先・関係・読了を保持する。
旧セーブの訪問回数や好感度から、これらの出来事を推測して埋めない。

## 既存の恋愛・友人システムとの接続

1. `hiyori_work_talk` の後に `hiyori_bond_question` を接続。選択肢は `id: "bond_q1_hiyori"`、`romance_char: "hiyori"`、各項目に `romance: 1` または `0`。
2. 好感度MAXかつ4本の物語を読了した後に `hiyori_bond_finale`。恋愛が開いているかは既存の `condition_type: "romance_open"`、`char_id: "hiyori"` で分岐する。
3. 締めくくりの最後の選択肢は `bond_q2_hiyori`。途中の質問を実際に回答済みであることも条件にする。専用ハガルは恋愛・友人のどちらにも渡す。ハガルは未決のため `route.finale.gift: null`。実在する `data/equipment.json` のIDを登録するまで締めくくりを無効にする。
4. 告白は既存形式の `confession_hiyori` から `confession_hiyori_accept`／`confession_hiyori_reject` へ `next_id` で分岐。共通 `onDialogueEnter` が恋人または友達の状態を記録する。途中の質問と最後の質問で恋愛を重ねた相手だけ予約する。
5. 恋人の絆は既存の私的デート・LIMEでだけ伸ばす。デートと友人の一服の文面にある `inner` も本番VNへ引き継ぐ。LIMEの文面は実際に送信した言葉なので、プレイヤー専用の本心を混ぜない。

ひよりにも既存の「はじめが想いを伝えるか決める」「既に恋人がいるときの確認」が使われる。
第1章の複数恋人の修羅場は既存3人の組合せ台本のみで、ひよりとの組合せは未制作。対応済みとして報告しない。

正式な入口からは [`daily/hiyori.js`](../remake/js/daily/hiyori.js) の `playHiyoriEvent(eventId)` を明示的に呼ぶ。
`availableHiyoriEvents()`／`hiyoriEventStatus()` は条件確認用。自動カレンダーは起動しない。
行動の体力・費用・日付・場所の移動は呼出し元の責任とし、実際に体力を使う自由行動なら既存の `paidAction` に包む。
締めくくりは既存の `finaleDue("hiyori")`／`playFinale("hiyori")` を使う。

作業中にmainへ入った[第3〜5章の採用方針](post_relationship_gameplay_plan_20261011.md)も照合済み。
遠距離・東京訪問・帰郷後の連絡、海外同行は恋人1人またはなし、友人と親友の判定統一、決着後は真エンディングへ進む方針は確定している。
これらの共通基盤は未実装。ひより固有の休暇・渡航台詞・同行差分は未決で、既存6人の参加条件から自動で推測しない。

### tonariの歴代アルバイトと「帰りたいのに帰れない」物語（オーナー追加確定・2026-10-11）

**確定した関係と動機**

- **tonariでこれまでアルバイトをしたのは、大学時代のひよりと現在のはじめの二人だけ**。スミさんは店長であってアルバイトではない。ひよりは卒業とともに退職し、その後はじめが勤務を始めたため、同僚として勤務期間は重ならない。ほかの先輩アルバイト・同期スタッフ・後任スタッフがいたことにしない。はじめが「元tonariのバイトのひよりさん」に会ったと報告すれば、スミさんは**一発で本人だとわかる**。
- ひよりは**最近の会社勤めに揉まれて疲れている**。大学時代に好きだったシーシャへ久しぶりに戻り、まずは**tonari以外のシーシャ店の客席**で過ごしている。具体的な店舗は実装時に現行マップ・シナリオと整合させて選び、新規店や時系列を勝手に決めない。
- 実は一番顔を出したいのは**古巣のtonari**。スミさんが嫌いだから避けているのではない。元気に働いていた学生の自分を知っているスミさんの前では、今ハマっている**「儚いお姉さん」演技が恥ずかしすぎてできない**。今の疲れた姿をどう見られるかも気になり、入りたいのに躊躇する。避けていることを過度なトラウマや店との絶縁へ膨らませない。
- はじめと別の店で出会い、はじめがtonariで働いていると知ると、ひよりは**自分がtonariの元スタッフ＝はじめの先輩であることを自分から話す**。「……ふふ、じゃあ、君は私の後輩になるのね」と、儚げな年上の先輩を気取る。店の癖やスミさんの教えをよく覚え、詳しさと技術の高さが自然に漏れる。はじめが彼女の元バイトという情報を隠して謎解きする構成にはしない。
- はじめはtonariで「ひよりさんって人に会いました。先輩だって言ってました」とスミさんに話す（ひより本人の言い方なら**「密告」**）。ここでは**秘密を守ると約束した相手を故意に裏切る主人公にしない**。ひよりが具体的に秘密を頼んだ場合は、はじめから事前に話していいか確認するなど、信頼を損なわない導線を優先する。スミさんは名前だけで即理解する。
- スミさんの「自称儚い女」への呆れ、**「セミに生まれたら12月まで鳴いてそう」**という評、学生時代の明るさと確かなシーシャの腕への本当の評価を回想で描く。笑える昔話から、今のひよりの変化を責めずに理解する温かさへ移行する。

**再会の着地点：元店員を、今は一人の客として迎える**

- ひよりは自分の意志でいつかtonariの扉を開ける。はじめが背中を押すことはあっても、**本人を無理やり連れてきたり、先に店で鉢合わせさせたりしない**。以前の「スミさんと遭遇すると無言の愛想笑いになる」は、**この久しぶりの再会で回収できる**。儚い芝居を続ける勇気はなく、会釈してぎこちなく笑うだけ。
- スミさんは珍しがったり「昔みたいに元気になれ」と追及したりしない。**今のひよりをそのまま受け入れ、黙って客席を勧め、飲みたい味を聞く**。かつてはカウンターの内側で作っていた子が、今は客側に腰掛けてシーシャを頼めるという立場の変化を静かに見せる。過去の腕前を認めることと、今働くよう求めないことを両立する。
- 台詞案としては「おう。久しぶり。……今日は客だろ、座れ」「何吸いたい？」程度の短い言葉でいい。ひよりが「……ここ、座っていいんですか」と元スタッフの癖を見せ、気が抜けて小さく笑う。**涙の演説・説明台詞・その場で突然大声で素に戻るギャグは不要**。長い不在の事情を問い詰めず、スミさんの手つきや距離感で優しさを伝える。
- **「ここに帰ってきていい」ことが、ひよりが素でいなければならない条件と結びつかない**。儚い女ごっこが好きな今の姿も、疲れている姿も、大学時代の元気な姿も、同じひより。友情ルート・恋愛ルートに関係なく成立する帰還のエピソードにする。
- ひよりがもう一度tonariで働く、仕事を辞める、シーシャだけで完全回復する、などは**未確定**。会社の疲れや仕事はこの一回の訪問で魔法のように解消しない。後日も客として立ち寄れる居場所ができた、という変化を主眼に置く。

### スミさんへの報告 → 学生時代の回想（オーナー確定の流れ）

1. はじめは**先にtonari以外のシーシャ店で現在のひよりと出会っている**。ひより本人が元tonariスタッフで、はじめの先輩だと告げる。はじめが帰店後に「ひよりさんに会いました。先輩だって言ってました」と報告すると、**tonariでバイト経験があるのはひよりとはじめだけなので、スミさんは即座に理解する**。続けて「あのひよりさん、なんか儚い感じでした」「『私は儚い女だから……』って言ってました」と話し、回想のきっかけになる。
2. スミさんは「儚い女は自分でそんなこと言わねえだろ……」と呆れ、**「あいつが儚い？ セミに生まれたら12月まで鳴いてそうなぐらいしぶといやつだぞ？」**と言う。**この強烈な否定から大学時代の回想へ移る**。大学時代は採用したピンクブラウンのミディアムヘア。学生スタッフのひよりは**明るく元気で、大きく笑い、賑やか**。シーシャを作るのも楽しみ、腕前にも自信がある。スミさんは彼女を「悪いやつじゃない」と評し、**シーシャの腕が良かったことは真面目に認めている**。回想はスミさんの記憶を画面化した演出で、はじめが過去に居合わせた意味にはしない。
3. 現在へ戻り、はじめが「この前の姿と全然違いますね」と驚いても、スミさんは**「まあ、そういう年頃なんだろ」**と片づける。あからさまな自称に呆れてはいるが、ひよりの今の趣味や本心を断定したり、本人に先回りして種明かししたりしない。
4. **ひよりはスミさんに素顔を知られているため、彼の前で『儚い女』ムーブをするのが恥ずかしすぎる**。後日、本人が久しぶりにtonariを訪れると、それまでの物憂げな芝居を止め、**無言の愛想笑い・会釈で切り抜けようとする**。以前の『鉢合わせ』はこの再訪シーンに集約してよい。スミさんは暴露せず、元スタッフに客席を勧めることで歓迎する。可笑しさは抑えめにして、再会の温かさを優先する。
5. この回想と鉢合わせは、**プレイヤーが違和感や事情を察せる**ための演出。はじめはプレイヤーの見た回想や `inner` を超能力的に知るわけではなく、本人の表情・言動とスミさんから実際に聞いた言葉だけで徐々に気づく。既存の斧投げの正体発覚イベントと `_hiyori_real_self_known` の発火条件を、回想だけで前倒ししない。

### 仲良くなっても続く『儚いお姉さん』ごっこ（オーナー確定）

- ひよりは**はじめに「儚いお姉さん」だと思ってほしい**ので、仲良くなって、多少バレバレになっても、自分からやめずに演じ続ける。素顔を知られたら儚いキャラ終了、恋人成立で卒業、という展開には**しない**。演じている姿も本物のひよりの一部であり、単なる虚偽や健康問題ではない。
- はじめの前では、物憂げな短いセリフや意味深な微笑みを頑張って維持する。付き合いが長くなるほど、はじめも薄々察し、優しく乗ったり自然に突っ込んだりする。**毎回「演技だ！」と指摘して潰さない**。はじめにとっては、どちらの姿もひよりの魅力。
- 会社の残業、空腹、疲労、嬉しさ、照れ、食べ物、勝負事などで芝居が小さく綻ぶことはある。ただし、**限界を迎えて素に戻り大声で叫ぶ大爆発は『ごくまれ』な特別の見せ場に限定する**。日常会話・各交流イベント・毎デートに繰り返さない。頻度を数字や毎章1回などのノルマにもしない。普段は心の声、言い間違い、芝居の過剰さ、表情の一瞬の変化などの小さな笑いにとどめる。大爆発時には明るく俗っぽい素の声が出て、本人が慌てて『今のは……魂の叫び……』と取り繕うこともあるが、**希少だからこそ効く演出**として大事に使う。
- スミさんの前だけは例外。素顔を知るスミさんには芝居を見られたくなくて、つい静かに会釈・愛想笑いでごまかす。仲が深まったはじめの前では、バレていても頑張って芝居を続ける。この**相手による態度の差**を守る。
- 本心欄 `inner` はプレイヤー向けの可視化。はじめが心中を読んだような返事をしない。稀に素の叫びが**実際の発言**として出たら、そのときははじめも普通に聞いて反応できる。シリアスな恋愛場面では、演技のギャグに邪魔されず気持ちを自分の言葉で伝える余地を残す。

### 憧れているのは『本物の儚さ』、自分は『儚い女ぶりたい』（オーナー追加決定）

- **性格の核**：『ちいかわ』のモモンガが『かわいく思われたい』と振る舞うように、ひよりは**『儚い女に見られたい』『儚いお姉さんぶりたい』**。参考にするのは承認欲求と、理想像を自分から大げさに演出する構図だけ。既存IPの台詞、口癖、見た目、具体的なエピソードは転用しない。ひより自身の性格・職歴・好きなもの・口調を守る。
- **自然体との対比**：つむぎは寡黙で物静か、ましろは眠そうでおっとりしており、どちらも**儚く見せようとはしていないのに、ひよりの目には自然に儚げに映る**。本人たちが自分を儚い女と認識していたり、病弱・不幸・悲劇的な人物だったりする設定にはしない。特にましろは第3章のmukai所属なので、ひよりとの出会いを第1章へ無理にねじ込まない。
- **ひよりの反応**：つむぎ・ましろを見て、羨ましさと少しの敗北感から**静かに悲しくなる**。例：表向きは儚い微笑み、内心だけ『……なんで、何もしてないのにあんなに儚いの……？』。本人たちを嫌ったり攻撃したり、恋愛の当て馬にしたりしない。優しい羨望や自分へのツッコミにとどめる。毎回比較する必要はない。
- **関係が進んでも続く**：はじめには本物の儚げなお姉さんとして見てもらいたく、演技がバレバレでもやめない。無理をしている姿もその人らしさなので、演技を卒業して素になれば正解という結末にしない。はじめは見抜くことを勝負にせず、ほどよく付き合う。
- **頻度の最優先制約**：普通の会話は儚さの自己演出と内心の落差で成立させる。**本当の素が爆発して大声で叫ぶのは、ごくまれ**。台詞制作担当はギャグとして便利でも頻発させない。下にある叫びのラフは発生頻度の見本ではなく、もし発生するときの例示のみ。

### 検討案：スミさんの回想を境にプレイヤーへ本心表示を解禁（未確定・未実装）

オーナー提案：「このキャラ、スミさんの話を聞いてから本音の声が聞こえるようにしてもいいかも」。**実装を決めたものではなく、演出の有力候補**として記録する。

1. **初対面からスミさんの昔話まで**：ひよりの表の台詞・表情のみを表示し、`inner` はプレイヤーにも出さない。はじめと同じく「本当に儚げなお姉さんなのかも」という第一印象を経験する。演技だとあからさまに示す種明かしを先出ししない。
2. **転換点**：はじめがスミさんに「儚い感じでした」「私は儚い女だからと言っていた」と報告する。スミさんの「儚い女は自分でそんなこと言わない」→「セミに生まれたら12月まで鳴いてそうなくらいしぶとい」→賑やかな学生時代の回想によってプレイヤーのひより観が変わる。
3. **昔話を聞いた後の再会**：初めてプレイヤー向けの本心表示が有効になる。表向きは物憂げな言葉なのに内心はテンション高めというギャップを解禁。**本心はあくまでプレイヤーが読める内心テキスト**であり、実際の音声・読心能力・はじめが聞ける声にしない。はじめの推理や既存の斧投げでの正体発覚フラグと混同しない。
4. **希少性を維持**：本心が見えるようになっても、声を荒らげて素に戻る大爆発はごくまれ。心中のツッコミは毎行付けず、儚い女を演じる努力、小さな綻び、切ない場面を邪魔しない程度に使う。
5. **技術的な未対応**：現行の `remake/js/vn/inner.js` と `engine.js` は、ひより台詞に `inner` があれば最初からプレイヤーへ表示する。正式採用した場合は、**スミさんの回想を実際に読了したことを示す保存フラグ**を設け、再読・SKIP・ロード・会話ログ・プレビューも含めて、その前後で表示を切り替える仕様検討が必要。既存の `_hiyori_real_self_known` を表示解禁フラグとして使わない。過去の台詞ログに遡って心の声が現れるかも要決定。
6. **本編への入口**：現在は `route.enabled: false` で、出会い・昔話・本心解禁はいずれも本編には未接続。具体的な実装、発火日時、フラグ名、演出効果は正式採用後に決める。
