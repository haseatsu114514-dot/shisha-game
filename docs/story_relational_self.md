# 空・縁起・分人を物語に反映する変更

2026-09-30 オーナー依頼。出発点は、シーシャ屋での自分と私生活の自分が違うことや、強み・個性を言えないことで「本当の自分がない」と苦しむ人への答え。

着地は、誰にも影響されない核を証明しなくてもよいこと。人との出会い、場所、価値観が混ざった今の自分で、既に自分。休んだり、変わったり、関係から離れたりする自由もある。

## 選んだ交流が主人公へ戻る仕組み

正本は `data/relationship_memories.json`。各記憶は `id`、`char_id`、`dialogue_id`、短い内心の `echo` を持つ。

```json
{ "type": "remember", "memory_id": "naru_hands" }
```

会話のこの行まで到達すると、`state.relationshipMemories` にIDを残す。訪問回数や好感度の上昇だけでは残さない。再読しても同じIDは増えない。選択肢の分岐に入れた場合も、実際に選んだ側だけが残る。

```json
{ "type": "reflection" }
```

この行で、直近の記憶から相手ごとに一つ、最大三人分を内心へ返す。同じ相手なら最後に読んだ記憶を使う。一人だけと交流したプレイにも、その一人の時間を返す。記憶がなければ今の一台へ目を向ける一文を出す。

第1章の折り返しの制作、第1章大会前夜、第2章大会前夜に接続済み。第5章の二本目前にも同じ命令を置いてある。知識ノートや図鑑と別にし、集めた数やコンプリート率を表示しない。記憶自体と振り返りにはステータス・好感度・大会点の加算がない。各訪問の従来の報酬は続く。

旧セーブに配列がない場合は空で開始する。過去の訪問から新しい台詞を読んだと推測しない。章を進めても記憶は消さず、セーブに保存する。

## つむぎの順序と主題

設定の正本は `data/characters.json` の `tsumugi.art_sns`。フォロワー数はビルドで `D.character_facts` に取り込み、台詞の `{tsumugiFollowers}` を表示時に置換する。

先に不思議な生き物の絵を見て、眠そうな顔などを好きになる。親しくなった訪問3回目で本人が投稿画面を開き、SNSの規模が分かる。数字で魅力を格上げせず、つむぎは以前と同じように絵の顔について話してほしいと頼む。

つむぎは、自分も絵も集合として既に受け入れている。中心の絵は、葉っぱの耳と煙の尾を持つ猫。友達の木、以前飼っていた猫の寝方、好きだった絵の線、tonariの煙が混ざった一匹。葉がない日の姿もそのまま描く。苔の羽の鳥や角に森のある鹿も、見てきたものが残った絵。

先輩に怒られた経験や話す慎重さは続くが、自分に心がないと信じたり、SNSの支持で個性を証明しようとしたりはしない。主人公が心や自己肯定を与える救済者にならず、つむぎの「どれも私が見てきたものなので」という自然な受け入れ方に主人公が触れる。

共感覚の色はその時の彼女の受け取り方。変わる色を偽物・人格喪失の判定に使わない。煙の線と相手の硬い声を見て、水や休む時間を差し出す。

## 誤って戻さない点

- 人の技を借りたことが衝突の原因ではない。なるとの衝突は、話を遮って点や勝利で相手を扱った行動。
- 空を「欠落した人だけの吸収の才能」に変えない。普通の育ち、名づけられない個性、混ざった興味は初めから有効。
- 居場所は回復・勝利より前。恋人やSNSの支持がないと救われない構造にしない。
- AIも人や環境からできる。今日の関係で落ち着く→観察→待つ・炭を動かす→煙、を描く。この9000の記録とセンサーの範囲で再現できなかった一戦であり、AI一般の不可能性にしない。
- 第4章の決勝は和風の一台。第5章の双方ダブルアップル12g・二本勝負・採点UI非表示は継続。

## 確認

`web/test/relationship_memories.mjs` で、第1・2章の10訪問先を各一人だけ選ぶ場合、未選択分岐、再読、複数交流の振り返り、恋人なし、SNS表示、セーブ再開、旧セーブを確認する。振り返りで能力値や好感度が増えないことも検査する。

変更後は台詞リンタ・旧語チェック・人物と話者チェック、データと配布HTMLのビルド、既存の `playthrough.mjs` → `ch2.mjs` → `screenshots.mjs` を直列で実行する。

2026-10-01確認結果: 両ビルド成功。台詞リンタはERROR 0、既存WARN 191、新規WARN 0。旧語・人物・話者のチェックも通過。交流のテスト、第1章通し、第2章通し、敗北からの再挑戦はいずれも成功。つむぎを集合として受け入れる役・猫の絵へ改稿した後に、交流のテストと第1章通しを再実行して成功した。第3章以降は台詞データの構造と設定を検査し、実プレイの完走は未接続のため対象外。
