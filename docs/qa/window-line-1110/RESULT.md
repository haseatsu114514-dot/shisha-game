**16:04の実機画像は、#3108 の修正がまだ公開されていない状態と整合する。現行 main では追加のレイアウト不具合を再現しなかった。** 本PRは再発検査と検証記録を追加する。CSS・枠画像・台詞・シナリオは変更しない。

- 起点 main: `23710f0200d41159dcd099ca7da80571fc0c9bf5`。新規ブランチ `codex/window-line-1110`。既存repoのオブジェクトを利用する sparse worktree。
- #3108 は `ea81e2ec19c446383d35bf4382cdd1f476cc6c81` として15:42 JSTにマージ済み。しかし16:08 JSTのキャッシュ回避取得でも、公開 `build.json` は `f5dd257`（15:11公開）。`ui-paper.css` は #3108 前の内容だった。

## 原因と3層の基準

元画像 `remake/img/ui/paper/dialogue.webp` は2464×384px、SHA-256 `899628e8286ac4b4d7b089d8ebb98989d09856b5fd43ffef91181a403ac9e55e`。公開版とmainで同一。中央xの罫線の濃い芯は原画y=104–106。表示は横1232×縦192ステージpx、background-positionはcenter、background-sizeは100% 100%。

`.vn-box` の上端を B とすると:

- 枠画像は上下8px張り出し、画像上端は **B−8**。
- 焼き込み罫線は **B−8 + 192×[104,107)/384 = B+[44,45.5)**。
- 本文の行ボックス開始は **B+44**。フォントの空白部分は罫線と同じ高さになるが、実際の字面はさらに約10px下から始まる。
- PCのBは530。スマホは `B=720−max(30,(safeBottom+8)/k)−176+2`。最後の+2は枠と操作列が共有するtranslate。
- 旧公開CSSでは、本文枠だけが安全領域を含む下端を使い、操作列の `--vn-dialogue-bottom` は16px。枠だけが持ち上がる一方、操作文字・区切り線が罫線付近に残る。下端21pxの852×393、932×430、780×301、780×361で再現。安全領域0では再現しない。
- #3108 後は紙テーマの `#stage` が安全領域込みの `--vn-dialogue-bottom` を操作列へ渡す。スマホ用の大きいタップ領域は上へ伸ばし、ラベルと縦線を下端基準へ揃える。枠と本文は元から同じ `.vn-box` 基準。8pxの張り出し・背景の中央配置・本文44pxには追加のずれを認めない。

従って、再現条件が成立する場合にだけ追加修正する、という依頼に従い、新たな寸法変更は行わない。PCの正しい配置は本PRで変化しない。画像編集も不要。

## 実画面と測定方法

Playwright 1.62.1 / Chromiumで本編を起動し、実際の `ch1_cold_open`、同じ `mountColdOpen()`、同梱フォントと画像を表示。安全領域はCDPの `Emulation.setSafeAreaInsetsOverride` で設定。全行が表示され、必要な2書体の読込が完了してから撮影。DPRごとに新しいBrowserContextを作り、PNGのピクセル幅も `CSS幅×DPR` と照合した。

旧版は調査開始時に公開サーバーから取得した紙CSSを、同じ本編のCSSリクエストへ返して比較した。枠画像・phone-density.css・vn-lounge.cssは旧公開版とmainでハッシュ一致。旧版の実URLを直接再生する試みは、調査中の公開切替で `js-f5dd257/` が404になったため完了しなかった。この比較は保存した公開CSSの再現であり、旧公開URLを実機操作したものではない。

数値はすべて1280×720ステージ上のY座標。DOM Range（字面の外側の空白を含む）と、実PNGの字面を区別した。PNGは通常表示と文字色だけを透明にした表示の差分から字面を採取（RGB差>30、同じ行に2画素以上）。本文は操作列と重ならない左側の文字領域を使い、旧版のAUTOを本文として数えない。生のDOM矩形、全5ラベル、区切り線、測定範囲はJSONに記録。ラスタ化の丸めにより約1画像pxの誤差がある。

## 回帰検査の変更

`remake/test/browser/conversation_ui.mjs` の既存ケースを拡張。旧チェックの「box.top+45」という推定だけに頼らず、読み込んだ実画像の罫線をCanvasで検出する。本文はDOMにゼロ寸法のbaselineマーカーを一時的に置き、Canvasの実グリフascentから字面上端を求める。本文の字面、操作ラベル、縦の区切り線、タップ領域を別々に判定する。

DPR3、852×393／932×430、下端21px＋左右47px、従来の844×390／844×340／780×301・下端34px・1280×720を含む10条件×3場面。正しい第1章冒頭に加えて第5章の2行も検査する。既存のタップ高・本文内包・操作との非交差・衣装検査は削らない。`ui_themes` と `phone_density` の既存期待値は別PR #3107 の領域なので変更しない。
