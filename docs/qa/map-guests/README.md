2026-10-15。基準main: e489bd8e。検証コミットはPRのheadを参照。

店主と実際に会えるゲストを同じ看板の上辺へ並べる。未面識のゲストは共通の人影と「見知らぬ客」だけを表示し、名前・画像URL・DOM属性にも正体を出さない。店が休業・未解禁・利用不能の場合は表示しない。つむぎは現行の客席訪問に合わせて昼夜ともtonariにいる。

オーナー確認により、ひよりの初対面を「最初に入った対象店」から、時間帯ごとの一つの滞在先へ変更。同じseed・章・日・枠・営業/解禁状態なら同じ店になり、地図表示と来店処理で同じ判定を使う。再会は既存の20%条件に当たる営業中の候補から一つだけ選ぶ。受諾済みLIMEは当日の指定枠・指定店を優先。tonariで本人に会うイベントがある時は他店へ重複表示しない。伝言をスミさんに報告するだけの場合、ひより本人の在店とは扱わない。

## 将来のゲスト設計（方針のみ）

オーナーの追加方針: 店主の好感度イベント完了を基本の登場きっかけとし、tonariのバイトや他店への出入りで出会う。継続して好感度を深める人物と、情報だけをくれる人物を区別する。

`spot-people.js`のゲスト一覧は人物ごとに独立した在店条件を持つ。将来は店主の正式イベント読了、当日の予定/時間帯、営業状態を条件に加える。好感度の数値だけから読了を推定しない。表示側は会話の既読・好感度・報酬を更新しない。情報だけの人物に親密度/連絡先/恋愛ルートを自動作成しない。新人物・新台本・閾値・報酬は今回追加していない。
