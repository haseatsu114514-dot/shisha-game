# 全22キャラ・100表情の目と顎の点検

通常だけでなく、現行manifestの全表情を目視した。キャラ名・表情・素材PNG・配信用WebP・切り出し座標は [比較ビューアー](../index.html) と [catalog.json](../catalog.json)、各表情の理由・優先度・確認時のSHA-256は [findings.json](findings.json)。以前の「みんと・あげは以外を一律に正常とする仮分類」は廃止した。

## 修正と残る候補

|---|---|

| あげは `sad` | 描かれた顎の濃い線・明るい縁。全身再描画v1をローカル反映 |
| みんと `smile` | 正面化したv1は不採用。元の傾いた顔・笑顔を保持するため元画像へ復元 |

| みんと 上記以外の8表情 | 顎線の濃さは経過確認。半目・ウインクを一律に開かない |

## 比較と根拠

みんとsmileの前回の高優先判定は撤回。目の軸の傾きを考慮した再確認では、画面右の虹彩・ハイライト・白目が読め、明確な眼の潰れとは判断しない。正面化で顔向き・頬・顎・口の角度を変えたことが過剰修正だった。元画像を維持する。

- `faces-001-005.webp` から `faces-096-100.webp` は**先行修正前**の全表情。白・灰・暗背景で、顔の拡大表示と50%を比較（顔の大きいパッキー・前園は枠に収まる縮尺）。原寸はビューアーで確認できる。修正前の識別は `technical-check.json` のSHA-256を使う。
- 100枚中97枚は素材PNGとWebPが全RGBA一致。残るサイ・マキ・占い師の3枚は非可逆変換による色差で、αは全て一致。[PNG/WebP比較](lossy-png-webp.png)でも目・顎の形状の破綻は見つからなかった。
- みんと・あげはの問題は元絵の描画にある。顎と首はほぼ不透明で、背景色を変えても線が残る。CSSが線を追加する処理もない。縮小では太い上まぶたが詰まって見えるが、縮小時だけ生じる目の左右差ではない。今回、透過由来の黒縁・縮小時だけの破綻と特定した例はない。
- ましろ `normal` は顎付近のα253、明るい縁RGB `[255,250,238]` と濃い線 `[65,34,30]` が隣接。透過縁ではない。`surprise` は茶色寄りで細く、別AIも現状許容と判定。
- ひより `normal / sad / smile` とサメちゃん `normal` の半目は両眼に共通。別AIの限定確認でも機械的な修正は不要。閉眼、眼鏡の発光、渦巻き目、髭、しわ、チョーカー、自然な首の影は不具合に含めない。
- 実VNでは、先行2キャラ全15表情をPC1280×720・スマホ844×390で切り替え確認。その他80表情もスマホ寸法で確認し、ゲームの実際の縮尺で顔を記録。主人公はじめの5表情はVNが意図して非表示にするため、素材の背景・縮尺比較で点検した。最初の自動確認はこの非表示仕様でtimeoutしたため、対象を表示可能なキャラへ修正した。結果・実画面は [runtime-review](../runtime-review/)、確認コードは [check-runtime.cjs](../check-runtime.cjs)。

「異常なし」はこの比較で明確な破綻を見つけなかったという目視判定であり、ユーザーの好みまで保証するものではない。黒い線の一括削除・全キャラ再生成は行っていない。

`build_catalog.py` は画像のSHA-256と個別記録が一致する場合だけ判定を表示し、記録のない画像は「未確認」にする。`build_audit.py` を再実行すると現在の素材で監査シートが更新されるため、この修正前スナップショットを履歴と混同しない。
