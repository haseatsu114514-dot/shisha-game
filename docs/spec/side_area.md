# 左右の余白の活用（YHK）

2026-11-11 オーナー決定。提案6案（台帳 YHK01〜06）から「ボタンがあるやつ・日にちとかの」を採用。条件は「スマホによって見えづらくても困るので、主流なスマホに合わせる」。

実装: `remake/js/core/side-area.js`・`remake/css/side-area.css`。検査: `remake/test/side_area.mjs`・`remake/test/browser/side_area.mjs`。

## 変えないこと

- 画面方針（#3035）はそのまま。ステージは固定 1280×720、余った所は場面背景のぼかし（`#backdrop`）。
- ステージの中の配置は動かさない。余白の層はステージの外（`#viewport` の中・`#stage` の隣）に左右1枚ずつ置く。
- 余白が無い画面（16:9）、上下に余る画面（iPad）では何も出さない。

## 出す物と、余白の幅の段

余白の幅はステージ上の px（片側）。`<html data-side>` に段が入る。

| 段 | 余白 | 例 | 出す物 |
|---|---|---|---|
| `off` | 20px 未満 | 16:9・iPad | なし |
| `narrow` | 20〜59px | | A 煙と縁 |
| `mid` | 60〜117px | 18:9（80px） | A＋B 縦書きの帯 |
| `wide` | 118px 以上 | 19:9（120px）・iPhone 19.5:9（140px）・20:9（160px） | A＋B＋C 親指ボタン |

- **A 煙と縁**: ぼかしの上に、外へ向かって暗くなる面・ゆっくり上へ流れる煙・ステージの端の細い線と影。動かすのは `transform` だけ。設定「揺れ・閃光を減らす」と端末の「動きを減らす」では流さない。
- **B 縦書きの帯**: 左の余白の上から1列で、章・街・日付と時間帯（例: 第一章／橙須／五日目・夜）。章と日付はセーブ一覧と同じ読み方、街は HUD の札と同じ（`currentCity`）。タイトル・スタッフロール・章の読み込み中などは出さない。店の名前は出さない（まだ知らない店の名前を見せないため）。
- **C 親指ボタン**: タッチ端末（`pointer: coarse`）で `wide` の時だけ。会話は左下に SKIP・LOG、右下に AUTO・「次へ」、右上に用語・設定。地図は右上に LIME・MENU。出している間、ステージの中の同じボタンは CSS で隠す（用語・設定も含む）。`<html data-side-pad="on">`。

## 置き場所の決まり（主流のスマホに合わせる）

対象は iPhone 13 以降（ノッチ・Dynamic Island）と、20:9 前後の Android。

- カメラの切り欠きは片側の真ん中（縦の 3〜7 割・外側寄り）に来る。どちら側かは持ち方で変わるので、左右とも真ん中にボタンを置かない。
- 帯はステージの端から 50px 以内の1列に収める（どの切り欠きよりも内側なので、下へ伸びても隠れない）。
- ボタンは 88px（iPhone で実寸 約48px）。端から 22px・間 12px で2つ重ねる（2つで縦の 29.2%）。
- 字は実寸 11.5px（日付は 12.5px）を下回らないよう、`--k` で割った値を下限にする（スマホ規格 `phone-density.css` と同じ考え方）。
- 切り欠きが縦に長い古い iPhone（X〜12）では、切り欠きの側だけ内側のボタンの外の縁が少し隠れる。

## 親指ボタンの作り

- 余白のボタンは、ステージの中の元のボタン（`.vn-ctl`・`.hud-lime`・`.hud-menu`）を代わりに押すだけ。処理は元のボタンのものをそのまま使う。「次へ」だけは `vn/engine.js` の `tapAdvance`（会話の面を押した時と同じ送り）。
- 元のボタンが押せない間（モーダル・LOG・LIME・演出が上に重なっている、会話中で HUD が止まっている等）は、余白のボタンを下げる。押す瞬間にも同じ当たり判定（`elementFromPoint`）で確かめ、押せない時は何もしない。
- 未読の数（LIME）・未使用の火種の数と増えた物の合図（MENU）・AUTO／SKIP の入り切りは、元のボタンから写す。
- 余白へ出している間は、会話欄の上へ伸びる操作札（`--phone-tap`）の分を空けず、選択肢を PC と同じ高さ（3択以上は会話欄の上 62px、2択は 94px）へ下げる（YHK14。新版は帯のすぐ上に自分で置く）。

## 試遊ページ（2026-11-13 の点検で追加）

共通の画面当て（`core/stage-fit.js`）を使う単体ページには、本編と同じ A 煙と縁を出す（`initSideArea({ stage, standalone: true })`）。ゲームの状態・会話・HUD が無いので、B 縦書きの帯と C 親指ボタンは出さない。

- 対象（7ページ）: `camel-race.html`・`axe-throw.html`・`desert-ride.html`・`ichidai.html`・`trpg-preview.html`・`trpg-campaign-preview.html`・`craft-preview.html`。各ページが `css/side-area.css` を読み、起動スクリプトから呼ぶ。
- 本編の設定を読む: 本編の起動（`main.js`）を通らないので、端末に保存した「左右の余白」（ぼかしだけ）と「揺れ・閃光を減らす」（煙を止める）を `localStorage` から直接読む。
- 制作の試遊ページ（`craft-preview.html`）は舞台が上のナビの下の `#viewport` に収まる。余白はその枠の左右に取る（1280×720 の窓でも、ナビのぶん舞台が縮み、左右に約46pxの余白ができて A が出る）。
- 対象外: 画面当てが別実装の開発用プレビュー（`conversation-preview.html`・`chapter2-preview.html`・`opening-preview.html` など。余白のぼかしも無い）。

## 切り替え

- 設定「左右の余白」: 「帯とボタン」（既定・`config.sideArea = "full"`）／「ぼかしだけ」（`"plain"`。これまでどおり）。
- DS風（`data-look="retro"`）では出さない（自前の操作の面を持ち、ぼかし・グラデーションを使わない様式のため）。
- 自動操作のブラウザ（`navigator.webdriver`）は、既定で C を出さない。既存のブラウザ検査がステージの中のボタンを押し、寸法を測っているため（見た目の様式の既定 `core/look.js`・LK09 と同じ線引き）。C の検査は `localStorage` の `suien_side_pad` を `"on"` にして明示する。`"off"` で遊ぶ端末でも止められる。

## まだやっていないこと

- 実機での確認（持っているだけで触れる誤タップ、切り欠きの側の押しやすさ、Android の端からのスワイプとの相性）。合わなければ設定で「ぼかしだけ」に戻せる。
- 余白のどこを押しても「次へ」にする案、思い出の壁・着せ替え枠・黒と細い線（YHK04）は入れていない。
- 会話と地図以外の画面（ショップ・シーシャ作り・ミニゲーム）のボタンは余白へ出していない。
- DS風（`data-look="retro"`）では余白の層を出さない（自前の操作の面を持つため）。この環境では DS風の画像が足りず見た目を確かめられていない。
