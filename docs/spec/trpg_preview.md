### 本編での本棚と招集

- 第2章から、バーの店員に提案されて部活を作ります。サメちゃんは設立のきっかけ役ではなく、後から誘う仲間です。
- 知り合いの好感度MAX（恋人は絆Lv1でも可）で、興味がある人を対面で勧誘できます。現行はひより・サメちゃん・アダム・つむぎ・クラウド・あげは（クラウド・あげはは第2章の隣町の店で会った後）。興味はcatalog、提案と承諾の台詞は `data/dialogue/trpg_club.json` で管理します。
- 「今日は誘わない」や途中退出では未入部。本人の承諾を最後まで読んだら入部し、以降は招集対象になります。訪問そのものの料金・行動枠に、勧誘の追加料金や枠はありません。
- 必須キャラが入部すると本が入荷。MAXだけでは入部・入荷・招集を自動解放しません。
- 初期価格は普通の一台500円／サメ映画800円。購入だけでは時間や体力を消費しません。価格と条件はcatalogで変更できます。
- 今夜の参加者は入部済み・シフトや予定なし・その配役に対応する候補から選びます。スミさん・なるは不参加です。
- 普通の一台のGMはひより、サメ映画のGMはサメちゃん。はじめは参加必須。空いているアダム・ひより・つむぎが任意枠に入ります。
- 必須の部員と、はじめがいれば成立。空いたPL席はサイの店の常連が手伝います。サメ映画では、ひよりが来られない時に入部済みのアダムを優先し、その後に常連を招集します。台詞と役紹介は本人用のものを使います。
- 昼や既存の夜の予定がある時は招集できません。買った本・入荷済みの本は、参加者の仕事の日にも棚に残ります。
- 結末・振り返り・後日談を最後まで読んだ時に、成否を問わずクリア。参加者・GM・日付・結末・提案を保存し、夜の1枠を同時に消費します。
- **クリアした本はもう一度遊べる**（TMX14・2026-11-11 オーナー決定「行動も推奨」）。遊ぶと夜の1枠を使う。記録は良い方を残す（星が多い方、同じなら盛り上がりが高い方）。`cleared[id].endingsSeen`（見た結末）と `plays`（遊んだ回数）を足し、本の札に「見た結末 2 / 4 · 3回遊んだ」と出す。
- 中断・通信失敗・画面撤去ではクリアや行動消費を記録しません。購入した本は保持します。
- **しおり**（TMX13・2026-11-11 オーナー決定「しおりは推奨で」）: 卓の途中は、場面の区切り（判定や会話が終わって操作を待つ時）ごとに `trpg.bookmark` へ自動で残る。中身は「押した順番」と seed・配役・役（画面ではない）で、同じ順番を同じ seed で押し直すと出目まで同じ場面に戻る。夜の行動もお金も使わない。次に店へ入ると、その本に「しおり：店内を調べる」と「続きから遊ぶ」「最初から」が出る。今夜の顔ぶれが違う時・物語の版が変わった時は「最初から」だけ。しおりは同時に1つで、読み終えると消える。卓の会話ログは続きからでは引き継がない。
- 好感度・恋人の絆・能力・体力・制作報酬は増減しません。記録がこの行動の思い出になります。

`trpg.bookmark` は `{id, version, chapter, day, seed, assignments, pc, actions, phase, title}`。形が崩れたしおりは読み込み時に捨てる（`core/state.js`）。
保存スキーマ15の `trpg.club` は `{founded:{chapter,day}|null, members:{[id]:{chapter,day}}}`。
設立と入部は実際の操作だけで記録し、旧セーブのMAXやクリア参加者から補いません。スキーマ14以前の入荷・購入・結末・シフトは保持します。
勧誘中のセーブ切替・画面撤去・ページ離脱は未入部で終了。通常訪問側が入部とその行動を一緒に保存します。

週間予定は `data/trpg_catalog.json` の `participants[].shifts`。既存には全員のシフト管理がないため、TRPG招集用の初期予定を登録しています。
ひよりは昼の仕事、つむぎは昼の制作、アダムは定休日以外のシフト、サメちゃんはDAY剰余3・5を休みとして設定しています。
これは全店舗の正史営業時間を変更するものではなく、今後の章で当日のシフトを `state.trpg.shifts` の
`{id, chapter, day, slot, busy, reason?}` で上書きできます。臨時休業と当日予約も参照し、上書きのシフトを優先します。
将来の遠隔地参加は、その章の参加者データで場所と登場条件を追加する必要があります。

試遊は `http://127.0.0.1:8123/remake/index.html?trial=trpg` を開く。物語だけを出目を固定して確かめる時は、検査用のページ `http://127.0.0.1:8123/remake/trpg-preview.html?harness=1&scenario=ordinary-cup&seed=54`。

### 卓の再構成: キャラクターシート・行動宣言・GMの裁定（2026-11-01）

オーナー「よりリアルなTRPGをしているようなゲーム性と再現性に。デザインからゲーム性まで見直して再構成」。短編2本の物語・調査地点・見立て・提案で決まる結末・料金・行動消費・保存形式は維持し、卓の遊び方を「実際のセッション」の形にした。

- **キャラクターシート**: 各PLが演じるPC（通常編: フィン・ニコ・ルカ／サメ編: レン・オット・セラ）に 観察・手際・話術・度胸 の4能力値（1〜5）と特徴、切り札を持たせた。`cast[].sheet`。座席バーにPC名と能力値、道具の「キャラクターシート」で全員分を読める。
- **行動宣言**: 3つの判定場面（話を聞く／一台を用意する／提供する・脱出する）で、サイコロを振る前に「誰が・どの能力で・何をするか」を3択から宣言する（`checks[].approaches`）。宣言するとPLがその行動を口にし、GMが「○○で判定。目標は30」と裁定する台詞（`trpg_*_declare_*`）が流れてから判定へ進む。
- **能力値が補正**: 判定は 2d20 ＋ 宣言したPCの能力値（従来の一律＋3を置き換え）。切り札（＋7・連携札1枚）、見立て（サメ編＋4）、勢い（＋4）は従来どおり重なる。見通しの確率も宣言した能力で計算する。
- **役の見せ場**: PLのPCが初めて前に出ると盛り上がり＋1（各1回）。**はじめ自身のPCも対象**（2026-11-12・TRF12。それまでは仲間のPCだけで、はじめ自身の行動は加点なしだった）。GMが兼任する空席のPCは対象外。
- **空席の兼任**: 来られなかった部員のPCはGMが演じる（宣言カードに「GM ○○ が演じる」）。シートは残り、能力値も同じ。代役（サメ編のアダム）は本人用の宣言台詞（`variants.adam`）で話す。
- **振り返り**: 各判定に「誰のPCが・どの行動で・能力いくつ」を残す。`result().checks[].approach/actor/sheet/stat/base` と `result().acted`。本棚の保存項目は変えていない。
- 既定の宣言（APIで `approach` を省略した場合）は一覧の先頭＝はじめのPC。純関数の既存テストはこの既定で動く。

PCの顔は、はじめも仲間も**その役を演じる本人の立ち絵**を丸窓に入れる（#3050、オーナー決定 2026-11-10「仲間キャラにも同じルールを」）。役ごとの似顔絵（`pc-*.webp`）と見た目の絵（`look-*.webp`）、その原画・指示書（`asset_sources/trpg-sheets/`）・切り出しツールは使わなくなったので削除した。シートに `portrait`／`color` は書かない（`validate_trpg_scenario.mjs` が検査し、古いデータに残っていてもセッションが捨てる）。「本人の顔＋役のコスプレ」の差分絵は試作中で、採用が決まってから組み込み先を決める。

### 判定に賭けるもの・20の目のクリティカル・卓の掛け合い（2026-11-11・TRF）

オーナー「TRPGのミニゲームを、さらにTRPGしてる感を強めたい。ゲームとして欠けている部分・つまらない所を直したい。やったことがない人にも、慣れている人にも楽しめる質に」。1卓を通して遊び、新旧の規則を4.5万卓ずつ回して比べた（下の表）。物語・台詞の本数・結末の決まり方（提案が結末を決める）・料金・行動消費・保存の形は変えていない。

見つけた弱点は3つ。①サイコロに賭けるものが無い（どの出目でも同じ場面へ進み、画面にも「結果にかかわらず進みます」と出ていた。4回とも「ひと手間」の卓は何も起きない）。②クリティカルとファンブルが起きない（20ゾロ・1ゾロは各 1/400。100卓に1回で、専用の掛け合いをほぼ誰も見ない）。③当時のスミさんGM卓には、出目の掛け合いが1つも無かった。

- **20の目はクリティカル、必ず成功**（TRF01）: 2個のうちどちらかが20なら、合計にかかわらず成功。連携札が1枚戻り（上限2枚）、盛り上がり＋2（頻度が上がったので＋3から下げた）。振り直しは出さない。**1の目が出て「思わぬ出来事」になった判定はファンブル**（盛り上がり＋2。1が出ても合計が19以上なら、ふつうの「ひと手間」）。20と1が同時なら20が勝つ。そのほかのゾロ目は従来どおり歓声（＋1）。見通しの確率・振り直しの見込みも同じ決まりで数える（`session.js` の `outcomeOf`）。
- **成功のごほうび**（TRF02）: 判定の前（宣言の画面と判定の卓）に「成功で ○○」の短い札（質問 ＋1／GMのヒント／会心の印）を出し、GMの裁定として賭けるものを先に見せる。失敗しても、ごほうびが無いだけで物語は進む。
  - 最初の判定（話を聞く）: **聞き込みで聞けることが1つ増える**（2 → 3。`interviewPicks()`）。案内文の「二つまで」は、その夜だけ「三つまで」と読み替える。
  - 思わぬ展開の判定: **GMのヒント**。次の準備の2項目で、今夜の事情に合わない選択肢に1つずつ「✕ 合わなそう」の付箋が付く。
  - 準備の判定: **GMのヒント**。最後の選択で、合わない選択肢に1つ付箋が付く。
  - 最後の判定: **会心のクライマックス**。結末の画面と振り返りに印が付く（`result().finale`）。盛り上がりは足さない（最後の判定の時点でメーターはほぼ上まで来ている）。
  - ヒントの付いた選択肢も選べる（助言で、鍵ではない）。どれに付くかは seed から別ハッシュで決め、サイコロの並びは変えない。隠れた事情が好む選択肢には付けない（`hintFor`）。結末は従来どおり提案だけで決まるので、**出目は「手がかり」を通して結末に効く**。
- **あと1・あと2**（TRF03）: 成功に1〜2足りない「ひと手間」は、合計の横に「あと1……！」と出し、GMとはじめの掛け合いが流れる（`result.near`）。

### 部のランクと成長点（2026-11-12・TRF13）

「おまかせ」で進めた2つめ。**卓を重ねるほど「煙とサイコロ部」が育ち、はじめの役が少し強くなる**。物語の台詞・結末の決まり方・料金・夜の行動は変えない。

### 役の絵: 札は同じ地の色・同じ拡大率、暗い場面では「紙のコマ」（2026-11-13・TRF26・TRF27）

オーナー「難しければみんな背景を特定の色にしていいかも」「顔アイコンとかキャラシとかで使う時は背景を白とかで統一すると切り抜きの雑さ目立たないかも」「キャラの拡大率とかなんか統一感がまだない。アイコンにした時とか並べた時に」「抜けすぎてしまってるのが経過を見てるとある」。

- **セッションゼロ**: 「物語をはじめる」のあと、GMの「キャラ作りの時間」から、仲間が順に自分の役を紹介し、はじめが「俺は{pc}。{pcTitle}でいく」で締めてから本編へ（`sessionZero`）。空席の役はGMが兼任し、紹介はしない。
- PC名は台詞・役名・宣言の説明ですべてトークン化した（`{pc}` はじめの役、`{pc:席}` 仲間の役、`{pcTitle}`、`{gm}`）。シートに「好きなもの」を表示。
- **初心者向けのキャラ作成**: 既定は「かんたん」。役どころを選ぶだけで名前と能力値が決まる。各能力に平易な説明と「この物語では○○の場面で使う」を表示。1つ目の役どころに「はじめてならこれ」。点の振り分けは「能力を自分で振る（慣れてきたら）」を押したときだけ出る。
- **宣言の「おすすめ」**: いちばん成功しやすい行動のカードに「おすすめ · いちばん成功しやすい」。遊び方に GM・PL・PC・判定 の用語集。
- **店長（六角サイ）のチュートリアル**（`data/dialogue/trpg_tutorial.json`、catalog の `tutorial`）: 表紙の上で、TRPGとは／GMとPL／PCとキャラクターシート／どうする？と宣言／2d20＋能力値で30以上／失敗しても続く／役を作ろう、の15行を図解パネル（`panel`）つきで話す。本編では最初の物語を読み終えるまで卓を開くたびに自動で流れ（`flags._trpg_tutorial_seen` を読了と同時に保存）、表紙の「はじめての人へ」でいつでも見直せる。独立プレビューは `?tutorial=1` で自動再生。

### キャラクター作成（2026-11-01）

オーナー「キャラクターシート作りみたいな要素。何通りかの見た目やキャラやステ振り」。表紙の「キャラクターを作る」で、はじめが演じるPCを決める（`scenario.builder`）。

- **見た目**: 選ばない（#3050、オーナー決定 2026-11-09）。PC の顔は演じる本人（はじめ）の立ち絵で固定する。`builder.looks` と `look-*.webp` は削除した（2026-11-10）。名前・出自・能力値のキャラメイクは従来どおり。
- **出自**: 3種（`builder.archetypes`）。例の名前・肩書き・特徴・能力値の初期配分（合計11点）。通常編: 見習い店番（フィン）／船乗り帰りの手伝い（マル）／本好きの常連（テオ）。サメ編: 新人甲板員（レン）／元ライフセーバー（ナギ）／無線係の見習い（ハル）。
- **名前**: 選ばない（オーナー決定 2026-11-10・TMX02）。役どころごとに決まった名前（フィン・マル・テオ…）で始まり、入力欄はない。台詞・宣言カード・役名の `{pc}` にその名前が入る（`view.js` の `pcText`）。`buildPc` の `name` 引数と6文字の検査は残している。
- **ステ振り**: 観察・手際・話術・度胸を各1〜5、合計11点以内で−／＋。余らせてもよい。「おまかせ」はseedから出自を選び1点を動かす（見た目を選んでいた1回目の乱数は捨てて引き、同じseedの出自・能力値は従来と同じ）（`randomPc`）。
- 何も作らなければ出自1つ目（従来のフィン／レン）で始まる。作った役は `snapshot().pc` / `result().pc` に入り、本編の本棚の記録に `cleared[id].pc`（名前・肩書き・出自・能力値。#3050 より前の記録には見た目のIDも残っている）として残る。中断した卓の役は保存しない。
- 純関数 `buildPc(scenario, {archetype, name, stats})` が検証（旧セーブの `look` は無視）（範囲外・点数超過・空名・7文字以上は例外）。`TrpgSession(scenario, {pc})` で席のシートを置き換える。仲間のシートは変えない。

### 卓の進行・メモ・判定

背景をステージ全面に表示し、探索では光る地点を直接調べます。地点の名前はホバー・キーボードフォーカス時に表示し、調査済み地点はチェックに変わります。
常設のサイドバーと会話窓をなくし、人物と字幕は会話中だけ表示します。5ステップの進行は読み上げ向けに維持します。
探索の目標は手がかり3個。サメ編では残りの調査箇所・新規調査の危機コスト・現在の危機も示します。
右下の「メモ」で発見を読み比べられ、見立ての画面でも「手がかりを見る」を開けます。再読は無料です。
見立て・準備・最後の作戦は、情景や道具のイラスト3択から選びます。準備は1項目ずつ進み、上のタブから前の選択へ戻れます。絵の説明はホバー・フォーカス・選択時に表示します。

判定は背景の上に大きなサイコロを表示します。成功の見込みは補正込みでいつも出し（TRF23）、「判定の詳細」を開くと2d20の閾値と3つの結果の概算確率を確認できます。助力と札の消費は常に表示し、実際に振るまで札を使いません。
見立ての正誤を隠すため、サメ編の追加補正は条件付きの確率範囲で示し、出目が決まってから実際の補正を表示します。
割合は各結果を四捨五入するため、合計が100%にならない場合があります。
振り直しは残すサイコロと実際の補正から成功の見込みを計算し、新しい出目が下がる可能性も案内します。
結末の「この卓を振り返る」では、選んだ提案・取得した手がかり・3回の判定・使った切り札を確認できます。
提案が結末を決め、判定が途中の出来事を変える既存ルール、費用・行動消費・保存形式は維持しています。

会話送りのEnter／Space長押しを抑止し、調査の会話後は元の地点へフォーカスを戻します。
判定中もTab／Shift+Tabはダイアログ内に留まり、結果の合計と評価を読み上げ対象にします。
回帰は `node --test remake/test/trpg_feedback.mjs` と `node remake/test/browser/trpg_experience.mjs`。

### 道具を使う手ざわりと見やすさ（2026-11-02・TRB19）

- **ダイストレイ**: 判定のダイスは木の縁とフェルトのトレイに、袋のある右上から投げ込む。宙では数字が転がり、跳ねて着地した瞬間に本当の目で止まる（結果まで約1.05秒。動きを減らす設定では0.04秒で静止）。ダイスは外側が移動と影、内側の体が回転するので、影はフェルトに落ちたまま。振り直しは選んだ1個を持ち上げて投げ直し、新しい目は着地で見える。補正はトレイの縁の真鍮のチップ。
- **音**: 手の中のカラカラと、2個ぶんの着地のカチッ（だんだん小さく）を合成で鳴らす。切り札を場に置く音、手がかりの紙片の音も同じく合成。
- **カード**: 切り札を借りるとカードが場に置かれ「場に出した」の印。上の連携札は小さなカードで、使うと裏返って抜け、戻ると表で入る。振り直しの選択肢もカードの見た目。
- **紙**: 新しい手がかりは調べた場所からメモ帳へ紙片が飛ぶ。キャラクターシートとメモのカードは机に一枚ずつ置かれる。
- **明るい背景の絵でも**: 選ぶ画面の見出し（聞き込み・思わぬ展開・準備・クライマックス）、聞き込みの説明、選んだ項目の一覧に暗い札を敷く（朝霧の王国など上部が白い絵）。
- **準備の項目タブと選択肢の絵**（2026-11-07）: 準備の画面は見出しの札（「1 / 2」つき）を少し上げ、項目のタブ（香り／選んでいない など）を下げて重ならないようにし、タブにも暗い札を敷く。タッチ操作の配置ではタブの下線を札の下端へ（2行目を横切らない）。選択肢の絵にはシール風の白いふち（2026-11-10・TMX03）と薄い暗い光彩（`drop-shadow(0 0 6px)`）を足し、霧や白壁の背景でも物の輪郭が溶けないようにする。
- **見やすさ**: 紙の画面では、説明・未選択タブ・手がかりの開閉・琥珀の札の文字を紙の文字色に。結末は左から夜の下地を敷き、絵のない本の場所名は右上の小さな札に。

### ゾロ目と卓の評価（2026-10-24）

判定のゾロ目は卓のイベント。**クリティカルとファンブルの決まりは 2026-11-11 に改めた（TRF01・上の節）**: 20の目が出たらクリティカルで必ず成功、1の目が出て思わぬ出来事になったらファンブル。クリティカルは、物語を続けると共有の連携札が1枚戻る（上限2枚。満タンなら拍手だけ）。最高の出目なので振り直しは出さない。他のゾロ目は歓声で、評価は変えない。（2026-11-11 まで: 20ゾロだけがクリティカル、1ゾロだけがファンブルで、どちらも評価を変えなかった。）
直後にGMとはじめの短い掛け合いを流す。台詞は `data/dialogue/trpg_table_talk.json`（catalogの `tableTalk`）で、話者は各シナリオのGMとはじめだけ。ファイルが読めない時・そのGMの台詞が無い時は掛け合いだけを省く。
結末では卓を星3つで評価する。★見立てが真相に合う ★提案が本来の結末に届く ★判定で2回以上うまくいく。称号は にぎやかな卓／よい卓／名卓／伝説の卓。結末画面・振り返りに内訳を出し、本編の本棚の記録には `cleared[id].stars` を任意項目で残す（旧記録は星なしで表示）。
探索の待機中は座席バーを画面下端へ下げ、調査地点に重ならないようにした。振り直しで成功に届かない時は「ひと手間以上」の見込みを示す。

### 卓の盛り上がり（2026-10-24）

上部に盛り上がり（0〜10。2026-11-12 まで 0〜8・TRF12）を表示する。上がる場面: 判定がうまくいく＋1、思わぬ出来事＋1（ハプニングも卓の華）、ゾロ目＋1／ファンブル＋2／クリティカル＋2（2026-11-11 まで＋3。評価の＋1と重ねない）、仲間の切り札＋1、ひらめきの振り直し＋1、各仲間への初めての相談＋1、見立ての話し合い＋1、役の見せ場＋1（自分の役も仲間の役も、初めて前に出る時。下の TRF12）。サイコロを振らない加点なので、同じシードの物語は変わらない。
3「あたたまってきた」・6「沸いてきた」・10「最高潮」（2026-11-12 まで 8）に届くたび勢いが1貯まり（最大2）、1つにつき＋4が次の判定の補正に加わって使い切る。判定の見通しにも「勢い」として含める。6・8に届いた直後はGMとはじめの掛け合い（`trpg_table_talk.json` の `heat_up` / `heat_max`）。
結末に夜の名前（静かな夜／和やかな夜／盛り上がった夜／大盛況の夜）と値を出し、本編の本棚の記録へ `heat` と `night` を任意項目で残す。結末そのものは従来どおり提案で決まる。

### 判定の手応えと進行表示（#649）

上端に現在の段階・完了した判定数・連携札、サメ編では危機を表示する。判定の卓にも同じ情報を置き、助力と振り直しで札を使った時点で更新する。出目確定時は「二つの出目＋補正＝合計」を示し、評価ごとの着地・光・効果音を加える。演出は出目や補正を生成し直さず、振り直しも既存のモデルが返した結果だけを描く。

段階の大見出しは小さくし、探索の中央と調査地点を空ける。出目確定時の動きは背景タブで停止し、動き軽減では省く。音は従来どおり初期OFF。通常／サメ両作品のルール・結末・料金・保存は変更しない。新規画像生成はせず、既存の卓・背景・キャラ素材を使う。

### 世界一普通の一台

標準の配役はGMひより、PLははじめ・アダム・つむぎ。架空の小冊子の作者は汐見しお。
物語は港町ノーラの茶房「波止場の灯」。PLが演じるのはフィン・ニコ・ルカ、
旅人はオル。本編人物・店舗を冒険の登場人物にしていない。

1. 旅人の話を聞く（2d20）。
2. 部屋の6箇所を調査し、3つ以上の手がかりから仮説を立てる。仲間への相談とメモ再読は自由。
3. 香りと席を組み合わせ、一台を準備する（2d20）。
4. 声のかけ方を選び、提供する（2d20）。結末と卓の振り返りを読む。

どの判定も 2d20 ＋ 宣言したPCの能力値（2026-11-01 まで一律＋3）。30以上は成功、19〜29はひと手間、18以下はハプニング。20の目が出たら合計にかかわらず成功（2026-11-11・TRF01）。
失敗しても次の場面へ進む。共有の連携札は2枚、切り札は一人一度。
アダムは準備＋7、つむぎは提供＋7、はじめは結果を見てサイコロ1個を振り直す。
切り札を使うたび連携札1枚を使うため、全員分を一度に使うことはできない。

旅人の事情は静かな休息・懐かしい時間・会話の3種類。提案は3×3×3通り。
結末は「雨音」「帰り道」「話の始まり」「一緒に見つける」の4種類。
香りに加えて席・声かけが結果に効く。判定の出来は途中の出来事を変える。
### サメは閉店を待たない

標準の配役はGMサメちゃん、PLははじめ・ひより・つむぎ。作中の架空の作者が書いたサメ映画風台本。
6つの調査地点のうち最大4箇所を選ぶ。3つ以上の手がかりで習性を見立て、道具・経路・最後の作戦を組み合わせる。
新しい場所の調査で危機＋1、判定は成功＋0／ひと手間＋1／ハプニング＋2、最大6。
危機5以上は卓の振り返りも変わる。再読・相談は危機も回数も使わない。見立てが合えば仕掛け判定に＋4。
香り・振動・光を追う3種類の怪物、4結末。どの作戦・出目でも全員生還し、先へ進める。
怪物の習性は架空の映画設定。現実のサメの生態説明ではない。ゴア表現やジャンプスケアは入れない。

両作とも各約10分の想定で、実時間の制限はない。読み込み待ちや考える時間を減点しない。
ページ更新後は本棚またはURLで指定した表紙から始まる。本編セーブ・手動枠・sessionStorageを読み書きしない。

## 呼び出す

呼び出し側のCSSに `remake/css/trpg.css` を含め、空の画面領域を渡す。

```js
import { runTrpg } from "./trpg/index.js";

const result = await runTrpg(host, {
  scenarioId: "shark-last-order", // "ordinary-cup" が既定
  signal: abortController.signal,
});
if (!result.cancelled) {
  // scenarioId、ending、variant、plan、hypothesis、clues、checksなどを返す。
  // 独立セッションの結果。本編ではcampaign-viewが読了時点で保存する。
}
```

`runTrpg()` は卓を片付けた時に解決し、画面・タイマー・イベント・中断リスナー・所有する音声を除去する。
再挑戦ボタンでは `replayRequested: true` を添える。再開の可否と本編の費用は呼び出し側が決める。
ロード中もAbortでキャンセルし、事前Abortならリソースを読まない。単体呼び出しは指定した1本だけ読む。
中断は `{ cancelled: true, scenarioId }`。単体の処理から本編の状態モジュールを読み込まない。
`mountTrpg()` には `finished`、読み取り用の `snapshot()`、`destroy()` がある。

独立した開発プレビューで2本の本棚を表示する場合は `mountTrpgCollection(host, { signal, closable: true, closeLabel })`
を `trpg/collection.js` から呼ぶ。`ready` は初回読み込み後、`finished` は閉じた後に解決する。
失敗時は画面内で再試行でき、読み込み中も閉じられる。`snapshot()` と `audioSnapshot()` は読み取り専用。

QA用: `?scenario=ordinary-cup&seed=9&traveler=quiet`、`traveler=home`、`traveler=company`。

## Campaignの入口と保存

`mountTrpgCampaign(host, {getState, save, nightBusy, readOnly})` は明示的に渡した状態だけを扱います。
`readOnly` なら入荷・購入・クリアを一切変更しません。`daily/trpg.js` は本編state/saveを渡すアダプターです。
`openTrpgBar()` が `{completed:true}` を返した場合、既にslotを消費し保存済みなのでcalendarは `slotsUsed:0` で受け取ります。
本編の状態schemaは15。設立・入部のない旧セーブは未設立から始め、購入済み・クリア済みの本は保持します。旧無料試遊の履歴や好感度から入部を推測しません。
