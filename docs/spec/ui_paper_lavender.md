## 2026-11-11 見た目の様式：新版（既定・全章）／旧版／DS風（LK）

オーナー依頼（2026-11-11）: 「今の様式も戻れるように残しつつ、新版として今のを磨き上げたやつと、DS風を作ってみて。まずは1章だけ。また切り替えられるように」。台帳は `docs/owner_requests.md` の LK。

- **切り替え**: 設定の「見た目（DS風は第1章のみ）」の段ボタン（新版／旧版／DS風）。保存先は端末の設定（`config.look`）で、セーブデータには入れない。`?look=neo|classic|retro` の URL でも切り替わる。「旧版」はこれまでの様式（`classic`）で、この節の「現行」も同じものを指す。
- **既定は新版**（LK09・2026-11-11 オーナー「新版をデフォルトにしたい。前のも残しつつ」）。何も選んでいない端末は新版になる。#3256 の頃に当時の既定として保存された旧版は選んだものと区別できないので、一度だけ新版へ移す（`core/look.js` の `migrateLook`・`config.lookVersion`）。その後に選び直した旧版・DS風は保つ。
- **自動操作のブラウザ（`navigator.webdriver`。ブラウザテスト）だけは旧版が既定**。既存の検査は旧版の画面の寸法を測っていて、ほかの作業で足される検査も旧版を前提に書かれるため。新版・DS風の検査は `?look=` か設定で明示して選ぶ。プレイヤーの既定は `remake/test/browser/look_default.mjs` が自動操作の印を外して確かめる。**新版の画面を変えた時は `look_neo.mjs` に検査を足す**（既存の検査では新版の崩れに気づけない）。
- **効く範囲**: 新版はすべての章で効く（LK13・2026-11-11 オーナー「新版を広げる」）。DS風は第1章にいる間とタイトルだけ効き、第2章以降は自動で旧版の表示になり、第1章へ戻れば DS風に戻る。章の制限は様式ごとに `core/look.js` の `LOOK_CHAPTERS`（`{ neo: null, retro: [1] }`。null はすべての章）。DS風の章を増やす時はここに足す。
- **仕組み**: 効いている様式は `<html data-look="…">`。現行の CSS・JS には手を入れず、新版は `css/look-neo.css`（＋心得の盤の `css/look-neo-board.css`・絵の部品の `css/look-neo-art.css`）＋`js/looks/neo.js`（＋`js/looks/neo/`）、DS風は `css/look-retro.css`＋`js/looks/retro.js`（＋`js/looks/retro/`）が、その様式の時だけ重なる。現行で遊ぶ端末は新版・DS風の JS を読み込まない（`js/looks/index.js`）。UIデザイン（配色のテーマ・`data-ui-theme`）とは別の設定。
- **変えないもの**: 進行・判定・報酬・台詞・セーブ・操作の当たり方。どの様式でも同じゲームが動く。
- **新版でそろえる範囲**（LK18・LK20・2026-11-11 オーナー「ミニゲームとかは固有のUIがあっていい。基本は雰囲気統一はしたい」「意図的に紫っぽくしてないやつは見分けて」）: そろえるのは日常の共通の画面（会話・地図と HUD・MENU・小窓・ショップ・心得の盤・章の場面カードなど）。次の2種類には新版の規則を書かない。
  - **固有の見た目を持つミニゲーム**: TRPG・斧投げ・てつこ・くじのガラガラ・一台勝負・スロット・DJ・ラクダレース・サンドボード・プリクラ。
  - **実物をまねた物・わざと紫にしていない物**: LIME（画面・HUD の印・朝の通知・交換の演出。スマホのメッセージアプリのオマージュ）、店のロゴと商品の絵を載せる生成りの札、登場カットインの帯、大会の規則の紙・チェキ・ロード中の漫画。
  - 新しい画面を新版へ合わせる前に、どちらかに当たらないかを確かめる（当たるなら旧版と同じ見た目のままにし、検査で一致を確かめる）。
- **新版がメイン**（LK17・2026-11-11 オーナー「今作ってる新版をメインにしていきたい」）。新しい画面・部品は新版（`?look=neo`）を基準に作って確かめ、旧版（紙とラベンダー）は残す様式として崩れないことを見る。紙のテーマの変数（`--paper-ink`・`--lavender-soft` など）で色を決める部品は、新版の面の中で読めなくなることがある（面は暗く、文字の変数だけ白くなる）ので、新版の規則を `css/look-neo.css` に足し、`look_neo.mjs` か `look_neo_more.mjs` に検査を足す。シーシャ作り（制作）の画面は作り直しの可能性があるので、新版への合わせ込みは保留。

### 新版（`neo`）

現行の横画面を磨く様式。絵は描き直さず、置き方と動きを変える。言葉づかいは「夜紫の半透明の面・金の細い罫線・ラベンダーの縁・白い文字」。

- 会話: 白い箱をやめ、下からの夜紫の半透明の帯に白い本文。名前はキャラの色の細い線（登場カットインの色）。AUTO などの操作は、帯の名前の行の右端の小さな札（人物の顔や頭に掛からない位置）。
- 立ち絵と背景: 会話中は背景をわずかにぼかして（1.5px。奥の物の形が分かる程度）暗くし、立ち絵に場面の光の色（昼・曇・夕・夜）・輪郭の外の薄い影・ゆっくりした呼吸を足す（「揺れ・閃光を減らす」、OS の動きを減らす設定、SKIP 中は止まる）。
- 選択肢: 夜紫の半透明の札に金の番号。
- 地図と HUD: ピンはロゴの札＋その下の夜紫の1枚の帯（上に店名、下に料金）。休みの店は色抜きと破線、選択は金の輪。HUD は夜紫の細い板1本、LIME と MENU は同じ大きさの丸い札。案内の板・行動の選択・トースト・獲得通知も同じ言葉づかい。料金・「!」・休み・未読の印と、押せる範囲は現行以上を保つ。
- 全画面 MENU: 夜紫の面。タブは線画の絵記号。ステータスにははじめ、人間関係には選んだ相手（未選択なら先頭）の立ち絵を大きく出す（会話と同じ画風の設定。`js/looks/neo/menu-figure.js`）。絵が読めない時は絵の枠を出さず全幅に戻る。
- モーダル（設定・LOG・用語集・確認・セーブ／ロード）とタイトルのメニューも夜紫の面と金の罫線。大会の規則の紙とショップの問いは、紙のまま。
- ショップ（全支店・LK16）: 夜紫の面と金の罫線。売り場のタブは選んだものが金、分類は選んだものがラベンダー、商品の絵（パッケージ・機材）は生成りの札に載せて絵は変えない。購入は金、選ぶまでは破線。商品の詳細などの問い（`.shop-dialog`）もモーダルと同じ面。
- LIME（LK20・2026-11-11 オーナー「あえて実際のラインのデザインをまねてる」）: **新版でも変えない**。実際のスマホのメッセージアプリをまねた見た目（緑の見出し・白い一覧・青みがかった灰のトーク・緑の自分の吹き出し・朝の通知の札）のまま。HUD の LIME の印も緑の角丸四角に白い吹き出し（大きさと位置だけ MENU と揃える）。LK16 で一度夜紫にしたのは取りやめた。
- レベルアップ・日付の幕・ギャラリー（LK16）: 札とボタンを夜紫の面と金の罫線へ。演出の動き・時間、ギャラリーの鑑賞面は変えない。
- 絵の部品（LK19・`css/look-neo-art.css`・2026-11-11 オーナー「CSSで作りました感強いところは直したい」）: 面・札・ボタンは CSS のグラデーションだけにせず、**制作・大会と同じ夜紫の絵の部品**（`img/ui/craft-night`。原画と依頼文は `asset_sources/ui/craft-night-20261102/`）を九分割で重ねる。板（`board`）＝小窓・行動の選択・章の場面カード・レベルアップ・盤の説明・リザルト・ギャラリー・ショップ・地図の案内、ガラスと金のボタン（`button-glass`・`button-gold`）、細い帯（`rank-strip`）＝行動の選択の札・会話の選択肢・HUD の板・通知・獲得の札、MENU の奥（`backdrop`）と札（`window`）。重ねるのは絵だけで、箱の大きさ・余白・文字・押せる範囲は `look-neo.css` のまま（縁の幅は 0 のまま、`border-image-width` で絵の縁の太さを決める）。絵が読めない時は `look-neo.css` の面が見える。新しい面や札を足す時は、まずこの部品を当てる（CSS だけの面を増やさない）。新しく要る部品は `asset_sources/ui/neo-20261111/` の依頼文で生成してから組み込む。**会話の帯の煙**（`img/ui/neo/band-smoke`。帯の上の端。地の文でも）と**見出しの飾り罫**（`img/ui/neo/heading-rule`。名前の下・小窓と LOG と行動の選択の見出しの下。元の金の線に重ねる）は第2弾で組み込んだ。会話の帯は下の絵を透かす作りなので絵の板を重ねない。
- 心得の盤（LK17・`css/look-neo-board.css`）: 紙の面をやめ、夜の店の灯りの絵（`growth_board/screen_backdrop.webp`）を背景に、見出し・盤の札・右の説明・下の帯・丸い札・ボタンを夜紫の面と金の罫線へ。光る管とマスで描く盤の面の中、並び・寸法・文は旧版と同じ。はじめての案内の吹き出しと見方の窓も同じ面。
- そのほかの残り（LK17）: 店の人の一言（斧投げBar・クラブSEAM）は夜紫の札に金の名前、斧投げBar の選んでいる部門は金の札。章のクリアのボタン、リザルトの板、古い STATUS の窓のタブ、大会の会話の間の MENU（HUD の MENU と同じ夜紫の札）、ショップのくじの行の札。
- 自前の見た目のまま: くじを引く演出、シーシャ作り・大会（元から夜紫の UI。作り直しの可能性があるので保留）、TRPG・斧投げ・てつこ・一台勝負・スロットなどのミニゲーム、物語の中の物（大会の規則の紙・チェキ・ロード中の漫画）、明るい台紙向けの絵を載せる生成りの札（店のロゴ・商品の絵・来店の札）、登場カットインの帯。
- 作り: 配色のテーマ7種のどれでも同じ見た目。光の色は背景の名前と色かぶせから昼・曇・夕・夜を CSS で見分ける。呼吸は立ち絵の層ごと動かす（立ち絵の画像に終わらない動きを付けると、会話エンジンが動きの終わりを待って止まるため）。

### 新版の縦持ち（LK11・LK12）

新版で縦長の画面（スマホの縦持ち・縦長の PC の窓）の時は、DS風の外枠と操作を使い、上画面は新版と同じ高解像度の絵にする（2026-11-11 オーナー「操作だけDS風であとは基本は新バージョン」「DSは新バージョン同じ素材で。テキストとかUIはドットっぽいと味があるので残していいかも」）。横長の画面は上の新版のまま。

- **上画面**: 背景・立ち絵・一枚絵を実機の解像度で描く（canvas の裏画面は CSS の大きさ × devicePixelRatio。減色・網点はしない）。人物がいる間は背景を少し暗く・わずかにぼかし、立ち絵に柔らかい影。一人の場面は人物へ 1.35 倍に寄る（切り替えは 280ms ほど）。場面の切り替えはクロスフェード。動きを減らす設定では即時。描き直しは入力が変わった時だけ・30fps まで。外枠を出している間は、新版の立ち絵の呼吸を止める（見えていない現行の画面の動きで毎フレーム描き直さないため）。
- **下画面と本体のボタン**: DS風と同じドット調（ドット書体・生成りの窓・ベタの影）のまま。仮組みで新版調と見比べて決めた。
- **タイトル**: キャラクターの絵を上画面いっぱいに（上寄りで切る）、ロゴを左上に。下画面はドット調のメニュー。
- **対応する場面・操作の中継**: DS風と同じ（タイトル、会話と選択肢、地図、tonari の行動選び、場面転換、日付の札・章タイトル・詩、登場カットイン）。
- **MENU・LIME・小窓・LOG・ショップ（シート・LK14・LK15）**: 元の画面の中身を読み、ドット調の部品へ写す汎用の「シート」（`retro/sheet.js`）で縦持ちのまま開いて閉じられる。押す・入力するは元の部品へ中継する（保存・反映・進行は元の処理のまま）。MENU は上画面にタブに合った絵（ステータスははじめ、人間関係は開いた相手の立ち絵）、下画面に今のタブの中身、本体のボタンに4つのタブと「閉じる」。LIME・設定・用語集・セーブ／ロード・大会の規則の紙・確認の問い・会話の LOG は、上下の画面をつないだ縦長の1枚。文と選択肢だけの小窓は、上画面にその場の絵・下画面に選択肢。DS風でも同じ部品で動く。 ショップ（全支店）は縦長の1枚に商品の一覧・数量・合計と購入・店を出る、売り場のタブは本体のボタン。セーブの引っ越し・夜のレベルアップ・LIME の初回の案内・章のクリアの画面も写す。
- **縦持ちの LIME の色（LK20）**: ドット調のまま、実物のアプリの色の役割にする（緑の見出し・白いトーク一覧・青みがかった灰のトーク・白い相手の吹き出し・緑の自分の吹き出し・緑の「閉じる」）。DS風でも同じ。
- **未対応の場面**（心得の盤・くじを引く演出・スロット・シーシャ作り・大会・ミニゲーム）: 小さい横長の画面は出さず、600ms 続いたら回転案内（`#rotate-hint`）を出す。案内の文は新版の縦持ちの間だけ「この画面は横向きで表示します／端末を横にしてください」（印は CSS で描く。止めると元の文に戻る）。案内が出ている間は、これまでどおり制作の時計と音が止まる（`core/rotate-guard.js`）。タッチでない縦長の窓では回転案内が出ないので、DS風と同じく小さい画面＋一言。
- **作り**: `js/looks/neo.js` が、縦長になった時に初めて `js/looks/retro.js` を読み、`startShell({ paint: "hd", mode: "portrait" })` で起動する（横長だけの端末は外枠のコードを読まない）。高解像度の描き方は `retro/painter-hd.js`、DOM の読み取りは DS風と共通の `retro/stage-read.js`。描き方は `<html data-retro-paint="hd|dot">`。
- 検証: `node remake/test/browser/look_neo_portrait.mjs`（縦持ちのタイトル・会話・地図と場面転換・tonari の行動選び、MENU で回転案内、横長と PC は今の新版、縦長の PC の窓、第2章は元の回転案内、様式の切り替えで痕跡が残らないこと）。

### DS風（`retro`）

上下2画面（各 256×192・4:3）のレトロな様式。上で見て、下で読む・触る。文字はすべてドット書体（DotGothic16）、角丸・ぼかし・グラデーションは使わない。

- **絵は今の素材を自動でドット絵にする**: 現行の画面を動かしたまま隠し、背景・立ち絵を 256×192 へ写す。絵の描き直し・追加はない。
  - 背景（会話の背景・地図・タイトルの絵・一枚絵）: 面積平均で縮小 → コントラストを少し上げる → 弱い輪郭強調 → Bayer 4×4 の網点 → その絵自身の64色へ減色。
  - 立ち絵: 不透明度を掛けて面積平均で縮小 → 弱い輪郭強調 → 元の絵から作った48色のうち一番近い色へ寄せる（網点なし）→ 透明度は2値。目・口・飾りの色を残したまま、にじみの中間色をなくす。
  - 一人の場面は人物へ1.35倍に寄る（切り替えはコマ送り）。フェードは半透明ではなく網点の抜き。重い処理は絵ごとに一度だけ行って覚える（`js/looks/retro/dot.js`・`painter.js`）。
  - 1ドットが実機の画素の整数倍になるよう外枠の幅をそろえ、補間なしで拡大して描く（倍率3の縦持ちで1ドット=4画素）。整数倍にできない画面は幅いっぱい＋`image-rendering: pixelated`。
- **出る条件**: 縦長の画面（スマホの縦持ち）と PC。横持ちのスマホでは旧版の画面のまま。DS風を出している間は、縦持ちの回転案内（`#rotate-hint`）を出さない。外枠・場面の見分け・操作の中継は、新版の縦持ち（上の節）と共通の部品。
- **対応済みの場面**: タイトル、会話と選択肢、日常の地図（行き先選び）、tonari の行動選びなどボタンが並ぶ画面、登場カットイン、場面転換（煙・暗転・移動の幕・夜明け）、夜明けの札・章タイトル・巻頭の詩（見えている文字を読み取って出す）。
- **未対応の場面**: ロード画面、シーシャ作り、大会、心得の盤、くじを引く演出、スロット。対応するまで旧版の横長の画面をそのまま表示し、縦長の画面では下に「この場面は横向きにすると大きく表示されます」と出す。覆いを写せないままタップ待ちが6秒続く時、中身が20秒変わらない時も、安全のため旧版の表示へ切り替える。雨・煙の効果と、会話中のはじめの顔の小窓は出ない。MENU・LIME・設定などの小窓・会話の LOG・ショップ・セーブの引っ越しは、新版の縦持ちと同じシートで出る（上の節）。
