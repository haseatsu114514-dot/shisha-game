# tonari フロア営業 — バイトを「一人で店を回す遊び」にする（2026-11-20・TFL01〜）

オーナー「バイトパートを龍が如く0や極2にあるキャバクラ経営ゲームみたいにしようと思ってます」（2026-11-20）から始まり、同日の「キャバクラ経営の仕様をまとめました本家の。これを元にどうシーシャにアレンジするかや実装を考えてみて」（「シーシャ経営ミニゲーム システム・UI設計仕様書 — 『龍が如く0』キャバクラ経営分析ベース — ワンオペ＆30種フレーバー調合型 実装リファレンス」）と「すみさんとタッグというより1人でワンオペで回す」を受けて、**ワンオペ＆フレーバー調合型**に作り直した（TFL13）。さらに同日の「完全に指定してくる人もいるのでそういう人はそのまま出す／抽象的な依頼が多く」「好感度1以上の人物がたまにレアで遊びに来たり」「表情アイコンが元ネタのまんまなので少し変えたい」「東京編やドバイ編でも同じゲームをやるバイトするってなると、原価とか仕入れとか利益とかは気にしない。ただ満足させて売上をいかに上げるかのゲームにする」を受けて、注文の種類・レアな来店・顔の印を足し、**原価・仕入れ・利益を外した**（TFL15〜20）。この文書は、実装した形の仕様の正本。試遊で変えたらここを直す。

- 本体: `remake/js/daily/tonari-floor-model.js`（ルール。DOMなし）／`tonari-floor-data.js`（単価・フレーバー30種・相性・客・注文の言葉・ケア・営業の種類・評価の台本）／`tonari-floor-view.js`（画面）／`tonari-floor-stage.js`（店内の絵と位置・届いた絵の登録）／`tonari-floor-art.js`（記号と客の影絵）／`remake/css/tonari-floor.css`
- 入口と確定: `remake/js/daily/tonari.js`（勤務札 `tonariMenu`・`serveFloorOrder`・日当）と `daily/calendar.js`（行動枠・営業中は保存を止める `holdActionSave`）
- 素材: Codex への依頼 [asset_sources/ui/tonari-floor-20261120/README.md](../../asset_sources/ui/tonari-floor-20261120/README.md)（Issue #3960。届くまでは採用済みの店内画＋コードの影絵。見た目の計画は §7）

## 1. オーナーの仕様書と、実装した形

遊びの芯は仕様書のとおり: **一人で全卓を見る**／**約30種のフレーバーから1〜3種を調合して出す**／**定番（プリセット）をひと押しで出して手数を減らす**／**作成は自動で進むので、その間にほかの卓のケアへ回る**／**延長は誘わず、満足した客が自分から言い出す**／**フィーバーは3段**。

| 仕様書 | 実装 | 補足 |
|---|---|---|
| 3フェーズ（準備・仕込み → リアルタイム営業 → リザルト） | 準備の画面（今日の定番と釣り合いの図・定番を組む）→ 営業 → 精算 | **仕入れ・原価・利益は扱わない**（オーナー決定 TFL20。ほかの店のバイトでも同じ遊びを使うため） |

スミさんは営業に出ない（奥で帳簿をつけている）。仕込みを持つ・レジを受ける・残った卓を引き継ぐ、の手伝いは無くした。助言の代わりに、はじめの心の声（今いちばん先に見る所）が下の帯に出る。スミさんの一言は、締めの精算にだけ出る。

入れていないもの: 仕入れ・原価・利益（オーナー決定）、ライバル戦、キャストの育成にあたる成長、常連帳（#1267）。店のファンは**合計の数だけ**を持ち越す（誰が常連かは持たない）。

**満足させて、売上を上げる遊び**（TFL20）: お金の出入りは売上だけ。売上は、卓を早く回す（注文を待たせない・会計をすぐ受ける）・満足を上げて追加ドリンクとトップ替えを引き出す・フィーバーで伸びる。東京編・ドバイ編でほかの店のバイトをする時も同じ遊びを使えるよう、店ごとの事情（仕入れ・原価）を持ち込まない。いま開いているのは第1〜2章の tonari だけ（ほかの章は §8）。

守ったこと: 常連帳・職場の好感度を作らない（#1267）。チップを描かない（売上ボーナスは店から）。失敗で日当・体力・交友は減らない。本編の人物は、たまに遊びに来るだけで、好感度は動かない（§3「レアな来店」）。いつものシフト（短い接客）はそのまま選べる。画面の構成は原作の営業パートに寄せ、絵・ロゴ・固有の意匠は写さない。

## 2. 入口と本編への接続

- 勤務札に「フロアを任される（バイト）」。**第1〜2章**（はじめがバイトとして立つ間）で、最初のシフトを一度済ませた後に出る。第3章以降はいつものシフトだけ。
- 行動枠・体力・能力の伸び・経験値・シフト上がりのスミさんの会話は、いつものシフトと同じ。同じ日にどちらか一方。
- 流れ: 前掛けの一行 → （はじめての日だけ）スミさんの `tonari_floor_first`（「今日は、店を一人で回してみろ」）／二回目から `tonari_floor_start` → その日の接客の話（カメオ・抽選の接客） → **フロア営業** → 閉店の一行・日当 → スミさんの会話。
- フロア営業は「今日の注文」（#1073）の代わり。ワンオペの営業は、その日の注文の記録（`_shift_order_`・`_shift_mix_`）に触れない（想起 #1415 は、いつものシフトでだけ進む）。
- 本編の常連の話として入るシフト（`story`）と、スミさんに呼ばれたシフト（`called`）は、いつものシフト。
- 営業中は保存しない（途中の体力や訪問記録だけが残らないよう、`holdActionSave`）。本編メニューは休止の窓から開け、離れると勤務前の保存へ戻る。LOAD・タイトルへ戻った時は何も残さない。
- 保存する値は `state.flags._tonari_floor = { nights, best, presets, fans }`（回した回数・いちばん良かった評価・定番ミックス・店のファンの合計）。SCHEMA は上げない。

## 3. 一回の営業

時間は刻み（tick）で進む。1刻み＝実時間0.5秒。営業は320〜384刻み（2分40秒〜3分強）。操作は刻みを使わない。

卓ごとの段階と、押した時に起きること:

| 段階 | 卓の札の見出し | 押すと |
|---|---|---|
| 空席 | （空席） | 何も起きない。客は来たら自分で座る（番号の若い空席から） |
| 注文待ち | 注文（残り秒が減っていく） | **調合の窓**が開く。定番を右の列から押せば、窓を開かずにそのまま出せる |
| 作成 | 作成中／作成待ち（進みの棒） | 何も進まない。仕上がると自動で卓へ運ばれる |
| くつろぎ | くつろぎ中（円＝滞在の残り、棒＝炭の残り） | 何も進まない |
| ケア | ケアの言葉、または「様子が変だ」 | 接客ビューが開く。5つの手から選ぶ。正解は◎、外すと× |
| 会計 | 会計 | その場で会計する（ひと押し。選ばない） |
| 片付け | （片付け中） | 3秒で空席に戻る |

- **注文の種類**（抽象的な依頼が多く、完全に指定してくる客もいる）:
  - **雰囲気だけ**: 「さっぱり系で、煙が多めのがいいな」。系統（フルーツ／さっぱり＝スッキリ／甘い／お茶かスパイス）と吸い心地を読んで組む。
  - **一種＋雰囲気**: 「ミントで、さっぱりお願いします」。挙げた一種を入れて、その雰囲気の系統を混ぜる（ミント＋スッキリ系の何か）。
  - **完全指定**: 「グレープミントで」「ダブルアップルだけで、お願いします」。**言われたとおりに、そのまま出す**（グレープ＋ミント）。よく頼まれる16通りから。
  - **NG つき**: 雰囲気＋「ミント無しでお願いします」。
  - **おまかせ**: 吸い心地だけ言う。相性が効く。
- **調合**: 棚（系統のタブ4つ）から1〜3種をボウルへ入れる。右に予想（4特性の棒と客の求める高さ・系統の合い方 ◎○△×・相性・NG に当たるか・予想の満足・作成の秒数）。名前の挙がったフレーバーは、棚のタブと札に印が付く。定番はひと押しでボウルに入り、注文との合い方の印が付いている。開いている間、店の時間は止まる。
- **一台の評価**（提供した時の満足）: `40 ＋ 24 × 系統の係数 × 相性 × 特性の比`。
  - 系統の係数: 求める系統がミックスに占める重み（also＝半分寄与）で ◎1.5／○1.2／△0.8／×0.4。おまかせは1.2。
  - 相性: タグの組が成立するごとに＋10%（おまかせは＋20%）。相性は10組（柑橘×清涼・茶葉×クリーム・ジューシー×スパイス・柑橘×甘い・デザート×ナッツ・フローラル×ジューシー・茶葉×柑橘・クリーム×ジューシー・王道×清涼・茶葉×スパイス）。
  - 特性の比: 求める特性（味・香り／チル／爆煙／持続性）の値 ÷ 要求（一般2・こだわり2.5）。0.5〜1.25。
  - NG に当たると係数が半分になり、さらに−12。指定のフレーバーを入れると＋10、入れないと−15。
  - 85以上＝ぴったり、65以上＝いい感じ、50以上＝悪くない、それ未満＝ちがうかも。
  - **完全指定は式で測らない**: 言われたとおりの物だけ＝92（ぴったり）、余計な一種を足す＝68（いい感じ）、頼まれた物が欠ける＝32（ちがうかも）。
- **お代**: 注文を受けた時にチャージ（ひとり700円）と初回のドリンク（ひとり600円）、提供した時にシーシャ（2,000円）が売上に入る。追加ドリンクは600円、トップ替えは1,500円。原価は扱わない。
- **くつろいでいる間**: 満足は炭が進むぶん少しずつ下がる（持続性の高いミックスほどゆるやか）。追加ドリンクは22秒ごとに抽選（大満足70%・満足40%・普通10%。客ごとに上限あり）。
- **ケア**（待ってくれるのは11秒。過ぎると満足−10）: 炭の替え時（定期。持続性が高いほど間隔が長い）・煙が薄い→炭を替える／喉にくる→炭を下ろす／喉が渇いた→お水を出す／むせている（初めての客）→吸い方を案内する／話したそう（話好きの客）→雑談する。正解で満足＋5、外すと−8。
- **自然延長**: 滞在が終わる時、大満足の客は35%、満足の客は10%で「トップ替え、お願いできますか」と言い出す（こちらからは誘わない）。＋1,500円で、滞在が15秒延びる。一卓に一度。閉店まで20秒を切ると言い出さない。
- **会計**: 卓を押すだけ（選ばない。見送りの言葉は出来事の行に出る）。待ってくれるのは8秒（過ぎると満足が下がる）。ファンは満足の段で決まる（大満足＋3／満足＋2／普通＋1／不満0／激怒−2、帰ってしまった組−3）。
- **レアな来店**（TFL19）: 本編の人物が、5回に1回ほど、三組目の客として遊びに来る。来るのは**顔見知り（`met`）で好感度1以上、その章に来られる人**だけ（面識だけ・好感度だけでは来ない）。はじめての営業には来ない。卓の札とドックに顔アイコンが出て、札が金に灯る。その人の注文と言葉で返し、精算に「今日は、〇〇が遊びに来た」と残る。**好感度は動かさない**。台詞は大会の話をせず、大会の前後どちらでも通る（交流の時系列ルール）。
  - つむぎ（第1〜2章）: 「お茶っぽくて、落ち着くのを」＝雰囲気だけ（茶葉・スパイス系＋チル）。
  - なる（第1章だけ。第2章は店を休んで修行に出ている）: 「甘いやつ頼むわ。バニラは入れてくれ」＝一種＋雰囲気（バニラ＋甘系）。
  - アダム（第1〜2章）: 「ダブルアップルを。それだけでいい」＝完全指定（ダブルアップルだけ）。
  - 来る条件は `tonari.js` の `floorVisitor`、注文と台詞は `tonari-floor-data.js` の `VISITORS`。人を足す時は、その章にいるか（旅・休業）を正本で確かめる。
- **フィーバー**: ゲージはぴったりの一台＋14・いい感じ＋7・正しいケア＋10・満足以上の見送り＋4で溜まる（100で1段、最大3段）。押すと、溜まった段までを一度に使う（Lv1＝2卓／Lv2＝4卓／Lv3＝全卓。くつろいでいる卓のうち、滞在の残りが長い卓から）。16秒の間、対象の卓は満足100で固定・ケアが出ない・炭が進まない・5秒ごとに追加ドリンク。明けたあとは、元の満足＋10。
- **締め**: 全組を送り出すか、時間が来たら終わり。残った卓はその時点の満足で会計し、注文前の客は帰る（数えない）。休止の窓から早じまいもできる。

## 4. 回すほど変わるもの

`nights`（回した回数）で決まる。数値の成長・装備・解放の作業は無い。育つのは、覚えた定番（最大8枠）と店のファンの合計だけ。

| 回 | 営業 | 注文 | ケア |
|---|---|---|---|
| 1回目 | はじめてのワンオペ（五組・ゆっくり）。心の声が指す卓が光り、進め方が出る | 雰囲気だけ・完全指定 | 言葉で伝わる |
| 2回目 | いつもの昼／夜（七組）。準備の画面で定番を組める。本編の人物がたまに来る | ＋一種＋雰囲気・NG つき | 言葉で伝わる |
| 3回目 | 種から選ぶ（短い客が続く日・初めてさんの日・いつもの日。雨の日は長居の日）七〜九組 | ＋おまかせ | 言葉で伝わる |
| 4回目〜 | 同上 | 同上 | 「様子が変だ」だけが出て、接客ビューの様子の一文から読む |
| 6回目〜 | 満席の日（十一組）が混ざる | 同上 | 同上 |

勤務札には「今日の予報」（営業の種類）と、これまでの最高の評価が出る。昼のシフトは時計が12:00〜16:00、客の呼び名も昼のもの（昼休みの二人など）になる。

## 5. 評価と報酬

全組の満足の平均（帰ってしまった組は0）で決まる。

| 評価 | 条件 | 店からの売上ボーナス |
|---|---|---|
| 大入り | 88以上、かつ誰も帰していない | 1,500円 |
| 上々 | 74以上 | 1,000円 |
| まずまず | 56以上 | 500円 |
| ばたばた | それ未満 | なし |

日当（基本8,000円＋大会の実績＋魅力の指名ボーナス等）は評価に関係なくいつもどおり。店の売上とファンは、はじめの所持金には入らない。

検査用のボット（`remake/test/tonari_floor_bot.mjs`。全営業×12の種）での目安: 棚からいちばん合う一台を出せば大入り、定番だけで回すと上々が中心（完全指定は棚から出さないと外れるので、まずまずも出る）、8秒に1操作のほぼ放置でばたばたが中心、わざと合わない一台を出すとばたばた。店の売上は、うまく回して4万円前後・放置で3万円前後。

## 6. 画面

構成（どこに何を置くか・選ぶ時の見せ方）は原作の営業パートと仕様書に寄せ、絵そのものは本作のもの。

営業中（店内の全体が見える）:

- **上の帯**: 左に**作成中の一台**（2枠。卓番号・ミックス名・進みの棒。順番待ちは「待ち N台」）、**まん中に残り時間**（大きな数字と減っていく帯。残り30秒で赤くなる）、右に店の売上と休止。
- **卓の札**（卓ごとに一つ、いつも出ている）: 箱の上に用件の見出し（金＝押すと進む用件: 注文・ケアの言葉・会計／暗い札＝作成中／緑＝くつろぎ中／紫＝フィーバー）。箱の上の帯は客の要望（**色＝求める吸い心地**。味・香り＝紫／チル＝緑／爆煙＝黄／持続性＝水色。注文待ちの間は系統や指定の一種を字で出し、NG つきは「NG」の印）。左の窓に卓番号と客、右の窓は注文待ちなら残り秒と求める吸い心地（完全指定は「指定」）・作成中は残り秒・提供後は満足の顔（煙のかたちの顔・5つの表情）とドリンクの杯数。箱の下の棒は作成の進み（提供後は炭の残り）。左下の円は滞在の残り、右下の赤い札はケア・会計を待たせている残り秒。
- **右に定番の列**（最大8つ。押すと、いちばん急ぎの注文待ちの卓へそのまま出す。注文待ちの卓がある間は金に灯る）。
- **下の帯**: 左に**卓のドック**（選んでいる卓の番号・客・人数とコース・ご利用の金額）、まん中に**出来事の行**（来店・作りはじめ・客のひとこと・ケア・追加ドリンク・自然延長・会計・売上の区切り）とはじめの心の声（押すとその卓へ）、**右にフィーバーのゲージ**（3段）。

調合の窓（注文待ちの卓を押した時。時間停止）:

- 上に卓番号・客・注文の言葉と、要望の札（系統・求める吸い心地・指定・NG）。
- 左に定番（注文との合い方の印 ◎○△×）、まん中に棚（系統のタブ。客の求める系統に◎。各フレーバーに名前・タグ・4特性の目盛り。NG に当たるものは赤い枠、指定のものは緑の枠）、右にボウル（3枠）と予想、「この一台で作る」「定番に登録／外す」。

接客ビュー（ケアで、卓を押した時。時間停止。会計はひと押しなので開かない）:

- 店内がその卓へ寄る（1.3倍。選んだ卓が画面の右寄りに来る）。作成中の一台・定番の列・出来事の行は引っ込み、ほかの卓の札は薄くなる。
- 左に選択肢の列（数字キーでも選べる）。列の上の札に客の言葉・様子と顔。下に大きなドック（満足と滞在のゲージ・ご注文の言葉と出している一台・ご利用の金額）。
- 選んだあと、判定の印（◎ ○ △ ×）が列の右に大きく出て、列の上の札が客の返事に替わる。1秒で閉じ、押せばすぐ閉じる。

そのほか:

- **準備**（開店前）: 営業の種類と予報、今日の定番（4特性の目盛りつき）と釣り合いの図（4特性のレーダー）、一台あたりの原価の目安。2回目からは「定番を組む」（客のいない調合の窓）。はじめての営業は進め方を4行出す。
- **フィーバーの突入**: 「FEVER TIME!」の帯が出ている間（約1.2秒）は時間が止まり、曲が切り替わる。フィーバー中は店内に色のついた灯りが揺れ、対象の卓の札が紫に灯る。
- **精算**: 左に売上の内訳（お迎えした組・チャージ・シーシャ・ドリンク・トップ替え）と店の売上（本編の人物が来た日は、その下に一行）。右に評価のメダル、店のファンの増減と合計、満足の段ごとの組数、**好評だったミックス**（平均の満足が高い順に3つ。定番に無ければその場で登録できる）。下にいいケア・追加ドリンク・自然延長・フィーバーの数、スミさんの一言、売上ボーナス。
- PC は矢印キーで卓を移り、Enter で押す。Esc で休止／窓を閉じる。F でフィーバー。列の選択肢は数字キー。調合の窓は Tab と矢印で移り、Enter で選ぶ（定番を選ぶと決定のボタンへ移る）。
- 横持ちのスマホ（844×390）で、押す所（卓・定番・棚・タブ・決定）は実画素40px以上。`prefers-reduced-motion` では動きを止める。

## 7. 見た目の計画（専用の店内と部品）

2026-11-20 オーナー「専用の画像生成で見た目とか作って見栄えからよくしたい。内装のレイアウトは変えてもいい」「席の形は『席席席／席　席』みたいにしたい。ソファで、下の2段は内側を向いた配置で」。会話用の店内画に卓の札を重ねる今の形（`STAGES.classic`）は、絵が届くまでの仮。

- **専用レイアウト**（`STAGES.floor`）: 少し上から見た店内に、ソファの席が上に3つ・下の左右に2つ。上の3席はソファがこちら向きで卓は手前、下の2席は内向き（左のソファは右向き、右は左向き）で卓は内側。左の端が入口、右の端がカウンター（その上に定番の列が重なる）。
- **重ねる順**: 店内 → 客 → 前景（上の段の卓・下の段のソファの手前の肘掛け）→ 卓の上の一台と煙 → 番号札 → 卓の札。
- **客の絵は1枚に1人**（右斜め前向きの、座った全身）。上の席では横に並べ、下の席では奥と手前に重ね、右の席は反転して内側を向かせる。
- 位置の正本は `tonari-floor-stage.js`。配置図と画面見本（`asset_sources/ui/tonari-floor-20261120/`）は、同じ数値から `remake/test/tonari_floor_guide.mjs` で描いたもの。
- 受け口はコードに入っている: `FLOOR_ART.stage` を `"floor"` にすると専用レイアウトへ切り替わり、`FLOOR_ART.guests`（ひとりずつ。二人組は `種類-a`・`種類-b`）・`props` に絵を登録すると影絵が絵に替わる。大満足の卓は、登録があれば笑顔の絵に替わる。
- 検査: `remake/test/browser/tonari_floor.mjs` の `seated-stage`（配置図の舞台で、席の形・重なりの順・卓の札が上の帯と定番の列に被らないこと・絵の差し替え・接客ビューで卓が隠れないことを見る）。
