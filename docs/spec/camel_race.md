## 1. 現実のラクダレース（描写の根拠）

- ラクダの背には**小型のロボット騎手**。2000年代に子どもの騎手が禁じられ（UAE は2005年に18歳未満を禁止）、代わりに普及した。初期は重い試作機だったが、今は**数キロ**の軽い箱型で、スピーカー（無線）と小さなムチの腕を持つ。
- **調教師はコース横の道を走る車（SUV）から**、小さなリモコンで操作する。送れるのは**声**（スピーカー越しの声かけ）と**ムチ**（腕を回してムチを振る。ゲームではボタンを押している間だけ）だけ。画面・台詞では「合図」と呼ばない（2026-11-02 オーナー「合図って言葉がわかりずらい」）。**進行方向は操縦しない**。ラクダは自分で走る。
- 本番は4〜10kmの長距離。主人公が参加するのは**調教師が監督する、若いラクダの練習レース（1,000m・4頭）**。
- 出典: [What's On: Meet the tiny robot jockeys riding Dubai's racing camels](https://whatson.ae/2021/08/meet-the-tiny-robot-jockeys-riding-dubais-racing-camels/)、[The National: UAE camel trainers prefer robot jockeys](https://www.thenationalnews.com/uae/uae-camel-trainers-prefer-robot-jockeys-1.96956)、[PRI: Ancient tradition, modern twist — robot jockeys](https://www.pri.org/stories/2014/12/29/ancient-tradition-camel-racing-arab-peninsula-modern-twist-robot-jockeys)、[Al Jazeera: Robots ride camels in race (2005)](https://www.aljazeera.com/news/2005/07/18/robots-ride-camels-in-race/)、[CultureMap: Robot jockeys and sprinting SUVs](https://houston.culturemap.com/03-04-15-robot-jockeys-and-sprinting-suvs-bring-camel-racing-the-sport-of-sheikhs-into-the-21st-century/)。

## 3. ミニゲーム仕様（`remake/js/minigames/`）

- `camel-race-model.js`: 純粋な競走モデル（seed 固定・テスト可能）。`camel-race.js`: Canvas 描写・操作・チュートリアル・リザルト。
- 4頭（自分1＋AI3: 先行型ナジュム・追い込み型リーフ・安定型サブール）。1,000m。ラクダは自動で走る。
- 操作の考え方（2026-11-02 オーナー「ゲーム的になんかあんまり面白くなかった」「ラクダ操ってる感とかスピード感」で作り直し）: 進路は操縦しない（現実どおり）。代わりに、**声が当たるとその場で一伸び**し、**ムチは押している間だけ効く**（押す＝加速してスタミナを使う、離す＝声で息を整える）。「押して抜く→離して声で整える→スパートで使い切る」の繰り返しで、手で走らせている感じを出す。
- **声をかける（Space／左ボタン）**: 自分のラクダの背のロボット騎手を囲む金の輪が出て1.25秒で縮む。内側の輪に重なった瞬間（±0.13s）が PERFECT、±0.36s が GOOD。その場で一伸び（PERFECT +1.0・GOOD +0.8 m/s。0.8秒ほどで消える）し、調子（rhythm）が上がる（基本速度 ×0.90〜×1.04）。外れた声・同じ輪への2度目は「無駄な声」（調子−・スタミナ−3）。1.5秒に3回以上は連打（さらにスタミナ−5）。輪を見送ると調子が大きく落ちる。調子は放っておくと毎秒7%ずつ落ちる。
- **ムチ（X／右ボタンを押し続ける）**: 押している間だけ騎手の腕が回り、+3.0 m/s（残り250mの LAST SPURT では +5.0）。スタミナを毎秒13（スパートは11）使う。6を下回ると腕が止まり、22まで戻るまで使えない（押していても空ぶかしで、採点で減る）。
- **スタミナ**: ムチを入れていない間は、毎秒 2.6×調子 − 0.9 で戻る（調子0.9なら +1.4）。30未満で速度が落ち始める。
- 所要（seed 1〜60 のシミュレーション）: PERFECT＋上手なムチ（中盤は息が満ちた時だけ短く、スパートで使い切る）で約50秒・1位、PERFECT だけでムチなしは約52.5秒・2位前後、GOOD＋上手なムチは約53秒・2位前後（たまに1位）、ムチを押しっぱなしは息が切れて約54.6秒・3〜4位、無操作は約60秒・4位、連打は最下位。AI は52〜55秒でゴールする。
- **採点 0〜100**: 順位（1位40／2位30／3位20／4位10）＋声かけ（35: PERFECT 1.0・GOOD 0.6 の割合。無駄な声−2・連打−1）＋ムチとスタミナ（25: スパート区間で3秒以上ムチ8・息が無いのに押していない9・残り30以下で終える8）。**S≥85／A≥70／B≥50／C**。
- 画面の配置（2026-11-02 オーナー「順位とかのせいで画面狭いの直したい」）: 上の見出し・順位と下のボタンの帯をやめ、コースを画面いっぱい（16:9）に出して、部品はコースの上に重ねる。左上に題名と時計、上の中央に進み具合、右上に「やめる」と縦に4枚の順位（入れ替わると上下に滑る）。左下の「声をかける」に調子の棒、右下の「合図」にスタミナのゲージと消費・待ち時間を入れた。SUV は自分のラクダの少し前を走らせ、2つのボタンの間に見えるようにした。スマホでは説明の字・キー・トップとの差を隠す。
- 画面の UI（2026-11-02 オーナー「UIとかもいい感じにしたい　順位とかのやつや　ボタンとか」）: 見出しの順位は放送風の4枚の札（金・銀・銅の順位の丸、毛色の帯、トップとの差）で、入れ替わると横へ滑り、上がると緑・下がると赤に一瞬光る。コースの上の HUD は HTML（進み具合のバー・SPURT 区間・ゴールの旗、時計と調子の5本の棒、スタミナのゲージと合図の状態）で、コースの大きさ（cqw）に合わせて縮む。ボタンは調教師のリモコン風（丸いアイコン・説明・キー）で、輪が出ている間は声のボタンが光り、合図のボタンは再使用までの残りが暗く満ち、スパート区間で縁が光る。押すと判定の色で一瞬光る。遊び方は絵と3つの点、リザルトは金銀銅のメダル・スコア・評価の紋章・内訳。いちばん手前の列の足元を手前の柵より上にし、柵をラクダの後に描いて脚の前を通す（柵から飛び出して見えた不具合）。名札は SUV より上に重ねる。
- 開始前に4ページのチュートリアル（2026-11-11 に駆け引きの4ページ目を足した。初回だけ。「とばしてスタート」あり）。終了後にリザルト（順位・タイム・内訳・PERFECT等の数）と「もう一度」「終える」。
- 画面の重ね方（2026-11-02 オーナー「背景とかしょぼく見える」で改善）: 奥はレース場の朝の絵（`bg_dubai_camel_track_morning`）を1.25倍にして、奥の柵の根元を走路の奥の柵にそろえ、レースの進み具合で320pxだけゆっくり流す。走路・SUV の道・手前の砂地は、蹄の跡・砂粒・轍を描き込んだ横につながるタイル（`groundTiles()`）を速く流す。白い管の柵と支柱の影、赤い縁の距離板、市松の帯のゴール門、柔らかい砂煙、右へ伸びる影、左からの朝の光と四隅の陰り。絵が読めないときは平らな空・砂丘に戻る。PERFECT 等の文字はコースの大きさに合わせて縮む（スマホ）。
- 演出: 朝の砂漠、2層の砂丘、柵と100mごとの表示板、START／FINISH ゲートとテント、並走する白いSUV（運転席の調教師・アンテナの点滅）、各頭の砂煙、ロボット騎手（箱型・バイザー・アンテナの灯・合図で振る腕）、LAST SPURT／GOAL のバナー、ゴールの紙吹雪。`prefers-reduced-motion` では粒子とアニメーションを省く。
- 自分のラクダの見分け方（2026-11-02 オーナー「どれが自分か分かりずらかった」）: 自分は SUV が並走する**いちばん手前の列**で大きく、足元に脈打つ金の輪、脇腹に金のゼッケン（★）、名札は金の札に今の順位（「★ ハビーバ 2位」）。頭の上に金の▼（輪が出ている間は輪）。スタートまでは「あなたのラクダ ハビーバ」の吹き出しと、ファーリスの「手前の金のゼッケンがハビーバだ！」。AI は番号のゼッケン（2 ナジュム 緑・3 リーフ 青・4 サブール 紫）で、色は順位の札・名札・進み具合の点と同じ。出だしの重なる間は AI の名札を出さない。スマホでは Canvas の名札・吹き出し・順位の文字を最大1.6倍にする。
- 演出の強化（同「演出がしょぼい」）: GO で赤白の柵が跳ね上がり、4頭の足元の砂が爆ぜて画面が揺れる。声の判定は騎手の上に太い縁取りで大きく出て、PERFECT は金の火花と波紋、GOOD は水色、外れは灰の煙。2回以上続くと「n COMBO」。調子が高い間は足元から金の粒。合図は揺れ・少し寄る・後ろで砂が爆ぜる・残像2つ。速いほど速さの線が増え、スパート区間は画面の縁が夕日色。順位が上がると「2位 ▲」（緑）、下がると「▼」（赤）。助手席のファーリスの声（上の中央）が、出走・抜いた・抜かれた・先頭の交代・半分・スパート・残り100m・息切れ・5連続・ゴールの着順で入る（2.2秒に1回まで）。ゴールは白く光って揺れ、約1秒スロー。ラクダは線を越えてもゆっくり速度を落として走り続ける（見た目だけ。採点はゴールの瞬間）。1着は金の紙吹雪とファンファーレ、2〜3着は少なめ。リザルトは点数を0から数え上げ、メダルが回って出て、評価の判子を押す。

## 4. 本編への接続（`remake/js/chapters/ch4-camel-progress.js`・`ch4-camel-race.js`）

- SAVE/LOAD・中断: 会話の段階は読了ごとに保存。本番の見学は `watched` で一度だけ。レースを途中でやめれば何も消費しない。記録と消費はリザルトの「終える」の前に保存するので、結果の会話を読み切れなくても二重にならない。
- 大会: `_ch4.part`・シェイクの秘匿フラグ・大会の結果には触れない。失敗しても進行に影響しない。
- 14日化（#2297・2026-11-02 接続済み）: 新しいセーブ（`_ch4.routeVersion === 2`）は `ch4-dubai-daily.js` の日常ループの地図に `ch4_dubai_camel` を1件出す（`camelDailySpot()`。誘われるまでは「Dr.fookah の店先」、誘われたら「ラクダレース場」）。押せない理由は `unavailable`／`unavailableTag`（また明日・レースは明日の朝・レースは昼だけ・今日はもう走った）。昼の枠は `visitCamelRace()` が記録と一緒に進めて保存し、日常ループには `slotsUsed: 0` を返す（二重に進めない）。体力・能力は使わない。旧セーブ（版1の5日）は従来どおり `ch4-map-model.js` の行き先。

### 10.1 駆け引き（`camel-race-model.js` の `PACK`・`DRAFT`・`DUEL`）

- **群れで走る**: 自分より8m以上遅れたライバルは追い足を使う（最大 +1.7m/s）。8mより近づくと0なので、追い足だけで抜かれることはない。追い足で稼いだ距離は「借り」で、コースの80%から先で足が鈍って返す（追い続けたラクダは最後に伸びない）。スパート前に自分を14m以上離した先頭は少し息を入れる（最大 −0.9m/s。自分がスパート区間に入ると待たない。45m以上離れたら待たない）。
- **風よけ**: 前のラクダの 1.5〜9m 後ろにいる間、息の戻りが毎秒 +1.0、ムチの消費が3割軽い。先頭は風を受ける。息が切れて腕が止まっている間は余分に戻らない（押しっぱなしを助けない）。「後ろで溜めて、最後に差す」が選べる。
- **競り合い**: 後ろから 2.5m 以内へ並びかけると、相手が根性のぶんだけ粘る（+1.3m/s・2.4秒。ナジュム1回・リーフ2回・サブール1回。出だしの8%は起きない）。3m前へ出れば「競り勝った」。競り合いの最中に当てた声は一伸びが大きい（PERFECT +0.8・GOOD +0.4）。**競り負けたラクダは気落ちして、そのあと 0.4m/s 遅くなる**ので、中盤に競り勝っておくと最後の直線が楽になる（スパートだけムチを使うより勝てる）。
- **終盤は声が忙しい**: スパート区間（75%から）は輪の間隔が 2.4〜3.4秒 → 1.5〜2.1秒 に詰まる。縮みも速め（0.7〜1.1秒）。
- **着差**: ゴールのバナーと結果のカードに「リーフと 0.33秒差」。0.15秒以内は「写真判定」。結果の6枠は「連打」を「無駄な声」の枠にまとめ、空いた枠に「競り合い 2勝／3回」。

- **体の潰しと伸ばし（CRF03）**: 足元を軸に、PERFECT 横1.09×縦0.93、GOOD 1.05×0.96、ムチを入れた瞬間 1.12×0.9。外した声・見送りは縮み、ムチが止まると沈む。GO は4頭とも前へ伸び、競り合いは相手も伸び、競り負けた相手は縮む。声を押した最初のコマから、背中の騎手が1.22倍に跳ねる（当たり外れに関係なく）。
- **揺れの向き（CRF04）**: GO は縦（蹄）、ムチは横（前へ出る）、抜いたは横だけ、抜かれたは縦だけ、競り勝ちとゴールは両方で長く（最大 横10px・縦6px・0.4秒）、PERFECT は縦3pxを一瞬。最初が強く、すっと収まる。弱い揺れは強い揺れを上書きしない。
- **閃光（CRF05）**: PERFECT は騎手のまわりだけ金色に光る（半径190px・0.14秒。数秒に1回あるので画面全体は光らせない）。競り勝ちとゴールは最初の0.034秒だけ暗く落としてから白。ムチが止まった時は暗い赤。
- **ムチが止まった・戻った（CRF06）**: 止まった瞬間に、止め・暗く沈む・体が縮む・低い音・「ムチが止まった……」・ボタンが赤く光る。22まで戻った瞬間に、高い音・ボタンが光る・「ムチ、いける！」。
- **音の役割（CRF07）**: 録音は増やさず、同じ録音を音量と高さ（再生の速さ）で鳴らし分ける（`core/audio.js` の `playCamelRaceSe(id, { gain, rate })`）。PERFECT は続くほど高く（1回 +3%・8回まで）。ずっと鳴る蹄は0.55倍に下げ、速いほど高い。見送りは低く、息の注意は小さく高く、競り合いの始まりは高い角笛、競り勝ちは追い抜きの音に高い鐘、先頭は高く大きく、抜かれたは低く小さく。
- **スタート（CRF08）**: 合図の数字は替わるたびに弾む。同じ訪問の2本目からは1.5秒（3・2・1・GO の並びのまま速く。最初の1本は3秒）。スタート前に声を押すと、ボタンが沈んで騎手が跳ね、はじめが「まだだ……」（判定・消耗なし）。ムチを押したまま GO を迎えると、そのままムチが入る。
- **ゴールの余韻（CRF09）**: 記録はゴールした瞬間に入る。余韻（スロー込みで約2.3秒）は、0.7秒たてば画面タップか Space で結果へ飛ばせる。ゴール後の「やめる」は閉じずに結果へ進む。**ゴールした走は、余韻の途中で閉じても完走として返る**（本編では昼の枠を使い、記録に残る。それまでは余韻の途中で閉じると走り切った記録が消えていた）。レースの途中でやめた時は、今までどおり何も消費しない。
- **次の目標（CRF10）**: 結果のカードに「次の評価 A まで あと ○点」と、いちばん点を落とした所の直し方を1つ（例「伸びる所：GOOD を PERFECT に（今回 GOOD 20回）」）。標準・上級・入門で条件に届かなかった時は、足りない条件を「✓ 3位以内　✗ 声かけ 18／20点」のように並べる。助言は地の文（人物の台詞にしない）。計算は `camel-race-feedback.js` の `camelNextGoal`。
- **抜いた・抜かれた（CRF12）**: 抜いた瞬間は止め・横の揺れ・前へ出る動き。抜かれた時は縦に小さく揺れ、低い音。
- 動きを減らす設定では、止め・揺れ・閃光・潰し伸ばし・前へ出る動きを使わない（音・文字・ボタンの光は出る）。
- 入れていない案: 声の判定幅やスタミナの数値でリスクとリターンを強める（§10.1 の実測＝誰が勝てるか・中級認定 60/60 が動く）。スタートの合図をボタンで飛ばす（合図の音が3拍）。
- 検証: `camel_race_feedback.mjs`（`camelNextGoal`）、ブラウザの `camel_judge_feedback.mjs` に、止めの間は時計が進まずムチが入る／余韻を飛ばしても記録は1件／2本目の合図は1.5秒／ゴール後の「やめる」は結果へ／ムチが止まった・戻った合図／動き軽減では止めない、を足した。
