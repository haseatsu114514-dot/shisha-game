## Git の手順

1. 作業場所は正規のチェックアウト（`shisha.canonicalRoot` に設定されている shisha-game）。空のフォルダや
   `/Users/hasegawaatsuki` では作業しない。
2. `git status` が clean か確認する。未コミットの変更があれば何もせず止まって報告する（別の作業の途中の可能性がある）。
3. 安全確認の「`project.godot` があること」は古いルール（Godot版は2026-06-15に削除済み・今はブラウザ版のみ）。
   代わりに `web/`・`data/`・`assets/` があり、`./tools/check_git_safety.sh` が通ればよい。
   それ以外の確認（repo root・hooksPath・canonicalRoot）は通常どおり行う。
4. `git fetch origin claude/admiring-goodall-m9bdg3` → `git checkout claude/admiring-goodall-m9bdg3`
5. 画像を生成して保存 → 追加した PNG だけを `git add` してコミット → このブランチへ push
6. main への push・マージ・`--force` は禁止。PRは作らない。main をこのブランチに取り込む必要もない。
7. 終わったら、ローカルは作業前のブランチ（通常は main）に戻す。

## 画像の共通ルール

- **背景は完全な単色マゼンタ(#FF00FF)**（7/7 の地面だけは全面が地面なので不要）。透過はこちらでやるので、AIに透過させない。
- ドットの粗さはこちらで揃えるので、普通の画質で生成してよい。
- 画風参考: `assets/backgrounds/bg_eden_shop.png` を第一基準にする。温かい照明の2Dドット絵〜ピクセルペインター調で、
  輪郭・影・質感に細かいドット感を残す。リアル写真調や滑らかすぎる3D調にしない。
  シーシャ台の先端は小さい凸型の金属ポストにし、凹んだカップ型・ボウル一体型・大きな先端パーツにしない。
- 文字・ロゴ・数字・透かし・フレーム・マスの区切り線を入れない。影を背景に落とさない。
- 特定の既存ゲームの模写はしない（一般的な「16bit時代のレトロJRPG」の画風で）。
- 各画像は最大3回まで作り直してよい。作り直した回は `_try2`・`_try3` のように連番で残し、
  一番良いものを指定のファイル名で保存する。
