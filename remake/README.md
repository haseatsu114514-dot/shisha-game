## 作り直しの方針（旧版との違い・2026-10-07に旧 `web/` 削除済みの履歴）

| 観点 | 旧版 `web/` | リメイク版 `remake/` |
|---|---|---|
| コード構成 | `game.js` 1ファイル約9,000行（512KB） | 責務ごとのESモジュール（1ファイル数百行まで） |
| データ | `build_data.py` で `data.js` に束ねる（要ビルド） | `data/*.json` を**実行時に直接読む**（台詞の正本は共有＝二重管理なし） |
| 進行の書き方 | コールバックの入れ子 | `async/await` で章の台本を上から読める形に |
| セーブ | 継ぎ足しの互換コード多数 | スキーマ版数つき `state` ＋ `migrate()` 1か所 |
| 大会 | 既存工程に仕様を後付け | `docs/master_spec.md` 第2部（穴あけ/炭焼き/調整2回/10カウント）を**最初から**設計の軸に |
| 画面 | 固定16:9 | 固定16:9（1280×720論理座標）＋煙ワイプ遷移を共通化 |
| 見た目 | 墨×金＋LINE風スマホ＋看板型マップピン | **日常パートは旧版のデザインを踏襲**（オーナー指摘で揃えた・下記）。大会は紫／真鍮／銀の制作UIに統一 |
| 書体 | 端末任せ（明朝・ゴシック・ドット等が混在） | **Zen Kaku Gothic New の1書体に統一**して同梱（`remake/fonts/`・SIL OFL）。外部フォントは読まない |

日常パートの見た目は旧版と同じ語彙に揃えている（「スマホとアイコンのセンスが悪くなった」の指摘を受けて）。
別の見た目を足すときもこの語彙から外さない:

- **HUD**: 左上に墨×金の DAY カード（角飾り）、右上に体力・★段階の五角形・アプリ風の LIME・MENU（`daily/hud.js`）

- **報酬通知**: ステ色（`--stat-*`）の漢字バッジのカード／好感度は顔ドット絵＋ハート（`core/ui.js` の `gainCard`）
- 顔アイコンは `assets/ui/face_icons/`（48px ドット絵）。`assets/ui/ui_*.png` は仮の色板なので使わない
- 外側の窓はラウンジの金縁を使い、窓の中のタブ・操作ボタン・小さな札は `css/ui-inner.css` の墨色と細い真鍮色の線で揃える。短い操作の文字は中央、説明付きの行動は左端を揃える。ステータスの情報・説明はグラフと5項目の下にまとめ、ショップはDAYカードの下から表示する

- 日付・所持金のHUDは300pxの固定幅。体力欄は最大体力に合わせてゲージと外枠が一緒に伸びる（残量が減っても器の幅は維持）。所持金は上限999,999円で、HUDはその桁数に合わせた20pxの文字。日常はDAY1〜13、大会はDAY14で、HUDと台詞の残り日数は同じ大会日を参照する。体力ゲージは最大値に対する残量が50%超=緑、25%超〜50%=黄、25%以下=赤。好感度・絆の通知は同じ相手への連続加算を700msで一枚にまとめ、実際の点数と端数は加算時にそのまま反映する
- 大会当日のカウントダウンも「次の大会まであと0日」。スロット横のエリア名・時間欄と筐体下の名前プレートは出さない
- 地図は墨色の共通面と銀の縁に、能力の色と被らない役割別の差し色（キャラの店=スチール／家・拠点=アイボリー／その他=石墨／ショップ=茶系／大会会場=銀白）。能力バッジは読みやすい角ゴシックの「技・感・根・魅・察」を項目色の控えめな四角い枠に重ね、正式名を併記する（アイコン案と比較してオーナーが選択）。洞察は青緑、体力回復は黄緑で区別し、能力アップ通知は実際の増加量を `+NP` で表示。能力アップの各色の面には煙マークを付けない。通知からHUDグラフの対応する頂点へ色の光を運ぶ（動きを減らす設定では光の移動を省略）

## 自由行動の成長

初期所持金は30,000円。能力は自分で選び実際に体力を消費した行動だけで育つ。
`core/stats.js` の `paidAction()` が台本・訪問の `earnStat()` / `applyStats()` を預かり、行動終了時に1能力につき実増加1P、最大2能力で確定する。
会話後に体力を使う約束も対象。強制イベント・チュートリアル・LIME・回復には加算しない。
バイト後の無料会話は同じ成長枠、追加体力を使う自主練は成功時2能力各1P・失敗時技術1Pの別枠。確定済みの能力加算だけを `gainStat()` が担当し、通常のゲーム内報酬から直接呼ばない。
初回・繰り返し・質問回も同じ1Pルール。同じ能力の報酬候補は重複加算せず、元の数値は候補の優先度に使う。章上限は48／66／82／90／100、★帯の減衰は廃止。既存セーブの現在値・所持金を保持し、旧経験値の端数は進捗率へ移行する（schema9）。
スロットの `onAction({ spent })` には実際の消耗を渡す。回復や強制案内では回さない。
スロットはハズレ／リプレイ1P、チェリー2P、ベル3P、REG16P、BIG／プレミア24P、フリーズ36P。確率・天井・再遊技・救済はそのまま。
成長通知は **STATUS UP** の下に能力名と実増加の **+NP** を置く。Pも数字と同じ19pxの大文字にし、21pxの能力名のすぐ右へ寄せる。漢字は黒い枠の中央へ揃える。煙なしの元の金属枠・漢字銘板・5色を維持し、通常272×68px。進化時だけ **LEVEL UP**・進化・短い恩恵を添え、スロットは **SLOT BONUS**。スロットの通知は同じ位置で枠が一度明るくなり、短い控えめな専用音を添える。ランク名はステータス画面で確認する。
全能力MAXは第5章で育成を重ねて狙う。第3章の必須ルートは帰郷まで接続済み。第4・5章の数値は成長モデルの検証値で、後続の心得の盤（`docs/stat-design/`）で見直す。[表示・バランスと検証記録](../docs/compact_gains_and_growth_20261008.md)。

マップでは店名＋「へ行く」を顔の下に、施設名を大きな記号の下に置く。顔は52px、新しいイベントだけ字面を中央に揃えた丸い「！」を表示する。既読・凛の不在日・定休日・臨時休業は印の対象外。SHISHARKは第2章になるまで地図へ出さない。

## タイトルのメディアギャラリー

GALLERYの「すべて／スチル／チェキ／プリクラ／漫画／ムービー」から閲覧する。

今回制作した漫画は未採用、ムービーは準備中。`data/gallery.json` の `items` は空で、候補画像を本編へ登録していない。

採用後は `remake/data/gallery.json` の `items` へ、次の形で1作品ずつ追加する（下記は形式例であり未登録）。

```json
[
  { "id": "comic_example", "kind": "comic", "title": "作品名", "approved": true, "requiredChapter": 3, "pages": ["img/comics/example-01.webp", "img/comics/example-02.webp"] },
  { "id": "movie_example", "kind": "movie", "title": "作品名", "approved": true, "requiredChapter": 2, "src": "movies/example.webm" }
]
```

- `approved: true` と `requiredChapter`（1〜5）が必須。未採用作品は一覧へ出さない。
- 複数章の人物や内容を含む場合は最も遅い必要章を指定する。複数の漫画を画像1枚にまとめる場合も、全話に必要な章で解放する。
- 配信画像は `img/`、動画は `movies/`、または採用した `../assets/` 内の素材を指定する。原画保管用の `asset_sources/` は参照しない。漫画はPNG/WebP/JPEG、動画はWebM/MP4。
- 未クリアの作品は題名・絵を隠し、必要なクリア章だけを案内する。漫画のページは指定順。画像の左右反転はしない。
- 章クリア・受取写真の端末内記録は `suien_remake_gallery_progress`。既存の見たCG記録 `suien_remake_gallery` を保持し、保存枠からの補完は読取だけで行う。
- 漫画はページ送りと拡大スクロール、動画は操作して再生。閉じると動画の読み込み・再生を止め、元のBGMへ戻す。

検証: `node --experimental-vm-modules remake/test/gallery.mjs` と `CHROME_EXECUTABLE_PATH=/usr/bin/chromium node remake/test/browser/gallery.mjs`。

## 共通ロード画面と２コマ漫画（導入用の基盤）

`/remake/loading-preview.html` で、漫画なし・２コマ仮枠・短い処理・失敗・中断を確認できます。本編の大会・練習で最初に作業台を開く際、220msを超える準備を共通ロード画面で待ちます。同じ一台の工程間・会話からの復帰は既存の小さな表示を維持します。プレビューはセーブ・設定を書き換えません。

`js/core/loading.js` の `withLoading(prepare, options)` は、渡された準備処理の完了を待つ共通ゲートです。呼び出した直後から背面の操作を無効にし、220ms以上かかると表示します。短い処理には待ち時間を足しません。必要な準備が完了するまで進行せず、失敗時はrejectして画面・操作・フォーカスを復元します。再試行や元の場面への復帰は呼び出し側で扱います。中断は `AbortSignal` を渡し、準備処理もsignalを確認してください。中断後に古い場面を描画しないよう、画面切替・時計の開始は必ずゲートのawait後に行います。同時に複数のゲートを開く呼び出しは拒否します。

```js
import { withLoading } from "./core/loading.js";
import { loadingPrefetch, prepareImage } from "./core/loading-prefetch.js";

// 前の会話・章カード等を見ている間。失敗はfalseとなり、必要時に再試行可能。
void loadingPrefetch.warm("craft:setup:asset-version", () => prepareImage(nextImageUrl));
// 実際に必要になったとき。同じキーの準備結果／進行中Promiseを再利用。
const image = await withLoading(async ({ report }) => {
  const result = await loadingPrefetch.prepare("craft:setup:asset-version", () => prepareImage(nextImageUrl));
  report(1, 1);
  return result;
}, { context: "craft", chapter: 1 });
// ここで画面を描画し、操作タイマーを開始する。
```

先読みキューは同時2件・保持と待ち行列の合計24件まで。成功した結果は古い順に手放し、失敗は再試行できます。満杯時の `prepare` はreject、`warm` はfalseです。キーには章・対象素材・必要な差分を含め、セーブ状態を変更しない準備だけを登録します。共有中の先読みは画面側の中断では止めず、その結果を再利用できます。画像は読込＋decodeを待ち、既定8秒で失敗を返します。既存の `warmCraftAssets`・`imageReady` 等も、必要な成功判定を呼び出し側で行ったうえでゲートへ渡せます。falseを返す既存ローダーの結果を無条件に成功扱いしないでください。

漫画は `js/core/loading-comics.js` へ、記載した形式で採用素材を登録します。２枚の画像と読み順に沿ったalt、章の下限、必要なら表示contextを指定します。横並びの左→右で表示し、全体は既存の1280×720と同じ比率で拡縮します。２枚ともデコードできた漫画だけを表示し、未登録・取得失敗・画像待ち4秒超過では通常表示に戻ります。漫画の通信を理由に処理完了を遅らせません。直前と同じ漫画は、他の候補があるときは避けます。漫画の選択はセーブに記録せず、ゲームの乱数・進行には影響しません。

### 画面レイアウト（2026-10-28 #1153 オーナーのモックアップ準拠）

上から順に、上中央のロゴ（カード上端にわずかに重なる）→ ベージュの紙面（題名＋２コマ＋任意の一行解説）→ カードより短い発光する進捗バー → 非イタリックの「LOADING…」＋煙飾りを縦に並べます（構成はオーナーのモック準拠。設計根拠は `work/claude-loading-design/DESIGN.md`）。ロゴ・バーの色・背景は**仮素材**で、`css/loading.css` の `.loading-gate` 冒頭に置いた CSS 変数（`--loading-logo` / `--loading-bar-gradient` / `--loading-backdrop`（背景の下地色）/ `--loading-backdrop-art`（背景イラスト。既定 `none`）/ `--loading-backdrop-art-pos` / `--loading-backdrop-fx`（CSS の窓・煙装飾の強さ。イラストを入れたら `0`））を**1か所書き換える**だけで差し替えられます（オーナーの正式画像が来たらここだけ変更）。寸法は 1280×720 基準の単位 `--loading-unit` でゲート実寸へ相似縮小され、カード幅は高さ連動の上限も受けるため、低い横画面でも全体が見切れません。進捗バーは `report(done, total)` の実数に追従し、`LOADING…` の煙は数字「3」に見えないよう離れた3本の立ち上りにしています。スマホ横はPCと同配置、スマホ縦は２コマを縦積みにして吹き出しが読める大きさを保ちます（ゲームは縦向きでは横向き推奨の案内を出します）。

**読む時間の確保**: 漫画が実際に画面へ表示された場合に限り、準備完了後に「タップ・クリック・キー（Enter／Space）で進む」読む時間の保持を入れます。漫画が出ていない・取得失敗・短い処理のときは従来どおり待たせずに進みます。保持中も #1038 のゲート（背面操作の無効化・中断・フォーカス復元・低減モーション）はそのまま有効です。

**コマの作画サイズ仕様（発注用）**: 1コマは **1920×1080 基準で 860×573px（アスペクト比 3:2）** を基準に作画してください。全コマ共通の固定表示枠が 3:2 で、原画が 3:2 以外でも**レターボックス**で収める（引き伸ばさない）ため、余白が出ないよう 3:2 での作画を推奨します。`region` で大きな原画シートの一部を切り出す場合も、切り出した領域の比率はそのまま保たれ、3:2 枠の中に歪みなく収まります。安全マージンとして、枠の縁から内側に **各辺 4%（約34×23px @860×573）** は吹き出し・重要な線を置かないでください（枠の縁で欠けないため）。

**表示枠とコマ規格の照合（2026-10-29 改訂）**: 表示枠は 43:25 から **3:2** へ変更されました（オーナー決定・案A。制作リファレンス `work/loading-comic-ref/REFERENCE.md` §2.1／`REF-RESEARCH.md` が根拠）。制作側のコマ規格も左右共通 460×307（3:2）に統一されています。採用済み第25話の切り出し（左 486×307・右 565×307）と Batch 1『炭の耳』（510×399・520×399）は旧規格の登録のままで、作り直しは不要です。表示はレターボックスで吸収します（第25話は左が高さ約95%・右が約82%、Batch 1 は幅約85–87%。切り取り・引き伸ばしはしません）。登録データが枠と食い違わないよう、`remake/test/loading_comics_spec.mjs`（CI quick）が region の比率帯（1.2〜2.0、3:2 を含むため帯自体は不変）を検証します。

**進捗バーの挙動**: バーは `report(done, total)` の実績が届くまでは不確定表示（割合を示さない）で、最初の実績から実数に追従します。実績を報告しない呼び出し（作業台の入場など）では、完了まで不確定表示のままになります。準備完了後の読書ホールド中は 100% で静止します。

**漫画データ形式**（`loading-comics.js`。各コマの `region`・`bubbles`・漫画の `caption` は任意）:

```js
{ id, title, minChapter, contexts?, note?,
  caption?: "初心者向けの一行解説（コマの下に表示）",
  panels: [ {
    src, alt,
    region?:  { x, y, width, height, sourceWidth, sourceHeight }, // 原画シートの切り出し
    bubbles?: [ { text, x, y, width?, fontSize? } ],              // 吹き出し画像の上にゲーム内テキストを重ねる

```

`bubbles` を使うと、吹き出しの**形は画像**に描き、**台詞はゲーム内テキスト**で重ねられるので誤字を後から直せます（`x`/`y`/`width` はコマ枠に対する%、`fontSize` は `cqw`）。従来どおり**文字入り画像の漫画**（`bubbles` なし）もそのまま使えます。シリーズ名・コマ番号・確認ボタンは表示しません。準備中はスキップできません。

### ロード／先読みを置く候補（提案）

| 優先 | 場所 | 先読みを始める時点 | 表示して待つ範囲 |
| --- | --- | --- | --- |
| 高 | 章の開始・セーブからの再開 | 章カード／ロード枠選択後、再開先が確定した時 | その章の台本と最初の背景・登場人物だけ。全章をまとめて読まない |
| 高 | 大会・通し練習の制作開始 | 大会前の会話／準備メニュー中 | `craft/readiness.js` が持つ最初の工程の素材。次工程は操作中に先読みし、時計は準備後に開始 |
| 中 | 初めて入る街・大型施設 | 行き先確定後の電車／扉の演出中 | 到着先の地図・背景・最初の会話だけ。既存演出で間に合えばロード画面不要 |
| 中 | ミニゲーム初回・映画等の大型メディア | 施設内メニュー／説明を読んでいる間 | 選んだ遊びの画像・モジュール・必要な音声。再生開始は実際の準備完了後 |
| 低 | 通常会話の表情・日々の地図 | 会話中／タイトル中の既存先読みを継続 | 日常のテンポを保つため、通常は既存の小さな待機表示だけ |

**制作開始の初回準備には接続済み**です。他の候補は通信制限下で待ち時間を測ってから追加します。起動直後は漫画自体の追加読込が負担になるため優先しません。重い同期CPU処理をPromiseで包んでも描画は止まるので、Worker化か小分けにしてイベントループへ戻す必要があります。`delayMs: 0` なら準備処理を呼ぶ前にゲートを描画するフレームを確保できますが、処理中の描画停止そのものは解消しません。


### 接続済みの漫画とゲーム内プレビュー

`/remake/craft-preview.html?loading=comic` は、本編と同じ `openBench` → `prepareBenchEntry` を通り、漫画付きロードから実際の制作画面へ進めます。確認用の追加素材待ちだけを約2.2秒挟み、本編には固定の待ち時間を加えません。通常の制作試遊は `?loading=comic` を付けずに開けます。ゲーム内のセーブ・設定は変更しません。

既存の「けむりのとなり 暴走編」第25話「メニュー改訂」をロード用に採用しました。原画は `asset_sources/short-comics-unhinged-ltr-20261025/25-28-chaos-ltr.png`、配信用は `img/loading/adam-chaos.webp`（約489KiB）です。原画の文字・絵・左右は変更せず、CSSの表示領域で25話の２コマだけを左→右に表示します。シート内の他の３話は表示しません。番外編の位置づけは素材台帳で管理し、ギャラリー全体の作品採用には広げません。

ロードの見せ方は『あつまれ どうぶつの森』の右下に小さく出る島アイコンの配置を参考に、中央の漫画へ視線を集め、待機表示だけを画面の隅へ寄せています（[任天堂の案内](https://www.nintendo.com/en-gb/Support/Purchases-Subscriptions/Games/How-to-Back-Up-and-Restore-Island-Save-Data-Animal-Crossing-New-Horizons--1818137.html)でも右下の島表示を説明）。固有のアイコンは流用しません。現在は本編の紫・既存の煙モチーフ・一枚の紙面で構成し、待機表示は独自の煙の線と「LOADING…」だけです。低減モーション指定では登場アニメーションと煙の動きを止めます。


### 市販ゲームのロード画面から採った方針

文字の少なさに加え、ゲーム固有の図形・素材感・動きをロードにも通す方針です。下表の「取り入れる点」は本作向けのデザイン判断であり、他作品の画像・ロゴ・アニメ素材は同梱しません。

| 調査対象と参照資料 | 確認できる事例／取り入れる点 |
| --- | --- |
| [Persona 5・Easy Alliesのレビュー](https://easyallies.com/review/persona-5) | 主人公の回転する絵と短い待機表示。汎用の点から、作品固有の煙のマークへ置き換える参考 |
| [NieR:Automata・ロード画面のUI事例](https://interfaceingame.com/screenshots/nierautomata-loading/) | 本編のUIとロード画面の関係を比較。ロードだけ別のWeb部品に見せず、色数・線・余白の規則を本編と揃える参考 |
| [Hades・ロード画面のUI事例](https://interfaceingame.com/screenshots/hades-loading/) | ロードを一枚の画面として構成する参考。画像を二つ独立して置かず、一枚の紙面としてまとめる |
| [ウマ娘・公式の4周年案内](https://dmg.umamusume.jp/news/detail/?id=2419) | ロード中の「1コマ」「ヒミツ」を公式が案内。キャラの短編を待ち時間のコンテンツにする方針の参考。表示要素を増やす根拠にはしない |

本作は、既存漫画の暖色に合わせた紙の縁、背面の低彩度の紫の面、既存の煙の図形、小さく動く煙の待機マークでまとめています。漫画の文字・絵・読み順は変えません。紙面の上部には各話の題名だけを添え、説明文は追加せず、準備完了時の自動遷移も維持します。登場は160〜260msで、待機の最低秒数や読了の確認は追加しません。

比較入口は `/remake/craft-preview.html?loading=comic`（紙面と煙の表示）と `/remake/craft-preview.html?loading=comic&look=plain`（前の表示）。上のリンクで往復できます。旧表示の切り替えは試遊ページ内だけで、本編の設定やセーブには追加しません。
