2026-10-12の配合別温度帯（#401、オーナー承認済みゲーム内モデル）:

- `temperature-model.js` が選択中の葉の既存 `heat_tolerance` を正の有限なgで加重平均し、倍率tを算出。緑 `[.42*t,.66*t]`、虹 `[.49*t,.59*t]`、中心 `.54*t` を配合プレビュー・蒸らし・吸い出し・提供・調整・判定・採点・背景・autoで共用する。
- 同比率で総gだけを変えても帯は同じ。総gは従来の温まり方に影響する。空配合はt=1、未知の葉や未定義/不正な耐熱性はその葉の倍率1。旧セーブに新しい温度帯フィールドを要求せず、共有定数を上書きしない。
- 危険 `.90`、爆発 `1.0`、冷え切り `.06` は絶対値を維持。演出の旧 `.76` は緑上端〜危険 `.90` の中の相対位置へ移し、高耐熱の葉が適温のまま過熱表示や熱すぎる吸引ペナルティを受けない。
- `node remake/test/mix_temperature.mjs` と `node remake/test/browser/mix_temperature.mjs` で全フレーバーの境界、実g操作から提供/調整、支給ミント、旧データ、採点、演出、auto、セッション分離を検証する。CI: `.github/workflows/mix-temperature.yml`。

## 作り直しの方針（旧版との違い）

| 観点 | 旧版 `web/` | リメイク版 `remake/` |
|---|---|---|
| コード構成 | `game.js` 1ファイル約9,000行（512KB） | 責務ごとのESモジュール（1ファイル数百行まで） |
| データ | `build_data.py` で `data.js` に束ねる（要ビルド） | `data/*.json` を**実行時に直接読む**（台詞の正本は共有＝二重管理なし） |
| 進行の書き方 | コールバックの入れ子 | `async/await` で章の台本を上から読める形に |
| セーブ | 継ぎ足しの互換コード多数 | スキーマ版数つき `state` ＋ `migrate()` 1か所 |

## 自由行動の成長

初期所持金は30,000円。能力は自分で選び実際に体力を消費した行動だけで育つ。
`core/stats.js` の `paidAction()` が台本・訪問の `earnStat()` / `applyStats()` を預かり、行動終了時に1能力につき実増加1P、最大2能力で確定する。
会話後に体力を使う約束も対象。強制イベント・チュートリアル・LIME・回復には加算しない。
バイト後の無料会話は同じ成長枠、追加体力を使う自主練は成功時2能力各1P・失敗時技術1Pの別枠。確定済みの能力加算だけを `gainStat()` が担当し、通常のゲーム内報酬から直接呼ばない。
初回・繰り返し・質問回も同じ1Pルール。同じ能力の報酬候補は重複加算せず、元の数値は候補の優先度に使う。章上限は48／66／82／90／100、★帯の減衰は廃止。既存セーブの現在値・所持金を保持し、旧経験値の端数は進捗率へ移行する（schema9）。
スロットの `onAction({ spent })` には実際の消耗を渡す。回復や強制案内では回さない。
スロットはハズレ／リプレイ1P、チェリー2P、ベル3P、REG16P、BIG／プレミア24P、フリーズ36P。確率・天井・再遊技・救済はそのまま。
成長通知は **STATUS UP** の下に能力名と実増加の **+NP** を置く。Pも数字と同じ19pxの大文字にし、21pxの能力名のすぐ右へ寄せる。漢字は黒い枠の中央へ揃える。煙なしの元の金属枠・漢字銘板・5色を維持し、通常272×68px。進化時だけ **LEVEL UP**・進化・短い恩恵を添え、スロットは **SLOT BONUS**。スロットの通知は同じ位置で枠が一度明るくなり、短い控えめな専用音を添える。ランク名はステータス画面で確認する。
全能力MAXは第5章で育成を重ねて狙う。第2章以降はまだ未接続なので、5章の調整結果は成長モデルの検証。[表示・バランスと検証記録](../docs/compact_gains_and_growth_20261008.md)。

マップでは店名＋「へ行く」を顔の下に、施設名を大きな記号の下に置く。顔は52px、新しいイベントだけ字面を中央に揃えた丸い「！」を表示する。既読・凛の不在日・定休日・臨時休業は印の対象外。SHISHARKは第2章になるまで地図へ出さない。
