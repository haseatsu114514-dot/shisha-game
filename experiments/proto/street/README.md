## 第1章での限定試験（2026-10-13・#456）

## 高解像度2.5D版（`?stage=hd`・AA9）

| | 標準 | 高解像度2.5D |
|---|---|---|
| 内部解像度 | 320×180 を4倍 | 640×360 を2倍（1ドットが半分の細かさ） |
| キャラ | 32px | 48px（5方向＋左右反転・2コマは同じ。オーナー選択） |
| 建物・小物・地面 | 元画像の約0.22倍 | 同じ元画像から約0.35倍（ドア56ドット・建物は最大172ドット）。追加の生成なし |

| ステージ | `stage_hankagai.json` | `stage_hankagai_hd.json`（標準版を `extends` して配置と大きさだけ上書き。テキストは標準版の1か所だけ） |
| 素材 | `assets/proto_street/` | `assets/proto_street_hd/`（`python3 tools/proto_street_assets.py --profile hd`） |

## ハリボテ背景版（`?stage=set`・AA11）

エリアマップ右上の「画質」で「ハリボテ」を選ぶ（URLに `?stage=set` でも同じ）。標準版・高解像度版はそのまま残している。

- 背景は Codex が描いた**画面1枚分のパネル×3枚（昼・夜）をつないだ一枚絵**（1840×360）。空・建物・歩道・車道まで描かれていて、その上をキャラが歩く
- キャラは元の歩行シートの細かさのまま**72ドット**（つむぎ・通行人2人とも既存のシートから変換。生成し直していない）
- 自販機・ベンチ・立て看板・植木・街灯・自転車は別の画像（Codexの小物シート）で、足元のyで前後に回り込める
- 手前を横切る電柱も Codex の画像（ぼかして、通りより速く動かす）
- 夜は夜のパネルに切り替え、少し暗くしてから窓・看板・ランタンの灯りを戻す。人と小物は別のレイヤーで夜の色に合わせる（窓の光が人の上に乗らない）
- ドア・看板の位置は `stage_hankagai_set.json` に、つないだ一枚絵の上で測った値で書いてある（パネルを作り直したら測り直す）
- 変換: `python3 tools/proto_street_assets.py --profile set`（パネルは各端の「建物の隙間」で重ね、左右の色が一番そろう上→下の切れ目で切り替える。全体を半透明で混ぜると塀や木が二重に見えるため）
- キャラ: `python3 tools/proto_walk_sheet.py --sizes 72 --colors 64 --no-preview`（つむぎ）／通行人は `--out-dir assets/proto_street_set --sizes 72 --colors 64`

既知の問題（ハリボテ版）:
- パネル同士の継ぎ目（建物の隙間の奥の景色）は、よく見ると木や家の並びがずれている
- 歩道の手前の方を歩くと、スマホでは右下のボタンにキャラが隠れることがある
- コードで描く小物（柵・道しるべ・「！」）は2倍で描いているので、背景よりドットが粗い
- 柵・道しるべ・「！」・砂ぼこりなどコードで描く小物は、標準版の絵を1.5倍で描いているので、画像よりドットが粗い

## 操作

- 移動: 矢印 / WASD（8方向）。地面をタップ（押したままドラッグ）でそこへ歩く。歩く速さは80ドット/秒
- ダッシュ（140ドット/秒）: Shift を押しながら移動／遠く（72ドット以上先）をタップ・ドラッグ／
  右下の「ダッシュ」ボタンをONにすると常に走る（ON/OFFはこのブラウザに記憶）。走ると足元に砂ぼこり
- 決定: Z / Enter / Space（入る・しらべる・話す・文送り）。対象があると頭上に「！」
- 閉じる: X / Esc。マップ（ファストトラベル）: M、または右下の「マップ」
- 入口・人・物をタップすると、その前まで歩いてから自動で決定する
- 通りの左端（「◀ エリアマップへ」の道しるべ）へ歩くとエリアマップへ戻る
- ファストトラベルは「通りの入口」と**一度入った店の前**だけ選べる（未訪問は「？？？」）

Codex から届いた注意点への対応:

| 注意点 | 対応 |
|---|---|
| 背景のマゼンタに色むら（#FF00FF からの距離が最大で約50） | `key_background()`: 距離75以内を背景、背景に接した縁だけ半透明にして色を戻す。絵の内側は距離に関係なく不透明のまま（PEPPERMINT のピンクのネオン〔距離100以上〕が抜けない）。自転車のスポークの間・ツタの隙間の背景も抜ける |
| シート寸法が列数・行数で割り切れない（1649×954 など） | 等分せず、塊（キャラ・建物・小物）を見つけて位置から並びを決めて切り出す |
| 建物のドア寸法 | 元画像のドアは高さ144〜169px（±8%）でばらつく。建物ごとに「ドアの高さ36ドット」になる倍率で縮め、建物の高さは110ドットで頭打ち → ゲーム内のドアは33〜36ドット（キャラは32ドット＋輪郭） |
| 学生のスマホの持ち手 | 正面・右・右上・背中は右手、**右下向きだけ左手**（採用版・試行版3枚とも同じ）。左向きは右向きの反転なので、左下は右手・左上は左手になる。32ドットではスマホが2〜3ドットなので目立たないが、気になるなら右下の列だけ作り直す（下の「既知の問題」） |
| 横・斜めの歩行コマ差 | 横・斜めは「踏み出し ⇔ すれ違い」の2コマで、歩いて見える（そのまま）。**背中向きは3人ともコマA・Bで同じ足を上げていて交互に見えなかった**ので、`--mirror-step up`（既定）でコマBを「コマAの脚だけ体の中心線で左右反転」して作り直した（カバン・スマホは入れ替わらない） |

縮小で元絵の黒い輪郭がぼやけて歩道の上で埋もれるため、歩行シートには外周1ドットの輪郭を足している（`--no-outline` で外せる）。

## 歩いた所感

- 速さ: 最初は64ドット/秒で、入口から一番奥の KEMURIKUSA まで約13秒かかり遠かった。オーナーの指摘（AA7・AA8）で

- 長さ: 画面約3枚・入れる店3つで「散歩」として間延びしない。これ以上長くするなら、途中にしらべる物か通行人をもう1つ置きたい
- ドアとキャラの比率: ドア33〜36ドット／キャラ32ドット（頭身2.5）。並ぶと「少し大きめのドア」に見えて自然
- 退屈にならないか: 1日に何度も通ると、しらべるテキストと通行人の台詞が固定なのですぐ見飽きる。
  本編に入れるなら、曜日・昼夜・章で台詞が変わる、通行人が日替わりで入れ替わる、くらいの変化は要る
- カメラは歩く向きの先を少し多めに見せる（先読み32ドット・走っている間は約45ドット）。横に長い通りでは先が見えるほうが歩きやすい

## 本編に組み込む場合（見積もり）

組み込み先はリメイク版（`remake/`・main に統合済み）を想定。旧版 `web/` は削除済み。

- **接続点**: リメイク版の `remake/js/daily/map.js` の `chooseSpot()` は「選ばれたスポットIDで解決する Promise」を返す。
  これを「エリアを選ぶ → 通りを歩く → 入口に入ったらそのスポットIDで解決」に差し替えれば、その先（会話・バイト・大会）は今のまま動く。
  入口ごとに `spotId` を持たせ、定休日・「今日はもう行った」・お金が足りない（`availability()`）は入口で一言出して入れなくする
- **時間の消費**: 歩くだけでは消費しない。入店して行動したときだけ今と同じく1コマ消費
- **テスト**: 通しテスト（`remake/test/playthrough.mjs`）は、通りを歩かずに入口へ入るデバッグ入口（`__street.warp` 相当）か、
  「ピンのマップに切り替える」設定を用意すれば今の手順を保てる
- **素材（1エリアあたり）**: 建物シート1〜2枚（6〜12棟）、小物シート1枚、地面1枚、通行人の歩行シート2〜3枚。
  ほかに一度だけ、主人公はじめのマスター＋歩行シート

## 既知の問題

- 大学生の右下向きだけスマホが左手（上の表）。直すなら、右下の列だけを「スマホは右手」と明記して作り直す
- PEPPERMINT と KEMURIKUSA の店内は夜の絵が無いので、夜も昼と同じ背景
- 夜の窓の灯りは「暖色で明るい画素」を抜き出して重ねているので、シャッターの店の錆びた看板など、明るい暖色の部分も一部光る
- 地面のタイルは真上から見た絵なので、斜め見下ろしの建物とは厳密には視点が合っていない（並べると気にならない程度）
- 32ドットのつむぎは顔の細部が読みにくい。主人公の歩行シートを作るときは、目と髪型をはっきりさせる指示を足すとよい
