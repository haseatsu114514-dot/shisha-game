## 確定した画風と制作単位

- 既存デザインのほぼ再現が基本。顔立ち・髪型・配色・衣装・小物・元の表情の魅力を保つ。
- 元画像の汚い切り抜き、不統一なサイズ、部分的な低画質を改善する。
- **高解像度の細かなドット絵のような質感を意図的に残し、高級感のある仕上げにする。**
  普通の滑らかなアニメ塗りに変えない。粗い巨大なドットやぼかし、ノイズを足す処理でもない。
- 表情に連動して指先・手首・肘・肩・首の角度などを少し変える。動きの大きさは性格に合わせる。
- **解像度（2026-10-09）**：ゲーム用896×1200での人物の高さ（約900〜1120px）より原画の人物が小さいと、引き伸ばしでぼやけ、キャラ間で画質がそろわない。5表情を横1枚のシートで作ると人物は約850pxに縮むので、**最終素材は1回の生成で1人・1表情、人物の高さ1300px以上**で作り、配置は縮小だけにする（凛v12の方式）。**顔の大きさ**はゲーム画面で中央値（みんと・アダム）から±10%以内（`python3 tools/make_reference_sheet.py facesize` で確認）。画風はみんと・アゲハが基準。調査と依頼文は [resolution-upgrade-20261009](../../../asset_sources/portraits/resolution-upgrade-20261009/README.md)。
- みんと・あげはは元から品質が高いので、元の顔と基本ポーズを大きく変えない。
- **1キャラ（別衣装は1セット）ずつ生成して見せ、オーナーの採用確認を待つ。**
  画像の確認、採用、ゲームへの組み込み／マージは区別して記録する。
- 生成開始を求められたら参照確認後すぐ生成を開始する。別の承認済み素材の整理で開始を後回しにしない。

## 毎回、過去の制作画像を画質・質感の基準にする

**新しいキャラ・別衣装・表情の修正を生成するたびに、この手順を行う。**

1. [画像一覧](references/style-references.json)にある過去の制作セットをすべて目視する。
   [比較ビューアー](references/style-gallery.html)で全表情を並べ、原寸表示も使う。
   現在の採用済み基準は、みんと営業姿v2・あげはv1・みんと私服v1の15枚。
   採用済みのつむぎ基本5差分と病み可愛いv2も、保存元シートとゲーム用PNGの両方を見る。
2. 少なくとも各セットの代表画像を**原寸（1画像px＝1表示px）**で確認する。
   顔・髪・服・透過の縁を拡大し、細かなドットの粒度、輪郭の太さ、陰影の段階、
   髪の光沢、布の描き込み、シャープさを比較する。縮小サムネイルだけで判断しない。
3. 生成ツールには、対象キャラの元画像に加え、**採用済みの過去画像を最低1枚、通常は2枚、実画像として添付する**。
   通常はみんと営業姿＋あげはを画風の参照にし、落ち着いた私服ではみんと私服も選ぶ。
   同じキャラの別衣装では採用済みの本人画像を優先する。
   つむぎを添付する場合も、初期基準のみんと／あげはを最低1枚含める。
4. 元画像は対象のデザイン・表情、過去の採用済み画像は画質・質感の参照、とプロンプトに明記する。
   他キャラの顔・髪型・衣装を移さず、細かな高解像度ドット絵調と高級感を揃える。
5. 出力を過去画像と同じ人物表示サイズ、および双方の原寸で比較してから見せる。
   滑らかすぎる塗り、粗いドット、ぼやけ、粒度の不統一、汚い縁があれば修正する。
6. 新しく制作した画像は参照一覧へ追加し、採用後は状態を更新する。
   次回も初期の採用済み基準と新しい採用画像の両方を見る。直前の1人だけを基準にして画風を徐々に変えない。

一覧のファイルパス、初期基準コミット、画素ファイルのSHA-256は保存済み。
新チャットの取得・比較・プロンプト例は[過去画像の参照手順](references/style-references.md)を使う。

## 1. 元画像を実際に見る

1. `CLAUDE.md` の Git Safety を実行し、正本のリポジトリを確認する。
2. `assets/sprites/characters/<id>/chr_<id>_*.png` を列挙する。
   `data/characters.json` は配列。キャラIDで該当要素を検索し、年齢・身長・`spriteScale`・性格を確認する。
   配列にいないキャラは個別プロフィールも確認する。サメちゃんは `kafuka`、プロフィールは
   `data/dialogue/kafuka.json` の `profile`、立ち絵は `assets/sprites/characters/kafuka/`。
3. **通常だけでなく既存の全表情を見る。** 古い `visual_concepts` が実画像と食い違うことがあるので、
   今ある絵を再現する依頼では実画像とオーナーの説明を優先する。
4. 表情の左右の目、口、舌、眉、涙・赤面、手の位置、小物の左右をメモする。
   左右は「画面左／画面右」で明記する。
5. 必要に応じ元画像をHTMLで並べた比較シートを作る。画像は背景を明暗両方で合成して見る。
   ツールの画像表示だけで低アルファの縁が派手に見える場合もあり、PNGの実際の透過を確認する。

## 2. 生成

- 画像生成・創作上の画像修正は画像生成ツールを使う。Pythonで顔やポーズを描き換えない。
- 参照は通常の基準画像＋重要な表情。別衣装では採用済み衣装の通常画像を同一人物性の最優先参照にする。
- このセッションの画像ツールはローカル参照画像が**最大5枚**。必要な表情を選び、残りは正確な文章で補う。
  そのうち1〜2枚を過去の採用済み画像に使う。対象の全表情を伝える必要がある場合は比較シートにまとめ、
  重要な表情と画風の基準画像は原画像も添付する。別の環境ではツールの上限を確認する。
  ローカル参照と会話の直近画像参照を同時指定しない。
- 元の表情の再現、小さなポーズ変化、同一の縮尺、足元基準、細かなドット絵調、透過の清潔さをプロンプトに明記する。
- 5差分なら左から順番を固定した1列のシートが有効。各人の髪・手・バッグが隣に重ならない十分な透過の間隔を要求する。
  頭の上と靴の下、両端にも余白を残す。生成後は全身が欠けていないか確認する。
- 透過背景を指定し、背景のグラデーション、光彩、色付きの縁、床影、背景に描かれた市松模様を作らない。
- プロンプトと生成元のシートは保存する。採用前の絵は確認用資料として扱い、ゲームのPNG／WebPを差し替えない。
  添付した画像のパスと、デザイン用／画風用の役割も記録する。
- [保存済みプロンプト](references/)は今回の作例。キャラごとに髪・衣装・表情・性格を読み直して書き換える。

## 3. 1セットを見せる

全身5差分に加え、元との顔比較、別衣装では採用済み衣装との頭身比較を必要に応じ用意する。
並び順と仕草の違いを簡潔に伝え、採用／修正の返答を待つ。
指摘された箇所は元画像を再確認し、指定された箇所を直す。次のキャラへ進むのは採用確認後。

## 4. 採用された素材だけを組み込む

同時に [portrait-fix](../portrait-fix/SKILL.md) を使う。

- ファイル名・表情キーを既存どおり保ち、キャンバスを **896×1200 RGBA** に揃える。
- キャラ／衣装セット全体で一つの拡縮率を使う。足元の下端と下20%の重心を通常に合わせる。
  表情ごとの拡縮で頭身や身長が変わらないようにする。体格設定 `spriteScale` は変更しない。
- 別衣装を持つキャラは他のセットを巻き込んで加工しない。共通のmanifestの高さ・足元アンカーが別衣装の表示にも影響するので確認する。
- 採用済みの腕・肩などのポーズ差は意図されたもの。位置ずれを直すために顔だけ合成し、体を全表情で同じに戻さない。
- 固定幅の5等分で髪や手が切れる場合は、透過の隙間または本体の連結成分で分ける。
  隣の髪が接触している箇所は個別に確認する。単に等分して見切れたまま入れない。
- **アルファを一括で閾値処理しない。** α64〜240の髪も原画。背景の低アルファ残りを整理するときは1キャラで確認してから次へ進む。
- RGBAを別キャンバスへ配置するときにアルファを二重に適用しない（`paste(image, xy)`）。
- 高密度のドット絵の清書版は、`remake/tools/build_images.py` で**lossless WebP・exact alpha**を保持する。
  PNGと配布WebPをRGBAで比較して、一致を確かめる。通信サイズとの交換条件はPRに明記する。
  変換のキャッシュはmtimeを使うため、PNG変更後のGit stash／checkoutで順序が変わると古いWebPを再利用し得る。
  一致しない場合は**対象キャラの生成WebPだけ**を削除して再生成し、もう一度RGBA比較とゲーム内確認をする。

## 5. ビルド・表示確認・記録

```bash
python3 tools/make_face_icons.py <id>   # 丸アイコン（LIME・看板・好感度カード等）も新しい立ち絵から作り直す
python3 remake/tools/build_manifest.py
python3 tools/align_sprite_anchor.py -c <id> --dry-run
# 凛を変更した場合の回帰。他のキャラはそのキャラの実画面で確認
node remake/test/rin_portraits.mjs
```

- 丸アイコンは `tools/make_face_icons.py` の `TUNE` で切り抜きを調整し、他キャラと並べて顔の大きさ・目線の高さを揃える。
  別衣装の顔は `EXTRA`（例: みんと私服＝`face_minto_private`）。
  アイコンは全員160px・256色・輪郭は滑らかな透明度（2026-10-04 オーナー指定。元絵の顔の切り抜きが約180〜240pxのため160pxが上限の目安）。拡大表示とスマートフォンの高密度表示で目が読めるか確認する。キャラ別に変える場合は `TUNE` の `size`。
- 表情の意味や仕草が旧画像と変わったら、そのキャラの全台詞の `face` 指定を場面に合わせて見直す
  （2026-10-04 PRT18〜PRT21。旧つむぎ・旧凛は表情ファイルの中身が名前とずれていた）。立ち絵と矛盾する外見の地の文も確認する。
- 修正対象は共有 `assets/` と現行 `remake/`。保存されている旧版のUIやゲームロジックを編集しない。
  旧版ビルドは回帰確認用。共有画像はCIでも配布HTMLに再ビルドされる。
- ローカルHTTPサーバー経由で**全表情を実際の会話エンジンに出す**。別衣装との切り替え、左右・上下のずれ、頭／髪／手の欠けを目視する。
  PNGだけ確認して終わらない。実際に読まれるWebPとmanifestも確認する。
- 必要な通し確認は `node remake/test/playthrough.mjs`。重いテストは並列実行しない。
  ブラウザの実行パスは環境に合わせる（例 `CHROME_BIN=/usr/bin/chromium`）。
- [owner-request](../owner-request/SKILL.md) に沿い、`docs/owner_requests.md` と制作記録へ採用済み・確認待ち・マージ状況を残す。
- Git Safetyを確認し、`origin/main` からのブランチとPRを使う。mainへの直接pushやforce pushはしない。
  オーナーがマージを指示済みなら、承認済み素材を確認後にマージする。改めて同じ許可を聞かない。
- 未承認の生成案は確認資料として保存できるが、ゲームの実素材へ採用しない。
