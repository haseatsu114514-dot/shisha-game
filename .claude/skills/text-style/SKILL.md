# テキスト規範（句読点・改行・改ページ）

2026-07-07 オーナー指定（G1/G2）で制定。**この規範が句読点・改行の正本**。
迷ったらここに従い、規範自体を変えるときはこのファイルを更新する。

## 句読点のルール

1. **台詞（speaker あり）の末尾に「。」を付けない**。
   - ✅ `わかりました` ／ ❌ `わかりました。`
   - 閉じ括弧の直前も同じ: ✅ `（そうか）` ❌ `（そうか。）`
   - `！` `？` `……` で終わるのは可。`……。` は `……` にする。
   - ナレーション（speaker 空）は散文なので「。」で終えて良い。
2. **冒頭の間投詞のあとは「、」**。
   - ✅ `え、俺が、大会にですか？` ／ ❌ `え。俺が、大会にですか？`
3. **「。……」＋短い続き（相槌・照れ笑い等）は「、……」**。
   - ✅ `頑張れますよね、……えへへ` ／ ❌ `頑張れますよね。……えへへ`
   - 続きが独立した文なら「。……」のままで良い:
     `一度やってみるといい。……覚えておいて、損はありません` は変えない。
4. **1台詞に「。」は2個まで**を目安に。3個以上になったら台詞行を分ける
   （ノベルゲームのテンポ。lint が WARN を出す）。

## 改行・改ページのルール

- 手動改行 `\n` は入れない（autoWrap が全角24字・禁則つきで折る）。
- **折る位置は「文末（。！？）→ 読点など（、……」♡──）→ 文節の頭」の順に選ぶ**（2026-11-11 TXW01・オーナー「二行目だけ短いとか、変な位置の改行が気になる」）。
  同じ種類の中では1行目をなるべく長くするが、**2行目だけが短い「切れ端」になるなら手前の区切りへ戻す**（短い方が長い方の4割を切るほど強く避ける）。
  - ✅ `上の青に当てたら上の2つ、／下なら下の2つが閉じるよ！` ／ ❌ `…下なら下の2つが／閉じるよ！`
  - 「うん。」「……はい。」のような短い文は1行目に単独で置いてよい。短い2文目（`〜見えてくる。／それだけだ`）も文末で折ったままにする。
  - 文末の直後に始まる「……」は次の文の頭なので、行頭に置ける（`〜だって。／……僕、`）。「、……」の「……」は前の句に付けたまま。
  - 1行に収まる「」『』（）の中、`#タグ` の途中、`『原点』の｜味` のような閉じ括弧＋「の」の直後では、なるべく折らない。
- **語の途中では折らない**（2026-10-09 TX01・オーナー「言葉の途中で改行するぐらいなら早めに改行」）。
  句読点で折れない行は、手前の文節の頭（BudouX 日本語モデル `remake/js/vn/budoux_ja.js`）で早めに折る。
  漢字同士の間・同じ字の連続（えへへ）・辞書の一語（ありがたい）では折らない。「♡」「──」の後も区切りで、行頭に来た空白は表示しない。
- 早めに折る分、40字台でも3行（2ページ）になりうる。新しい台詞は台詞エディタか `node remake/test/text_wrap.mjs` で確かめる。
- 一文を2つの吹き出しにまたがせない。2ページになる長い台詞は、エンジンが**ページの切れ目を文末に合わせる**（TXW03）が、
  文が長いと文の途中でページが割れる。心の声は各行を（）で閉じる（`lint_dialogue.py` が閉じていない括弧をWARN）。
  どうしても演出で折りたい時だけ、1行が全角24字以内になる位置に置く。
- 1台詞は**全角48字（2行）以内**。超えると自動改ページで文が割れる（lint WARN）。
- 最後のページに短い断片だけが残る「孤立ページ」（例: `ありがたい）` 1行）はエンジン側で避ける（`vn/text.js` のページ分け）。
  それでも変な割れ方をしたら台詞を分けるのが正道。
- 会話以外の画面の文字（メニュー・説明・ボタン・通知・LIME）はブラウザが折る（TXW04・TXW05）。全体に `word-break: auto-phrase`（文節で折る）と
  `text-wrap: pretty`（最後の行だけ短い形を避ける）、ボタンと2〜3行の一言・注記に `text-wrap: balance`（行の長さをそろえる）を当ててある
  （`remake/css/base.css` の冒頭）。新しい短い注記の部品は、そこの一覧にセレクタを足す。UIの文字に手動の `<br>` や `\n` を足して整えない。
  部品の規則に `word-break: break-word` / `break-all` / `keep-all` / `normal` を書くと文節の折り返しが消える（LIMEの吹き出しで起きていた）。
  CI の `remake/test/css_wrap_guard.mjs` が止める。どうしても要る時だけ、そのファイルの ALLOWED に理由つきで足す。
  幅が狭すぎて1〜3字ずつ折れる箱は、折り返しの指定ではなく箱の幅か文を直す。

## ツール（書いたら必ず通す）

```bash
# 1) 自動整形（上のルール1〜3を機械的に適用。--dry-run で差分確認から）
python3 tools/tidy_dialogue_text.py --dry-run
python3 tools/tidy_dialogue_text.py

# 2) リンタ（規範違反は WARN、旧名等は ERROR）
python3 tools/lint_dialogue.py

# 2b) 書いた台詞が本編でどう折れるかを見る（TXW08。本編と同じ組版で、main から足した・変えた台詞だけ）
node .claude/skills/text-style/check_wrap.mjs            # 「要確認」が出たら直す（0件にしてからコミット）
node .claude/skills/text-style/check_wrap.mjs "台詞" …   # 書く前に文を試す
#   【直す】= CI で止まる（remake/test/text_wrap.mjs が全台詞で0件を確かめる）: 2行目だけ短い・文の途中でページが割れる
#   要確認 = 知らせるだけ: 1行目だけ短い・手で改行している・2ページに分かれる（文末で切れていれば読める）
#   「長い文。／短い2文目」は規範どおりなので知らせない。直し方は、言い換える・読点の位置を変える・文を「。」で2つに分ける
#   判定の中身は remake/test/text_wrap_rules.mjs（スキルと CI で同じもの）

# 3) 手動で微調整したいとき（ブラウザの台詞エディタ。検索→編集→保存＋本編と同じ改行プレビュー）
python3 tools/text_editor_server.py   # → http://127.0.0.1:8321/
#   ・保存すると data/dialogue/*.json に直接書き戻る
#   ・プレビューは remake/js/vn/text.js の autoWrap 実物を配信＝本編とズレない
#   ・画面の「台詞の検査」「⬆️コミット&プッシュ」で 4) まで完結できる（main/masterでは拒否）
#   ・使い方の詳細は docs/tools/text_editor_manual.md（アプリ内「❓ヘルプ」からも読める）

# 4) 反映
# remake/ はJSONを直接読む。保存後、ブラウザを再読み込みする
```

## 注意（壊しやすい場所）

- 報酬キュー行（`……【技術】と【センス】が上がった。`）は**規定フレーズを一字一句変えない**
  （docs/gameplay_agent_reference.md「報酬を地の文に埋めない」参照）。tidy はナレーション末尾の「。」を触らないので安全。
- `remake/js/` 内のインライン台詞（インライン文字列）にも同じ規範を適用する。
  tidy は JSON しか見ないので、工程モジュールなどに台詞を書くときは手で従うこと。
- `remake/js/vn/text.js` を変更すると、台詞エディタも同じ実物を配信する。組版を複製しない。
