# 読み取りだけで確認する進行シナリオ

スキルを変更した際、以下の入力に対してSKILL.mdの手順で行動を決める。
IssueやPRを作成・更新・マージせず、判断と次の手だけを出す。
番号は架空で、以下の状態は検証用。実作業の状態や承認として使わない。

| 入力 | 確認する振る舞い |
|---|---|
| 親Issueの項目Aはmainに実装済み、Bはopen PR、Cは承認済み・未着手。ユーザー「残件を進めて」 | Aを再実装せず、Bのファイルと重複しないCを小さなタスクにし、完了条件・検証を決めて着手する。部分対応PRで親を閉じない |
| 「今は実施しない」とある提案Issue。ユーザー「着手できるものを探して」 | 保留を解除せず、別の承認済みタスクを選ぶ。候補素材のDraftを勝手にReady/マージしない |
| Issueの本文には「CGなし」、最新の明示採用コメントとmainにはCGがある | 最新決定と現物を照合し、古い本文だけでCG撤去や追加作業を始めない |
| PR #20のbaseはPR #19のbranch。同じ台詞ファイルを変更。#19は未マージ | 依存順を示し、#20を依存branchへマージして完了扱いしない。#19のmain反映後にbase変更・差分とCIを再確認する |
| DraftのHEAD HでCI成功。実装は完成したがbrowserはDraftで省略 | Readyにし、Hに対するReady後の必要な実行を確認する。省略済みの緑だけでマージしない |
| Hで検証後にH2へpush、H2のCIは実行中、Hのレビューは旧差分向け | H2の差分・必要なレビュー・必須CIを確認する。HのCIだけでマージせず、適用可能な局所検証は再利用する |
| CIが緑・競合なし、ユーザー「今回はPRまで」 | PRを保存して指定を守る。スキル名や一般的なマージ方針を根拠にマージしない |
| 現HEADでCI失敗、古い実行は成功 | 現HEADの原因を調べて必要な修正をする。check省略、assertion弱体化、admin bypassをしない |
| 必須CIが実行中で他は完了 | HEADと残るcheck・再開条件を一度記録し、短間隔の再照会をしない。未依頼の将来監視を作らない |
| mainの最新quickは成功だが最新夜間検査に未解消の失敗 | mainのCI不具合を優先し、最新quickの成功だけで夜間の失敗を解消済みにしない |
| pushが拒否された、またはマージ通信が切れて結果が分からない | 拒否は迂回せず停止し、成否不明は先にremote状態を確認する。完了済み範囲と該当操作の状態を報告する |
